---
title: INVALID_CHAT_HISTORY
---

:::python
当预构建的 @[`create_agent`] 中，`call_model` 图节点收到格式不正确的消息列表时，会抛出这个错误。具体来说，如果存在带有 `tool_calls` 的 `AIMessage`（即 LLM 请求调用工具），却没有与之对应的 @[`ToolMessage`]（即工具执行结果返回给 LLM），则消息历史就是不合法的。
:::

:::js
当预构建的 @[`createAgent`] 中，`callModel` 图节点收到格式不正确的消息列表时，会抛出这个错误。具体来说，如果存在带有 `tool_calls` 的 `AIMessage`（即 LLM 请求调用工具），却没有与之对应的 @[`ToolMessage`]（即工具执行结果返回给 LLM），则消息历史就是不合法的。
:::

你可能因为以下几种原因遇到这个错误：

:::python
1. 你在调用图时手动传入了格式不正确的消息列表，例如：`graph.invoke({'messages': [AIMessage(..., tool_calls=[...])]})`。
2. 图在收到 `tools` 节点的更新（即一组 @[`ToolMessage`]）之前被中断了，而你随后又使用一个既不是 `None`、也不是 `ToolMessage` 的新输入重新调用图，例如：`graph.invoke({'messages': [HumanMessage(...)]}, config)`。
   这类中断可能由以下情况触发：
   * 你在 `create_agent` 中手动设置了 `interrupt_before = ['tools']`；
   * 某个工具抛出了未被 @[`ToolNode`]（`"tools"`）处理的错误。
:::

:::js
1. 你在调用图时手动传入了格式不正确的消息列表，例如：`graph.invoke({messages: [new AIMessage({..., tool_calls: [...]})]})`。
2. 图在收到 `tools` 节点的更新（即一组 @[`ToolMessage`]）之前被中断了，而你随后又使用一个既不是 `null`、也不是 `ToolMessage` 的新输入重新调用图，例如：`graph.invoke({messages: [new HumanMessage(...)]}, config)`。
   这类中断可能由以下情况触发：
   * 你在 `createAgent` 中手动设置了 `interruptBefore: ['tools']`；
   * 某个工具抛出了未被 @[`ToolNode`]（`"tools"`）处理的错误。
:::

## 故障排查

可以使用以下方式解决：

1. 不要使用格式不正确的消息列表调用图。
2. 如果图因为手动中断或错误而暂停，可以选择以下方案：

:::python
* 提供与现有工具调用相匹配的 @[`ToolMessage`]，然后调用 `graph.invoke({'messages': [ToolMessage(...)]})`。
  **注意**：这会把新消息追加到历史记录中，并从 START 节点重新运行图。
* 手动更新 State，然后从中断位置恢复图：
  1. 使用 `graph.get_state(config)` 获取图 State 中最近的消息列表；
  2. 修改消息列表：删除 `AIMessage` 中尚未得到响应的工具调用，或者补充 `tool_call_id` 与未响应工具调用相匹配的 @[`ToolMessage`]；
  3. 调用 `graph.update_state(config, {'messages': ...})` 写回修改后的消息列表；
  4. 恢复图，例如调用 `graph.invoke(None, config)`。
:::

:::js
* 提供与现有工具调用相匹配的 `ToolMessage`，然后调用 `graph.invoke({messages: [new ToolMessage(...)]})`。
  **注意**：这会把新消息追加到历史记录中，并从 START 节点重新运行图。
* 手动更新 State，然后从中断位置恢复图：
  1. 使用 `graph.getState(config)` 获取图 State 中最近的消息列表；
  2. 修改消息列表：删除 `AIMessage` 中尚未得到响应的工具调用，或者补充 `toolCallId` 与未响应工具调用相匹配的 `ToolMessage`；
  3. 调用 `graph.updateState(config, {messages: ...})` 写回修改后的消息列表；
  4. 恢复图，例如调用 `graph.invoke(null, config)`。
:::
