## 定义和更新 State

本节介绍如何在 LangGraph 中定义和更新 [State](/oss/langgraph/graph-api#state)，主要包括：

1. 如何使用 State 定义 Graph 的 [Schema](/oss/langgraph/graph-api#schema)
2. 如何使用 [Reducer](/oss/langgraph/graph-api#reducers) 控制 State Update 的处理方式

### 定义 State

:::python
LangGraph 中的 [State](/oss/langgraph/graph-api#state) 可以使用 `TypedDict`、Pydantic Model 或 Dataclass 定义。下面使用 `TypedDict`。关于 Pydantic，请参阅[使用 Pydantic Model 作为 Graph State](#use-pydantic-models-for-graph-state)。
:::

:::js
LangGraph 中的 [State](/oss/langgraph/graph-api#state) 使用 `StateSchema` Class 定义。它提供统一 API，可以为各字段使用 [Standard Schema](https://standardschema.dev/)（例如 [Zod](https://zod.dev/)），也可以使用 `ReducedValue`、`MessagesValue`、`UntrackedValue` 等特殊 Value Type。
:::

默认情况下，Graph 的输入与输出使用同一个 Schema，由 State 决定。如果希望分别定义输入与输出 Schema，请参阅[定义输入和输出 Schema](#define-input-and-output-schemas)。

:::python
下面以 [Messages](/oss/langgraph/graph-api#messagesstate) 为例。对于许多 LLM 应用，这是一种非常通用的 State 表示方式。更多细节参见[在 Graph State 中使用 Message](/oss/langgraph/graph-api#working-with-messages-in-graph-state)。
:::
:::js
下面以 [Messages](/oss/langgraph/graph-api#working-with-messages-in-graph-state) 为例。对于许多 LLM 应用，这是一种非常通用的 State 表示方式。更多细节参见[在 Graph State 中使用 Message](/oss/langgraph/graph-api#working-with-messages-in-graph-state)。
:::

:::python
```python
from langchain.messages import AnyMessage
from typing_extensions import TypedDict

class State(TypedDict):
    messages: list[AnyMessage]
    extra_field: int
```

这个 State 同时跟踪一组 [Message](https://python.langchain.com/docs/concepts/messages/) 对象和一个额外的整数 Field。
:::

:::js
```typescript
import { StateSchema, MessagesValue } from "@langchain/langgraph";
import * as z from "zod";

const State = new StateSchema({
  messages: MessagesValue,
  extraField: z.number(),
});
```

这个 State 同时跟踪一组 [Message](https://js.langchain.com/docs/concepts/messages/) 对象和一个额外的整数 Field。
:::

### 更新 State

:::python
先构建一张只包含一个 Node 的简单 Graph。一个 [Node](/oss/langgraph/graph-api#nodes) 本质上就是一个读取 Graph State 并返回更新的 Python Function。函数的第一个参数始终是 State：

```python
from langchain.messages import AIMessage

def node(state: State):
    messages = state["messages"]
    new_message = AIMessage("Hello!")
    return {"messages": messages + [new_message], "extra_field": 10}
```

这个 Node 会向 Message List 追加一条消息，并填充 `extra_field`。
:::

:::js
先构建一张只包含一个 Node 的简单 Graph。一个 [Node](/oss/langgraph/graph-api#nodes) 本质上就是一个读取 Graph State 并返回更新的 TypeScript Function。函数的第一个参数始终是 State：

```typescript
import { AIMessage } from "@langchain/core/messages";
import { GraphNode } from "@langchain/langgraph";

const node: GraphNode<typeof State> = (state) => {
  const messages = state.messages;
  const newMessage = new AIMessage("Hello!");
  return { messages: [newMessage], extraField: 10 };
};
```

这个 Node 会向 Message List 追加一条消息（拼接由 Reducer 负责），并填充 `extraField`。
:::

<Warning>
Node 应该直接**返回 State Update**，而不是原地修改 State。
</Warning>

:::python
接下来定义包含这个 Node 的简单 Graph。使用 [`StateGraph`](/oss/langgraph/graph-api#stategraph) 定义作用于该 State 的 Graph，然后用 [`add_node`](/oss/langgraph/graph-api#nodes) 添加 Node。

```python
from langgraph.graph import StateGraph

builder = StateGraph(State)
builder.add_node(node)
builder.set_entry_point("node")
graph = builder.compile()
```
:::

:::js
接下来定义包含这个 Node 的简单 Graph。使用 [`StateGraph`](/oss/langgraph/graph-api#stategraph) 定义作用于该 State 的 Graph，然后用 [`addNode`](/oss/langgraph/graph-api#nodes) 添加 Node。


### 使用 Reducer 处理 State Update

State 中的每个 Key 都可以拥有自己独立的 [Reducer](/oss/langgraph/graph-api#reducers) Function，由它决定 Node 返回的 Update 如何应用。如果没有显式指定 Reducer，默认行为是**覆盖**这个 Key 的旧值。

:::python
对于 `TypedDict` State Schema，可以通过给对应 Field 添加 Reducer Function Annotation 来定义 Reducer。

前面的例子中，Node 会通过追加 Message 更新 `"messages"` Key。下面给这个 Key 增加 Reducer，使新的 Update 自动追加：

```python
from typing_extensions import Annotated

def add(left, right):
    """Can also import `add` from the `operator` built-in."""
    return left + right

class State(TypedDict):
    messages: Annotated[list[AnyMessage], add]  # [!code highlight]
    extra_field: int
```

现在 Node 可以进一步简化：

```python
def node(state: State):
    new_message = AIMessage("Hello!")
    return {"messages": [new_message], "extra_field": 10}  # [!code highlight]
```
:::

:::js
前面的示例已经使用了带内置 Reducer 的 `MessagesValue`。对于自定义 Field，可以使用 `ReducedValue` 定义 Update 应如何应用。

前面的 Node 会通过追加 Message 更新 `"messages"` Key；`MessagesValue` Reducer 会自动完成这一工作：

```typescript
import { StateSchema, MessagesValue, ReducedValue } from "@langchain/langgraph";
import * as z from "zod";

// MessagesValue already has a built-in reducer
const State = new StateSchema({
  messages: MessagesValue,  // [!code highlight]
  extraField: z.number(),
});
```

Node 只需要返回新 Message，拼接由 Reducer 完成：

```typescript
import { GraphNode } from "@langchain/langgraph";

const node: GraphNode<typeof State> = (state) => {
  const newMessage = new AIMessage("Hello!");
  return { messages: [newMessage], extraField: 10 };  // [!code highlight]
};
```
:::

:::python

#### MessagesState

实际应用中，更新 Message List 还需要考虑：

* 可能需要更新 State 中已经存在的某条 Message。
* 可能希望接受 [Message Format](/oss/langgraph/graph-api#using-messages-in-your-graph) 的简写形式，例如 [OpenAI Format](https://python.langchain.com/docs/concepts/messages/#openai-format)。

LangGraph 内置 @[`add_messages`] Reducer 来处理这些情况：

```python
from langgraph.graph.message import add_messages

class State(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]  # [!code highlight]
    extra_field: int

def node(state: State):
    new_message = AIMessage("Hello!")
    return {"messages": [new_message], "extra_field": 10}

graph = StateGraph(State).add_node(node).set_entry_point("node").compile()
```

```python
input_message = {"role": "user", "content": "Hi"}  # [!code highlight]

result = graph.invoke({"messages": [input_message]})

for message in result["messages"]:
    message.pretty_print()
```

```
================================ Human Message ================================

Hi
================================== Ai Message ==================================

Hello!
```

对于使用 [Chat Model](https://python.langchain.com/docs/concepts/chat_models/) 的应用，这是非常通用的 State 表示。LangGraph 还内置了 `MessagesState`，因此可以直接扩展：

```python
from langgraph.graph import MessagesState

class State(MessagesState):
    extra_field: int
```

### 使用 `Overwrite` 绕过 Reducer

有时你希望绕过 Reducer，直接覆盖某个 State Value。LangGraph 为此提供 [`Overwrite`](https://reference.langchain.com/python/langgraph/types/) Type。当 Node 返回被 `Overwrite` 包裹的值时，对应 Reducer 不会执行，该 Channel 会直接被设置为这个值。

当你希望重置或替换累计 State，而不是继续合并旧值时，这很有用。

```python
from langgraph.graph import StateGraph, START, END
from langgraph.types import Overwrite
from typing_extensions import Annotated, TypedDict
import operator

class State(TypedDict):
    messages: Annotated[list, operator.add]

def add_message(state: State):
    return {"messages": ["first message"]}

def replace_messages(state: State):
    # Bypass the reducer and replace the entire messages list
    return {"messages": Overwrite(["replacement message"])}

builder = StateGraph(State)
builder.add_node("add_message", add_message)
builder.add_node("replace_messages", replace_messages)
builder.add_edge(START, "add_message")
builder.add_edge("add_message", "replace_messages")
builder.add_edge("replace_messages", END)

graph = builder.compile()

result = graph.invoke({"messages": ["initial"]})
print(result["messages"])
```

```
['replacement message']
```

也可以使用特殊 Key `"__overwrite__"` 的 JSON Format：

```python
def replace_messages(state: State):
    return {"messages": {"__overwrite__": ["replacement message"]}}
```

<Warning>
当多个 Node 并行执行时，在同一个 Superstep 内，同一个 State Key 最多只能有一个 Node 使用 `Overwrite`。如果多个 Node 同时尝试覆盖同一个 Key，会抛出 `InvalidUpdateError`。
</Warning>
:::

### 定义输入和输出 Schema

默认情况下，`StateGraph` 使用单一 Schema，所有 Node 都通过这个 Schema 通信。但也可以为 Graph 分别定义 Input Schema 与 Output Schema。

当指定不同 Schema 后，Node 之间仍会使用一个内部 Schema 通信。Input Schema 用于确保输入符合预期结构，而 Output Schema 会过滤内部数据，只返回 Output Schema 声明的信息。

下面展示如何分别定义输入与输出 Schema。

:::python
```python
from langgraph.graph import StateGraph, START, END
from typing_extensions import TypedDict

# Define the schema for the input
class InputState(TypedDict):
    question: str

# Define the schema for the output
class OutputState(TypedDict):
    answer: str

# Define the overall schema, combining both input and output
class OverallState(InputState, OutputState):
    pass

# Define the node that processes the input and generates an answer
def answer_node(state: InputState):
    # Example answer and an extra key
    return {"answer": "bye", "question": state["question"]}

# Build the graph with input and output schemas specified
builder = StateGraph(OverallState, input_schema=InputState, output_schema=OutputState)
builder.add_node(answer_node)  # Add the answer node
builder.add_edge(START, "answer_node")  # Define the starting edge
builder.add_edge("answer_node", END)  # Define the ending edge
graph = builder.compile()  # Compile the graph

# Invoke the graph with an input and print the result
print(graph.invoke({"question": "hi"}))
```

```
{'answer': 'bye'}
```
:::

:::js
```typescript
import { StateGraph, StateSchema, GraphNode, START, END } from "@langchain/langgraph";
import * as z from "zod";

// Define the schema for the input
const InputState = new StateSchema({
  question: z.string(),
});

// Define the schema for the output
const OutputState = new StateSchema({
  answer: z.string(),
});

// Define the overall schema, combining both input and output
const OverallState = new StateSchema({
  question: z.string(),
  answer: z.string(),
});

// Define the node that processes the input
const answerNode: GraphNode<typeof OverallState> = (state) => {
  // Example answer and an extra key
  return { answer: "bye", question: state.question };
};

// Build the graph with input and output schemas specified
const graph = new StateGraph({
  input: InputState,
  output: OutputState,
  state: OverallState,
})
  .addNode("answerNode", answerNode)
  .addEdge(START, "answerNode")
  .addEdge("answerNode", END)
  .compile();

// Invoke the graph with an input and print the result
console.log(await graph.invoke({ question: "hi" }));
```

```
{ answer: 'bye' }
```
:::

注意，`invoke` 的输出只包含 Output Schema 中声明的字段。

### 在 Node 之间传递私有 State

有时 Node 之间需要交换某些中间信息，但这些数据并不属于 Graph 的主 Schema，也不需要成为 Graph 的整体输入或输出。此时可以使用 Private State，只在特定 Node 之间共享。

下面构建一个由 `node_1`、`node_2`、`node_3` 组成的顺序 Graph，其中 `node_1` 与 `node_2` 之间会传递 Private Data，而 `node_3` 只能访问公共 Overall State。

:::python
```python
from langgraph.graph import StateGraph, START, END
from typing_extensions import TypedDict

# The overall state of the graph (this is the public state shared across nodes)
class OverallState(TypedDict):
    a: str

# Output from node_1 contains private data that is not part of the overall state
class Node1Output(TypedDict):
    private_data: str

# The private data is only shared between node_1 and node_2
def node_1(state: OverallState) -> Node1Output:
    output = {"private_data": "set by node_1"}
    print(f"Entered node `node_1`:\n\tInput: {state}.\n\tReturned: {output}")
    return output

# Node 2 input only requests the private data available after node_1
class Node2Input(TypedDict):
    private_data: str

def node_2(state: Node2Input) -> OverallState:
    output = {"a": "set by node_2"}
    print(f"Entered node `node_2`:\n\tInput: {state}.\n\tReturned: {output}")
    return output

# Node 3 only has access to the overall state (no access to private data from node_1)
def node_3(state: OverallState) -> OverallState:
    output = {"a": "set by node_3"}
    print(f"Entered node `node_3`:\n\tInput: {state}.\n\tReturned: {output}")
    return output

# Connect nodes in a sequence
# node_2 accepts private data from node_1, whereas
# node_3 does not see the private data.
builder = StateGraph(OverallState).add_sequence([node_1, node_2, node_3])
builder.add_edge(START, "node_1")
graph = builder.compile()

# Invoke the graph with the initial state
response = graph.invoke(
    {
        "a": "set at start",
    }
)

print()
print(f"Output of graph invocation: {response}")
```

```
Entered node `node_1`:
    Input: {'a': 'set at start'}.
    Returned: {'private_data': 'set by node_1'}
Entered node `node_2`:
    Input: {'private_data': 'set by node_1'}.
    Returned: {'a': 'set by node_2'}
Entered node `node_3`:
    Input: {'a': 'set by node_2'}.
    Returned: {'a': 'set by node_3'}

Output of graph invocation: {'a': 'set by node_3'}
```
:::

:::js
```typescript
import { StateGraph, StateSchema, GraphNode, START, END } from "@langchain/langgraph";
import * as z from "zod";

// The overall state of the graph (this is the public state shared across nodes)
const OverallState = new StateSchema({
  a: z.string(),
});

// Output from node1 contains private data that is not part of the overall state
const Node1Output = new StateSchema({
  privateData: z.string(),
});

// Node 2 input only requests the private data available after node1
const Node2Input = new StateSchema({
  privateData: z.string(),
});

// The private data is only shared between node1 and node2
const node1: GraphNode<typeof OverallState> = (state) => {
  const output = { privateData: "set by node1" };
  console.log(`Entered node 'node1':\n\tInput: ${JSON.stringify(state)}.\n\tReturned: ${JSON.stringify(output)}`);
  return output;
};

const node2: GraphNode<typeof Node2Input> = (state) => {
  const output = { a: "set by node2" };
  console.log(`Entered node 'node2':\n\tInput: ${JSON.stringify(state)}.\n\tReturned: ${JSON.stringify(output)}`);
  return output;
};

// Node 3 only has access to the overall state (no access to private data from node1)
const node3: GraphNode<typeof OverallState> = (state) => {
  const output = { a: "set by node3" };
  console.log(`Entered node 'node3':\n\tInput: ${JSON.stringify(state)}.\n\tReturned: ${JSON.stringify(output)}`);
  return output;
};

// Connect nodes in a sequence
// node2 accepts private data from node1, whereas
// node3 does not see the private data.
const graph = new StateGraph(OverallState)
  .addNode("node1", node1)
  .addNode("node2", node2, { input: Node2Input })
  .addNode("node3", node3)
  .addEdge(START, "node1")
  .addEdge("node1", "node2")
  .addEdge("node2", "node3")
  .addEdge("node3", END)
  .compile();

// Invoke the graph with the initial state
const response = await graph.invoke({ a: "set at start" });

console.log(`\nOutput of graph invocation: ${JSON.stringify(response)}`);
```

```
	Input: {"a":"set at start"}.
	Returned: {"privateData":"set by node1"}
Entered node 'node2':
	Input: {"privateData":"set by node1"}.
	Returned: {"a":"set by node2"}
Entered node 'node3':
	Input: {"a":"set by node2"}.
	Returned: {"a":"set by node3"}
```

### 使用 Pydantic Model 作为 Graph State

@[StateGraph] 初始化时接受 @[`state_schema`] 参数，用于指定 Graph Node 可以访问和更新的 State “形状”。

示例通常使用 Python 原生 `TypedDict` 或 [`dataclass`](https://docs.python.org/3/library/dataclasses.html) 作为 `state_schema`，但 @[`state_schema`] 可以是任意 Python [Type](https://docs.python.org/3/library/stdtypes.html#type-objects)。

这里展示如何使用 [Pydantic BaseModel](https://docs.pydantic.dev/latest/api/base_model/) 作为 @[`state_schema`]，从而对**输入**增加 Runtime Validation。

<Note>
**已知限制**
* 当前 Graph Output **不会**自动变成 Pydantic Model Instance。
* Runtime Validation 只会对进入 Graph 第一个 Node 的输入执行，不会对后续 Node 或输出逐步验证。
* Pydantic Validation Error Trace 不会显示错误具体来自哪个 Node。
* Pydantic 的递归验证可能较慢。对于性能敏感应用，可以考虑使用 `dataclass`。
</Note>

```python
from langgraph.graph import StateGraph, START, END
from typing_extensions import TypedDict
from pydantic import BaseModel

# The overall state of the graph (this is the public state shared across nodes)
class OverallState(BaseModel):
    a: str

def node(state: OverallState):
    return {"a": "goodbye"}

# Build the state graph
builder = StateGraph(OverallState)
builder.add_node(node)  # node_1 is the first node
builder.add_edge(START, "node")  # Start the graph with node_1
builder.add_edge("node", END)  # End the graph after node_1
graph = builder.compile()

# Test the graph with a valid input
graph.invoke({"a": "hello"})
```

  ```python
      number: int
      # Pydantic will parse string booleans to bool
      flag: bool
  ```

### 其他 State 定义方式

虽然推荐使用 `StateSchema` 定义 State，LangGraph 也支持其他几种方式。

#### Channels API

Channels API 提供更底层的 State Management 控制。LangGraph 内置多种 Channel Type：

| Channel Type | 行为 | 适用场景 |
|--------------|----------|----------|
| `LastValue` | 保存最近一次值 | 每次更新直接覆盖的简单 Field |
| `BinaryOperatorAggregate` | 使用 Reducer Function 合并值 | 累加 Counter、List 等 |
| `Topic` | 把所有值收集成 Sequence | Event Stream、Audit Log |
| `EphemeralValue` | 每个 Superstep 之间重置 | 临时计算 State |

**使用 Object Shorthand：**

传入带 `reducer` 和 `default` 的对象会创建 `BinaryOperatorAggregate` Channel；传入 `null` 会创建 `LastValue` Channel：

```typescript
import { BaseMessage } from "@langchain/core/messages";
import { StateGraph } from "@langchain/langgraph";

interface WorkflowState {
  messages: BaseMessage[];
  question: string;
  answer: string;
}

const workflow = new StateGraph<WorkflowState>({
  channels: {
    // BinaryOperatorAggregate: combines values with a reducer
    messages: {
      reducer: (current, update) => current.concat(update),
      default: () => [],
    },
    // LastValue: stores the most recent value (null = no reducer)
    question: null,
    answer: null,
  },
});
```

**直接使用 Channel Class：**

如果需要更细控制，可以直接实例化 Channel Class：

```typescript
import { BaseMessage } from "@langchain/core/messages";
import { StateGraph, LastValue, BinaryOperatorAggregate, Topic } from "@langchain/langgraph";

interface WorkflowState {
  messages: BaseMessage[];
  question: string;
  events: string[];
}

const workflow = new StateGraph<WorkflowState>({
  channels: {
    messages: new BinaryOperatorAggregate<BaseMessage[]>(
      (current, update) => current.concat(update),
      () => []
    ),
    question: new LastValue<string>(),
    // Topic collects all values pushed during execution
    events: new Topic<string>(),
  },
});
```

#### Annotation.Root

`Annotation.Root` 提供声明式的 State + Reducer 定义方式。它与 `StateSchema` 类似，但语法不同：

```typescript
import { BaseMessage } from "@langchain/core/messages";
import { Annotation, StateGraph, messagesStateReducer } from "@langchain/langgraph";

const State = Annotation.Root({
  messages: Annotation<BaseMessage[]>({
    reducer: messagesStateReducer,
    default: () => [],
  }),
  question: Annotation<string>(),
  count: Annotation<number>({
    reducer: (current, update) => current + update,
    default: () => 0,
  }),
});

const graph = new StateGraph(State);
```

#### 使用 Zod v3 Object

使用 Zod v3 时，可以通过普通 `z.object()` Schema 定义 State。LangGraph 为 Zod v3 扩展 `.langgraph` Plugin，提供 `.reducer()` 与 `.metadata()`：

```typescript
import { z } from "zod/v3";
import { BaseMessage } from "@langchain/core/messages";
import { StateGraph, messagesStateReducer } from "@langchain/langgraph";

const State = z.object({
  messages: z
    .array(z.custom<BaseMessage>())
    .default([])
    .langgraph.reducer(messagesStateReducer),
  question: z.string().optional(),
  answer: z.string().optional(),
  count: z
    .number()
    .default(0)
    .langgraph.reducer((current, update) => current + update),
});

const graph = new StateGraph(State);
```

#### 使用 Zod v4 Object

Zod v4 使用基于 Registry 的方式。通过 LangGraph Registry 为 Schema Field 附加 Metadata：

```typescript
import * as z from "zod";
import { BaseMessage } from "@langchain/core/messages";
import { StateGraph, MessagesZodMeta, messagesStateReducer } from "@langchain/langgraph";
import { registry } from "@langchain/langgraph/zod";

const State = z.object({
  messages: z
    .array(z.custom<BaseMessage>())
    .default([])
    .register(registry, MessagesZodMeta),
  question: z.string().optional(),
  answer: z.string().optional(),
  count: z
    .number()
    .default(0)
    .register(registry, { reducer: (current: number, update: number) => current + update }),
});

const graph = new StateGraph(State);
```

#### 对比

| 方式 | Reducer | Type Safety | Zod Version | 推荐程度 |
|----------|----------|-------------|-------------|-------------|
| `StateSchema` | ✅ 内置 | ✅ 完整 | v3 或 v4 | ✅ 推荐 |
| Channels API | ✅ 手动 | ⚠️ 部分 | N/A | 高级场景 |
| `Annotation.Root` | ✅ 内置 | ✅ 完整 | N/A | Legacy |
| Zod v3 + `.langgraph` | ✅ Plugin | ✅ 完整 | 仅 v3 | Legacy |
| Zod v4 + Registry | ✅ Registry | ✅ 完整 | 仅 v4 | Legacy |

## 添加 Runtime Configuration

有时希望在调用 Graph 时动态配置行为，例如在 Runtime 指定使用哪个 LLM 或 System Prompt，同时又不希望把这些配置参数污染到 Graph State 中。

添加 Runtime Configuration 需要：

1. 为 Configuration 定义 Schema
2. 在 Node 或 Conditional Edge 的函数签名中接收 Runtime
3. 调用 Graph 时传入 Configuration

下面是一个简单示例：

:::python
```python
from langgraph.graph import END, StateGraph, START
from langgraph.runtime import Runtime
from typing_extensions import TypedDict

# 1. Specify config schema
class ContextSchema(TypedDict):
    my_runtime_value: str

# 2. Define a graph that accesses the config in a node
class State(TypedDict):
    my_state_value: str

def node(state: State, runtime: Runtime[ContextSchema]):  # [!code highlight]
    if runtime.context["my_runtime_value"] == "a":  # [!code highlight]
        return {"my_state_value": 1}
    elif runtime.context["my_runtime_value"] == "b":  # [!code highlight]
        return {"my_state_value": 2}
    else:
        raise ValueError("Unknown values.")

builder = StateGraph(State, context_schema=ContextSchema)  # [!code highlight]
builder.add_node(node)
builder.add_edge(START, "node")
builder.add_edge("node", END)

graph = builder.compile()

# 3. Pass in configuration at runtime:
print(graph.invoke({}, context={"my_runtime_value": "a"}))  # [!code highlight]
print(graph.invoke({}, context={"my_runtime_value": "b"}))  # [!code highlight]
```

```
{'my_state_value': 1}
{'my_state_value': 2}
```
:::

:::js

## 添加 Retry Policy

调用 API、数据库或 LLM 时经常需要自定义 Retry Policy。LangGraph 支持为每个 Node 单独配置重试策略。

:::python
把 `retry_policy` 参数传给 @[`add_node`] 即可配置。`retry_policy` 接受 `RetryPolicy` Named Tuple。下面使用默认参数创建并绑定到 Node：

```python
from langgraph.types import RetryPolicy

builder.add_node(
    "node_name",
    node_function,
    retry_policy=RetryPolicy(),
)
```

默认情况下，`retry_on` 使用 `default_retry_on`，会重试大多数 Exception，但不会重试以下类型：

* `ValueError`
* `TypeError`
* `ArithmeticError`
* `ImportError`
* `LookupError`
* `NameError`
* `SyntaxError`
* `RuntimeError`
* `ReferenceError`
* `StopIteration`
* `StopAsyncIteration`
* `OSError`

对于 `requests`、`httpx` 等常见 HTTP Library 的 Exception，默认只会重试 5xx Status Code。
:::

:::js
把 `retryPolicy` 参数传给 [`addNode`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.Graph.html#addnode) 即可配置。下面把默认 `RetryPolicy` 绑定到 Node：

```typescript
import { RetryPolicy } from "@langchain/langgraph";

const graph = new StateGraph(State)
  .addNode("nodeName", nodeFunction, { retryPolicy: {} })
  .compile();
```

默认 Retry Policy 会重试大多数异常，但不包括：

* `TypeError`
* `SyntaxError`
* `ReferenceError`
:::

## 设置 Node Timeout

使用 @[`add_node`] 的 `timeout` 参数，可以限制单次 Async Node Invocation 的最长运行时间。可以传秒数或 `datetime.timedelta`。

```python
import asyncio
from typing_extensions import TypedDict

from langgraph.errors import NodeTimeoutError
from langgraph.graph import END, START, StateGraph

class State(TypedDict):
    value: str

async def call_model(state: State) -> State:
    await asyncio.sleep(2)
    return {"value": "done"}

builder = StateGraph(State)
builder.add_node("model", call_model, timeout=1.0)
builder.add_edge(START, "model")
builder.add_edge("model", END)
graph = builder.compile()

try:
    await graph.ainvoke({"value": "start"})
except NodeTimeoutError:
    print("Node timed out")
```

Node Timeout 只支持 Async Node。如果对 Sync Node 设置 `timeout`，Graph 编译时会抛出错误，因为 Python 的同步执行无法在同一进程中安全取消。

Node 超时后，LangGraph 抛出 `NodeTimeoutError`，它继承自 Python 内置 `TimeoutError`。如果 Node 的 `retry_policy` 会重试 `TimeoutError` 或 `NodeTimeoutError`，那么超时 Attempt 会被重试。每次 Attempt 都有独立计时器。

超时 Attempt 不会提交其 Buffered Writes，这可以防止 State Update 或 Child Task Scheduling 在 Timeout Boundary 之后泄漏出去。

## 配置更细粒度 Timeout Policy

@[`add_node`] 的 `timeout=` 参数还可以接收 @[`TimeoutPolicy`]，分别控制 Run Timeout 与 Idle Timeout。

<Note>
Per-node Timeout 需要 `langgraph>=1.2`。
</Note>

```python
from langgraph.types import TimeoutPolicy

builder.add_node(
    "call_model",
    call_model,
    timeout=TimeoutPolicy(run_timeout=120, idle_timeout=30),
)
```

完整 Timeout Lifecycle、Idle Timeout Refresh Source 与 `runtime.heartbeat()` 参见[容错](/oss/langgraph/fault-tolerance#timeouts)。

## 处理 Node Error

@[`add_node`] 的 `error_handler=` 参数注册一个函数：当 Node 失败并耗尽所有 Retry 后执行。Handler 会接收当前 State 与带有 Failure Context 的 @[`NodeError`]，并可以通过 @[`Command`] 路由到恢复分支：

<Note>
Node-level Error Handler 需要 `langgraph>=1.2`。
</Note>

```python
from langgraph.errors import NodeError
from langgraph.types import Command, RetryPolicy

def payment_error_handler(state: State, error: NodeError) -> Command:
    return Command(
        update={"status": f"compensated: {error.error}"},
        goto="finalize",
    )

builder.add_node(
    "charge_payment",
    charge_payment,
    retry_policy=RetryPolicy(max_attempts=3, retry_on=ConnectionError),
    error_handler=payment_error_handler,
)
```

补偿模式与 `Command` Routing 参见[容错](/oss/langgraph/fault-tolerance#error-handling)。

## 设置 Graph-wide Node Defaults

<Note>
需要 `langgraph>=1.2`。
</Note>

使用 @[`set_node_defaults`]，可以一次性为 Graph 中所有 Node 设置 `retry_policy`、`timeout`、`cache_policy` 或 `error_handler`，无需在每次 @[`add_node`] 时重复。Per-node 显式配置始终优先；Default 会在 @[`StateGraph.compile`] 时应用：

```python
from langgraph.types import RetryPolicy, TimeoutPolicy

graph = (
    StateGraph(State)
    .set_node_defaults(
        retry_policy=RetryPolicy(max_attempts=3),
        timeout=TimeoutPolicy(run_timeout=30),
        error_handler=fallback_handler,
    )
    .add_node("a", node_a)
    .add_node("b", node_b, retry_policy=RetryPolicy(max_attempts=5))  # overrides default
    .add_edge(START, "a")
    .compile()
)
```

`retry_policy` 与 `timeout` Default 会应用到所有 Node，包括 Error Handler Node。`cache_policy` 与 `error_handler` Default 只应用于普通 Node——Handler 不会捕获自身错误，也不能安全缓存 Handler Result。Default 不会自动继承到 Subgraph。

完整优先级与适用范围参见[容错：Graph Defaults](/oss/langgraph/fault-tolerance#graph-defaults)。

### 在 Node 内访问 Execution Info

通过 `runtime.execution_info` 可以访问执行身份与 Retry 信息，而无需直接读取 `config`。

| 属性 | 类型 | 说明 |
| --------- | ---- | ----------- |
| `thread_id` | `str \| None` | 当前执行的 Thread ID；没有 Checkpointer 时为 `None` |
| `run_id` | `str \| None` | 当前执行的 Run ID；Config 未提供时为 `None` |
| `checkpoint_id` | `str` | 当前执行的 Checkpoint ID |
| `checkpoint_ns` | `str` | 当前执行的 Checkpoint Namespace |
| `task_id` | `str` | 当前执行的 Task ID |
| `node_attempt` | `int` | 当前 Node Attempt 编号（从 1 开始） |
| `node_first_attempt_time` | `float \| None` | 第一次 Attempt 开始的 Unix Timestamp；重试时保持不变 |

#### 获取 Thread 与 Run ID

```python
from langgraph.graph import StateGraph, START, END
from langgraph.runtime import Runtime
from typing_extensions import TypedDict

class State(TypedDict):
    result: str

def my_node(state: State, runtime: Runtime):
    info = runtime.execution_info
    print(f"Thread: {info.thread_id}, Run: {info.run_id}")
    return {"result": "done"}

builder = StateGraph(State)
builder.add_node("my_node", my_node)
builder.add_edge(START, "my_node")
builder.add_edge("my_node", END)
graph = builder.compile()
```

#### 根据 Retry State 调整行为

```python
from langgraph.graph import StateGraph, START, END
from langgraph.runtime import Runtime
from langgraph.types import RetryPolicy
from typing_extensions import TypedDict

class State(TypedDict):
    result: str

def my_node(state: State, runtime: Runtime):
    info = runtime.execution_info
    if info.node_attempt > 1:
        return {"result": call_fallback_api()}
    return {"result": call_primary_api()}

builder = StateGraph(State)
builder.add_node("my_node", my_node, retry_policy=RetryPolicy(max_attempts=3))
builder.add_edge(START, "my_node")
builder.add_edge("my_node", END)
graph = builder.compile()
```

即使没有 Retry Policy，`execution_info` 仍然可用：`node_attempt` 默认值为 `1`，`node_first_attempt_time` 为 Node 开始执行的时间。

### 在 Node 内访问 Server Info

### 在 Node 内访问 Drain State

```python
from langgraph.runtime import Runtime

def my_node(state: State, runtime: Runtime) -> State:
```

| -------- | ---- | ----------- |

## 添加 Node Cache

当某个操作代价很高（耗时或耗钱），可以使用 Node Cache 避免重复执行。LangGraph 支持为每个 Node 单独配置 Cache Policy。

## 创建分支

并行执行 Node 对提升 Graph 整体性能非常重要。LangGraph 原生支持 Fan-out / Fan-in，并可以结合普通 Edge 与 Conditional Edge 构建分支数据流。

### 并行运行 Graph Node

下面从 `A` 扇出到 `B` 和 `C`，再汇聚到 `D`。State 使用加法 Reducer，使各分支写入的值被累计，而不是相互覆盖。

:::python
```python
import operator
from typing import Annotated, Any
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    aggregate: Annotated[list, operator.add]

def a(state: State):
    print(f'Adding "A" to {state["aggregate"]}')
    return {"aggregate": ["A"]}

def b(state: State):
    print(f'Adding "B" to {state["aggregate"]}')
    return {"aggregate": ["B"]}

def c(state: State):
    print(f'Adding "C" to {state["aggregate"]}')
    return {"aggregate": ["C"]}

def d(state: State):
    print(f'Adding "D" to {state["aggregate"]}')
    return {"aggregate": ["D"]}

builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(c)
builder.add_node(d)
builder.add_edge(START, "a")
builder.add_edge("a", "b")
builder.add_edge("a", "c")
builder.add_edge("b", "d")
builder.add_edge("c", "d")
builder.add_edge("d", END)
graph = builder.compile()
```
:::

:::js
```typescript
import { StateGraph, StateSchema, ReducedValue, GraphNode, START, END } from "@langchain/langgraph";
import * as z from "zod";

const State = new StateSchema({
  aggregate: new ReducedValue(
    z.array(z.string()).default(() => []),
    { reducer: (x, y) => x.concat(y) }
  ),
});

const nodeA: GraphNode<typeof State> = (state) => ({ aggregate: ["A"] });
const nodeB: GraphNode<typeof State> = (state) => ({ aggregate: ["B"] });
const nodeC: GraphNode<typeof State> = (state) => ({ aggregate: ["C"] });
const nodeD: GraphNode<typeof State> = (state) => ({ aggregate: ["D"] });

const graph = new StateGraph(State)
  .addNode("a", nodeA)
  .addNode("b", nodeB)
  .addNode("c", nodeC)
  .addNode("d", nodeD)
  .addEdge(START, "a")
  .addEdge("a", "b")
  .addEdge("a", "c")
  .addEdge("b", "d")
  .addEdge("c", "d")
  .addEdge("d", END)
  .compile();
```
:::

使用 Reducer 后，各 Node 的更新会累积。`b` 和 `c` 在同一个 [Superstep](/oss/langgraph/graph-api#graphs) 中并发执行；`d` 会在二者都完成后执行。

<Note>
并行 Superstep 中 Update 的顺序不保证稳定。如果业务需要确定顺序，建议把各分支输出写到独立 Field，并同时附带排序值，随后显式排序。
</Note>

<Accordion title="异常如何处理？">
LangGraph 以 [Superstep](/oss/langgraph/graph-api#graphs) 为事务边界。并行分支虽然同时执行，但整个 Superstep 是**事务性的**：如果其中任意 Branch 抛出 Exception，则这个 Superstep 的 State Update 都不会应用。

使用 [Checkpointer](/oss/langgraph/persistence) 时，同一 Superstep 中成功 Node 的结果仍会保存；恢复执行后，这些成功 Node 不会重复运行。

对于容易失败的 API Call，可以：

1. 在 Node 中使用普通 Python / TypeScript Error Handling 捕获并处理异常。
2. 配置 `RetryPolicy`，仅重试失败 Branch，不重复成功 Branch。
</Accordion>

<Tip>
可以通过 Invocation Config 的 `max_concurrency` 控制最大并发任务数量。
</Tip>

:::python
### 延迟 Node 执行

当分支长度不同，希望某个 Node 等待所有 Pending Task 完成后再运行时，可以使用 `defer=True`。

```python
import operator
from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    aggregate: Annotated[list, operator.add]

def a(state: State): return {"aggregate": ["A"]}
def b(state: State): return {"aggregate": ["B"]}
def b_2(state: State): return {"aggregate": ["B_2"]}
def c(state: State): return {"aggregate": ["C"]}
def d(state: State): return {"aggregate": ["D"]}

builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(b_2)
builder.add_node(c)
builder.add_node(d, defer=True)
builder.add_edge(START, "a")
builder.add_edge("a", "b")
builder.add_edge("a", "c")
builder.add_edge("b", "b_2")
builder.add_edge("b_2", "d")
builder.add_edge("c", "d")
builder.add_edge("d", END)
graph = builder.compile()
```

`b` 与 `c` 同一个 Superstep 并发执行；由于 `d` 设置了 `defer=True`，它会等所有 Pending Task 完成，因此会等完整 `b` Branch 结束。

当所有 Branch 都必然执行时，也可以使用 List-form Edge：

```python
builder.add_edge(["b_2", "c"], "d")
```

三种方式含义不同：

- **List of start nodes**：只有列出的所有 Node 都执行完成后，`d` 才执行一次。如果某个 Node 根本没被 Conditional Edge 选择，`d` 不会执行。
- **Separate edges**：只要某个 Incoming Branch 在某个 Superstep 完成，`d` 就会运行；如果分支长度不同，可能多次执行。
- **Separate edges + `defer=True`**：等待所有被实际选择的 Branch 完成后，只执行一次 `d`。

`defer=True` 等待的是整个 Graph 中没有 Pending Task，而不仅是直接连接到它的 Branch。针对该 Node 的 `Send` 仍会单独触发一次执行。
:::

### 条件分支

如果 Fan-out 需要根据 Runtime State 动态变化，可以使用 Conditional Edge 选择一个或多个目标 Node。

:::python
```python
import operator
from typing import Annotated, Literal, Sequence
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    aggregate: Annotated[list, operator.add]
    which: str

def a(state: State):
    return {"aggregate": ["A"], "which": "c"}

def b(state: State): return {"aggregate": ["B"]}
def c(state: State): return {"aggregate": ["C"]}

builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(c)
builder.add_edge(START, "a")
builder.add_edge("b", END)
builder.add_edge("c", END)

def conditional_edge(state: State) -> Literal["b", "c"]:
    return state["which"]

builder.add_conditional_edges("a", conditional_edge)
graph = builder.compile()
```
:::

:::js
```typescript
import { StateGraph, StateSchema, ReducedValue, GraphNode, ConditionalEdgeRouter, START, END } from "@langchain/langgraph";
import * as z from "zod";

const State = new StateSchema({
  aggregate: new ReducedValue(
    z.array(z.string()).default(() => []),
    { reducer: (x, y) => x.concat(y) }
  ),
  which: z.string(),
});

const nodeA: GraphNode<typeof State> = (state) => ({ aggregate: ["A"], which: "c" });
const nodeB: GraphNode<typeof State> = (state) => ({ aggregate: ["B"] });
const nodeC: GraphNode<typeof State> = (state) => ({ aggregate: ["C"] });

const conditionalEdge: ConditionalEdgeRouter<{ InputSchema: typeof State; Nodes: "b" | "c" }> = (state) => {
  return state.which as "b" | "c";
};

const graph = new StateGraph(State)
  .addNode("a", nodeA)
  .addNode("b", nodeB)
  .addNode("c", nodeC)
  .addEdge(START, "a")
  .addEdge("b", END)
  .addEdge("c", END)
  .addConditionalEdges("a", conditionalEdge)
  .compile();
```
:::

```python
        return ["c", "d"]
    return ["b", "c"]
```

## Map-Reduce 与 Send API

LangGraph 使用 Send API 支持 Map-Reduce 和其他高级 Branching Pattern。`Send` 可以为每个动态分支提供独立 Input，同时让这些分支的输出通过 Reducer 汇总回主 State。

:::python
```python
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send
from typing_extensions import TypedDict, Annotated
import operator

class OverallState(TypedDict):
    topic: str
    subjects: list[str]
    jokes: Annotated[list[str], operator.add]
    best_selected_joke: str

def generate_topics(state: OverallState):
    return {"subjects": ["lions", "elephants", "penguins"]}

def generate_joke(state: OverallState):
    joke_map = {
        "lions": "Why don't lions like fast food? Because they can't catch it!",
        "elephants": "Why don't elephants use computers? They're afraid of the mouse!",
        "penguins": "Why don't penguins like talking to strangers at parties? Because they find it hard to break the ice."
    }
    return {"jokes": [joke_map[state["subject"]]]}

def continue_to_jokes(state: OverallState):
    return [Send("generate_joke", {"subject": s}) for s in state["subjects"]]

def best_joke(state: OverallState):
    return {"best_selected_joke": "penguins"}

builder = StateGraph(OverallState)
builder.add_node("generate_topics", generate_topics)
builder.add_node("generate_joke", generate_joke)
builder.add_node("best_joke", best_joke)
builder.add_edge(START, "generate_topics")
builder.add_conditional_edges("generate_topics", continue_to_jokes, ["generate_joke"])
builder.add_edge("generate_joke", "best_joke")
builder.add_edge("best_joke", END)
graph = builder.compile()
```
:::

:::js

## 创建和控制循环

构建带 Loop 的 Graph 时，需要一种终止执行的机制。最常见的方式是使用 [Conditional Edge](/oss/langgraph/graph-api#conditional-edges)，在满足终止条件时路由到 [END](/oss/langgraph/graph-api#end-node)。

还可以在 Invocation 或 Streaming 时设置 Graph Recursion Limit。它定义 Graph 在抛出错误之前允许执行多少个 [Superstep](/oss/langgraph/graph-api#graphs)。

<Tip>
如果希望达到 Recursion Limit 时返回最后 State，而不是抛错，请参阅下一节。
</Tip>

:::python
```python
builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)

def route(state: State) -> Literal["b", END]:
    if termination_condition(state):
        return END
    else:
        return "b"

builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "a")
graph = builder.compile()
```
:::

:::js
```typescript
const route: ConditionalEdgeRouter<{ InputSchema: typeof State; Nodes: "b" }> = (state) => {
  if (terminationCondition(state)) {
    return END;
  } else {
    return "b";
  }
};

const graph = new StateGraph(State)
  .addNode("a", nodeA)
  .addNode("b", nodeB)
  .addEdge(START, "a")
  .addConditionalEdges("a", route)
  .addEdge("b", "a")
```

:::

下面定义一个简单 Loop，使用 Conditional Edge 实现终止条件：

:::python
```python
import operator
from typing import Annotated, Literal
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    aggregate: Annotated[list, operator.add]

def a(state: State):
    print(f'Node A sees {state["aggregate"]}')
    return {"aggregate": ["A"]}

def b(state: State):
    print(f'Node B sees {state["aggregate"]}')
    return {"aggregate": ["B"]}

builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)

def route(state: State) -> Literal["b", END]:
    if len(state["aggregate"]) < 7:
        return "b"
    else:
        return END

builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "a")
graph = builder.compile()
```
:::

:::js
```typescript
import { StateGraph, StateSchema, ReducedValue, GraphNode, ConditionalEdgeRouter, START, END } from "@langchain/langgraph";
import * as z from "zod";

const State = new StateSchema({
  aggregate: new ReducedValue(
    z.array(z.string()).default(() => []),

  ),
});

const nodeB: GraphNode<typeof State> = (state) => ({ aggregate: ["B"] });

};

  .addNode("a", nodeA)

```

### 强制 Recursion Limit

某些应用无法保证一定会达到业务终止条件。可以设置 Graph [Recursion Limit](/oss/langgraph/graph-api#recursion-limit)，在给定数量的 [Superstep](/oss/langgraph/graph-api#graphs) 后抛出 `GraphRecursionError`，再由应用捕获处理。

```python
from langgraph.errors import GraphRecursionError

```

```typescript
import { GraphRecursionError } from "@langchain/langgraph";

try {
  await graph.invoke({ aggregate: [] }, { recursionLimit: 4 });

    console.log("Recursion Error");
  }
}
```

:::python
<Accordion title="扩展示例：达到 Recursion Limit 时返回 State">
如果不希望抛出 `GraphRecursionError`，可以在 State 中加入 Remaining Step 计数，并在接近限制时主动走向 END。

LangGraph 提供特殊的 `RemainingSteps` Annotation。底层会创建一个 `ManagedValue` Channel，它只在本次 Graph Run 生命周期内存在。

```python
import operator
from typing import Annotated, Literal
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.managed.is_last_step import RemainingSteps

class State(TypedDict):
    aggregate: Annotated[list, operator.add]
    remaining_steps: RemainingSteps

def a(state: State):
    return {"aggregate": ["A"]}

def b(state: State):
    return {"aggregate": ["B"]}

builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)

def route(state: State) -> Literal["b", END]:
    if state["remaining_steps"] <= 2:
        return END
    else:
        return "b"

builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "a")
graph = builder.compile()

result = graph.invoke({"aggregate": []}, {"recursion_limit": 4})
print(result)
```
</Accordion>

:::python
<Accordion title="扩展示例：包含 Branch 的 Loop">
更复杂的情况下，一个 Loop 中的某一步可能 Fan-out 到两个 Node。可以把 Graph 理解为一组循环的 Superstep：

1. Node A
2. Node B
3. Node C 与 D 并行
4. Node A
5. ……

List-form Edge 会等 `c`、`d` 两个 Branch 都完成，再返回 `a`。关于它与 Separate Edge 的区别参见[延迟 Node 执行](#defer-node-execution)。

```python
    aggregate: Annotated[list, operator.add]

def a(state: State): return {"aggregate": ["A"]}
def b(state: State): return {"aggregate": ["B"]}
def c(state: State): return {"aggregate": ["C"]}
def d(state: State): return {"aggregate": ["D"]}

builder.add_node(a)
builder.add_node(b)
builder.add_node(c)
builder.add_node(d)

        return "b"
    return END

builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "c")
builder.add_edge("b", "d")
builder.add_edge(["c", "d"], "a")
graph = builder.compile()
```
</Accordion>

## 使用 `Command` 同时更新 State 与控制 Flow

有时希望在同一个 Node 内既更新 State，又决定下一步去哪个 Node。LangGraph 支持从 Node 返回 @[Command]：

:::python
```python
def my_node(state: State) -> Command[Literal["my_other_node"]]:
    return Command(
        update={"foo": "bar"},
        goto="my_other_node"
    )
```
:::

:::js
```typescript
import { Command } from "@langchain/langgraph";

const myNode = (state: State): Command => {
  return new Command({
    update: { foo: "bar" },
    goto: "myOtherNode"
  });
};
```
:::

下面是一个完整例子：先执行 A，然后由 A 的结果决定去 B 还是 C。

:::python
```python
import random
from typing_extensions import TypedDict, Literal
from langgraph.graph import StateGraph, START
from langgraph.types import Command

class State(TypedDict):
    foo: str

def node_a(state: State) -> Command[Literal["node_b", "node_c"]]:
    print("Called A")
    value = random.choice(["b", "c"])
    goto = "node_b" if value == "b" else "node_c"
    return Command(
        update={"foo": value},
        goto=goto,
    )

def node_b(state: State):
    print("Called B")
    return {"foo": state["foo"] + "b"}

def node_c(state: State):
    print("Called C")
    return {"foo": state["foo"] + "c"}

builder = StateGraph(State)
builder.add_edge(START, "node_a")
builder.add_node(node_a)
builder.add_node(node_b)
builder.add_node(node_c)
graph = builder.compile()
```

<Warning>
`Command[Literal["node_b", "node_c"]]` Return Type Annotation 对 Graph Rendering 很重要，它告诉 LangGraph `node_a` 可能导航到哪些 Node。
</Warning>
:::

:::js
```typescript
import { StateGraph, StateSchema, GraphNode, Command, START } from "@langchain/langgraph";
import * as z from "zod";

const State = new StateSchema({ foo: z.string() });

const nodeA: GraphNode<{ InputSchema: typeof State; Nodes: "nodeB" | "nodeC" }> = (state) => {
  console.log("Called A");
  const value = Math.random() > 0.5 ? "b" : "c";
  const goto = value === "b" ? "nodeB" : "nodeC";
  return new Command({ update: { foo: value }, goto });
};

const nodeB: GraphNode<typeof State> = (state) => ({ foo: state.foo + "b" });
const nodeC: GraphNode<typeof State> = (state) => ({ foo: state.foo + "c" });

const graph = new StateGraph(State)
  .addNode("nodeA", nodeA, { ends: ["nodeB", "nodeC"] })
  .addNode("nodeB", nodeB)
  .addNode("nodeC", nodeC)
  .addEdge(START, "nodeA")
  .compile();
```

<Warning>
JavaScript / TypeScript 版本需要通过 `ends` 指明 `nodeA` 可能导航到哪些 Node，这对 Graph Rendering 是必要的。
</Warning>
:::

### 导航到 Parent Graph 中的 Node

使用 [Subgraph](/oss/langgraph/use-subgraphs) 时，有时需要从 Subgraph Node 跳转到 Parent Graph 中另一个 Node。此时在 `Command` 中指定 `graph=Command.PARENT`：

:::python
```python
def my_node(state: State) -> Command[Literal["other_subgraph"]]:
    return Command(
        update={"foo": "bar"},
        goto="other_subgraph",
        graph=Command.PARENT
    )
```
:::

:::js
```typescript
const myNode = (state: State): Command => {
  return new Command({
    update: { foo: "bar" },
    goto: "otherSubgraph",
    graph: Command.PARENT
  });
};
```
:::

<Warning>
**使用 `Command.PARENT` 更新 State**
如果从 Subgraph Node 向 Parent Graph Node 发送的 Update 修改了 Parent 与 Subgraph 共同拥有的 State Key，那么 Parent Graph 中这个 Key **必须**定义 [Reducer](/oss/langgraph/graph-api#reducers)。
</Warning>

:::python
```python
import operator
from typing_extensions import Annotated

class State(TypedDict):
    foo: Annotated[str, operator.add]

def node_a(state: State):
    print("Called A")
    value = random.choice(["a", "b"])
    goto = "node_b" if value == "a" else "node_c"
    return Command(
        update={"foo": value},
        goto=goto,
        graph=Command.PARENT,
    )

subgraph = StateGraph(State).add_node(node_a).add_edge(START, "node_a").compile()

def node_b(state: State):
    print("Called B")
    return {"foo": "b"}

def node_c(state: State):
    print("Called C")
    return {"foo": "c"}

builder = StateGraph(State)
builder.add_edge(START, "subgraph")
builder.add_node("subgraph", subgraph)
builder.add_node(node_b)
builder.add_node(node_c)
graph = builder.compile()
```
:::

### 在 Tool 内使用

一个常见需求是在 Tool 内直接更新 Graph State。例如 Customer Support 应用可以在对话开始时，根据 Account ID 查询 Customer Info。Tool 可以返回 `Command(update={...})`：

:::python
```python
from langchain.tools import ToolRuntime

@tool
def lookup_user_info(runtime: ToolRuntime):
    """Use this to look up user information to better assist them with their questions."""
    user_info = get_user_info(runtime.server_info.user.identity)
    return Command(
        update={
            "user_info": user_info,
            "messages": [ToolMessage("Successfully looked up user information", tool_call_id=runtime.tool_call_id)]
        }
    )
```
:::

:::js
```typescript
import { tool } from "@langchain/core/tools";
import { Command } from "@langchain/langgraph";
import * as z from "zod";

const lookupUserInfo = tool(
  async (input, runtime) => {
    const userId = runtime.serverInfo?.user?.identity;
    const userInfo = getUserInfo(userId);
    return new Command({
      update: {
        userInfo: userInfo,
        messages: [{
          role: "tool",
          content: "Successfully looked up user information",
          tool_call_id: runtime.toolCall.id
        }]
      }
    });
  },
  {
    name: "lookupUserInfo",
    description: "Use this to look up user information to better assist them with their questions.",
    schema: z.object({}),
  }
);
```
:::

<Warning>
Tool 返回 @[`Command`] 时，如果 Graph 的 Message History 存在于 `messages`（或其他 State Key），`Command.update` **必须**包含这个 Message Key，而且其中必须包含与 Tool Call 对应的 `ToolMessage`。LLM Provider 要求带 Tool Call 的 AI Message 后紧跟 Tool Result Message，否则 Message History 不合法。
</Warning>

如果 Tool 会通过 @[`Command`] 更新 State，推荐使用预构建 @[`ToolNode`]。它能够自动处理 Tool 返回的 `Command` 并传播到 Graph State。自定义 Tool-calling Node 则需要手动把 Tool 返回的 `Command` 作为 Node Update 传播。

## 可视化 Graph

LangGraph 可以可视化任意 [Graph](https://reference.langchain.com/python/langgraph/graphs/)，包括 @[`StateGraph`]。

:::python
下面通过绘制 Fractal Graph 展示可视化能力：

```python
import random
from typing import Annotated, Literal
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

class State(TypedDict):
    messages: Annotated[list, add_messages]

class MyNode:
    def __init__(self, name: str):
        self.name = name
    def __call__(self, state: State):
        return {"messages": [("assistant", f"Called node {self.name}")]}

def route(state) -> Literal["entry_node", END]:
    if len(state["messages"]) > 10:
        return END
    return "entry_node"

def add_fractal_nodes(builder, current_node, level, max_level):
    if level > max_level:
        return
    num_nodes = random.randint(1, 3)
    for i in range(num_nodes):
        nm = ["A", "B", "C"][i]
        node_name = f"node_{current_node}_{nm}"
        builder.add_node(node_name, MyNode(node_name))
        builder.add_edge(current_node, node_name)
        r = random.random()
        if r > 0.2 and level + 1 < max_level:
            add_fractal_nodes(builder, node_name, level + 1, max_level)
        elif r > 0.05:
            builder.add_conditional_edges(node_name, route, node_name)
        else:
            builder.add_edge(node_name, END)

def build_fractal_graph(max_level: int):
    builder = StateGraph(State)
    entry_point = "entry_node"
    builder.add_node(entry_point, MyNode(entry_point))
    builder.add_edge(START, entry_point)
    add_fractal_nodes(builder, entry_point, 1, max_level)
    builder.add_edge(entry_point, END)
    return builder.compile()

app = build_fractal_graph(3)
```
:::

:::js
下面创建一张简单 Graph 展示 Visualization：

```typescript
import { StateGraph, StateSchema, MessagesValue, ReducedValue, GraphNode, ConditionalEdgeRouter, START, END } from "@langchain/langgraph";
import * as z from "zod";

const State = new StateSchema({
  messages: MessagesValue,
  value: new ReducedValue(
    z.number().default(0),
    { reducer: (x, y) => x + y }
  ),
});

const node1: GraphNode<typeof State> = (state) => ({ value: state.value + 1 });
const node2: GraphNode<typeof State> = (state) => ({ value: state.value * 2 });

const router: ConditionalEdgeRouter<{ InputSchema: typeof State; Nodes: "node2" }> = (state) => {
  if (state.value < 10) return "node2";
  return END;
};

const app = new StateGraph(State)
  .addNode("node1", node1)
  .addNode("node2", node2)
  .addEdge(START, "node1")
  .addConditionalEdges("node1", router)
  .addEdge("node2", "node1")
  .compile();
```
:::

### PNG

:::python
也可以直接渲染成 `.png`，支持三种方式：

* Mermaid.ink API（无需额外 Package）
* Mermaid + Pyppeteer（需要 `pip install pyppeteer`）
* Graphviz（需要 `pip install graphviz`）

**使用 Mermaid.Ink**

```python
from IPython.display import Image, display
from langchain_core.runnables.graph import CurveStyle, MermaidDrawMethod, NodeStyles

display(Image(app.get_graph().draw_mermaid_png()))
```

![Fractal graph visualization](/oss/images/graph_api_image_10.png)

**使用 Mermaid + Pyppeteer**

```python
import nest_asyncio

nest_asyncio.apply()

display(
    Image(
        app.get_graph().draw_mermaid_png(
            curve_style=CurveStyle.LINEAR,
            node_colors=NodeStyles(first="#ffdfba", last="#baffc9", default="#fad7de"),
            wrap_label_n_words=9,
            output_file_path=None,
            draw_method=MermaidDrawMethod.PYPPETEER,
            background_color="white",
            padding=10,
        )
    )
)
```

**使用 Graphviz**

```python
try:
    display(Image(app.get_graph().draw_png()))
except ImportError:
    print(
        "You likely need to install dependencies for pygraphviz, see more here https://github.com/pygraphviz/pygraphviz/blob/main/INSTALL.txt"
    )
```
:::

:::js
也可以直接把 Graph 渲染成 `.png`，这里使用 Mermaid.ink API：

```typescript
import * as fs from "node:fs/promises";

const drawableGraph = await app.getGraphAsync();
const image = await drawableGraph.drawMermaidPng();
const imageBuffer = new Uint8Array(await image.arrayBuffer());

await fs.writeFile("graph.png", imageBuffer);
```
