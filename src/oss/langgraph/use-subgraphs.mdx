本指南介绍如何使用 Subgraph。**Subgraph（子图）**本身是一张[图](/oss/langgraph/graph-api#graphs)，但它会作为另一张图中的一个[节点](/oss/langgraph/graph-api#nodes)使用。

Subgraph 适合以下场景：
- 构建[多智能体系统](/oss/langchain/multi-agent)
- 在多张图中复用一组 Node
- 分布式开发：当不同团队需要独立开发图的不同部分时，可以把每一部分定义为 Subgraph。只要遵守 Subgraph Interface（输入和输出 Schema），Parent Graph 就不需要知道 Subgraph 内部的实现细节

## 定义 Subgraph 的通信方式

添加 Subgraph 时，需要明确 Parent Graph 与 Subgraph 如何通信：

| 模式 | 何时使用 | State Schema |
|---------|------------|--------------|
| [在 Node 内调用 Subgraph](#call-a-subgraph-inside-a-node) | Parent 与 Subgraph 的 **State Schema 不同**（没有共享 Key），或者需要在二者之间转换 State | 编写 Wrapper Function，把 Parent State 映射为 Subgraph Input，再把 Subgraph Output 映射回 Parent State |
| [把 Subgraph 直接作为 Node](#add-a-subgraph-as-a-node) | Parent 与 Subgraph **共享 State Key**——Subgraph 与 Parent 读写相同的 Channel | 把已编译 Subgraph 直接传给 `add_node`，不需要 Wrapper Function |

<a id="invoke-a-graph-from-a-node"></a>
### 在 Node 内调用 Subgraph

当 Parent Graph 与 Subgraph 使用**不同的 State Schema**（没有共享 Key）时，可以在一个 Node Function 内调用 Subgraph。这在[多智能体](/oss/langchain/multi-agent)系统中很常见，例如你希望每个 Agent 都拥有自己的私有 Message History。

Node Function 在调用 Subgraph 前先把 Parent State 转换成 Subgraph State；Subgraph 返回后，再把结果转换回 Parent State。

:::python
```python
from typing_extensions import TypedDict
from langgraph.graph.state import StateGraph, START

class SubgraphState(TypedDict):
    bar: str

# Subgraph

def subgraph_node_1(state: SubgraphState):
    return {"bar": "hi! " + state["bar"]}

subgraph_builder = StateGraph(SubgraphState)
subgraph_builder.add_node(subgraph_node_1)
subgraph_builder.add_edge(START, "subgraph_node_1")
subgraph = subgraph_builder.compile()

# Parent graph

class State(TypedDict):
    foo: str

def call_subgraph(state: State):
    # Transform the state to the subgraph state
    subgraph_output = subgraph.invoke({"bar": state["foo"]})  # [!code highlight]
    # Transform response back to the parent state
    return {"foo": subgraph_output["bar"]}

builder = StateGraph(State)
builder.add_node("node_1", call_subgraph)
builder.add_edge(START, "node_1")
graph = builder.compile()
```
:::

:::js
```typescript
import { StateGraph, StateSchema, START } from "@langchain/langgraph";
import * as z from "zod";

const SubgraphState = new StateSchema({
  bar: z.string(),
});

// Subgraph
const subgraphBuilder = new StateGraph(SubgraphState)
  .addNode("subgraphNode1", (state) => {
    return { bar: "hi! " + state.bar };
  })
  .addEdge(START, "subgraphNode1");

const subgraph = subgraphBuilder.compile();

// Parent graph
const State = new StateSchema({
  foo: z.string(),
});

// Transform the state to the subgraph state and back
const builder = new StateGraph(State)
  .addNode("node1", async (state) => {
    const subgraphOutput = await subgraph.invoke({ bar: state.foo });
    return { foo: subgraphOutput.bar };
  })
  .addEdge(START, "node1");

const graph = builder.compile();
```
:::

  ```typescript
  import * as z from "zod";

  // Define subgraph
  const SubgraphState = new StateSchema({
    // note that none of these keys are shared with the parent graph state
    bar: z.string(),
    baz: z.string(),
  });

  const subgraphBuilder = new StateGraph(SubgraphState)
    .addNode("subgraphNode1", (state) => {
      return { baz: "baz" };
    })
    .addNode("subgraphNode2", (state) => {
      return { bar: state.bar + state.baz };
    })
    .addEdge(START, "subgraphNode1")
    .addEdge("subgraphNode1", "subgraphNode2");

  const subgraph = subgraphBuilder.compile();

  // Define parent graph
  const ParentState = new StateSchema({
    foo: z.string(),
  });

  const builder = new StateGraph(ParentState)
    .addNode("node1", (state) => {
      return { foo: "hi! " + state.foo };
    })

    for await (const token of message.text) {

    }
  }
  ```

  ```python
  from typing_extensions import TypedDict
  from langgraph.graph.state import StateGraph, START, END

  class GrandChildState(TypedDict):
      my_grandchild_key: str

  def grandchild_1(state: GrandChildState) -> GrandChildState:
      # NOTE: child or parent keys will not be accessible here
      return {"my_grandchild_key": state["my_grandchild_key"] + ", how are you"}


  grandchild = StateGraph(GrandChildState)
  grandchild.add_node("grandchild_1", grandchild_1)

  grandchild.add_edge(START, "grandchild_1")
  grandchild.add_edge("grandchild_1", END)

  grandchild_graph = grandchild.compile()

  # Child graph
  class ChildState(TypedDict):
      my_child_key: str

  def call_grandchild_graph(state: ChildState) -> ChildState:
      # NOTE: parent or grandchild keys won't be accessible here
      grandchild_graph_input = {"my_grandchild_key": state["my_child_key"]}
      grandchild_graph_output = grandchild_graph.invoke(grandchild_graph_input)
      return {"my_child_key": grandchild_graph_output["my_grandchild_key"] + " today?"}

  child = StateGraph(ChildState)
  # We're passing a function here instead of just compiled graph (`grandchild_graph`)
  child.add_node("child_1", call_grandchild_graph)
  child.add_edge(START, "child_1")
  child.add_edge("child_1", END)
  child_graph = child.compile()

  # Parent graph
  class ParentState(TypedDict):
      my_key: str

  def parent_1(state: ParentState) -> ParentState:
      # NOTE: child or grandchild keys won't be accessible here

  def parent_2(state: ParentState) -> ParentState:
      return {"my_key": state["my_key"] + " bye!"}

  def call_child_graph(state: ParentState) -> ParentState:
  ```

### 把 Subgraph 作为 Node

当 Parent Graph 与 Subgraph **共享 State Key** 时，可以把已编译 Subgraph 直接传给 `add_node`。不需要 Wrapper Function——Subgraph 会自动读取和写入 Parent 的 State Channel。例如在[多智能体](/oss/langchain/multi-agent)系统中，多个 Agent 往往会通过共享的 [messages](/oss/langgraph/graph-api#why-use-messages) Key 通信。

如果 Subgraph 与 Parent 共享 State Key，可以按下面两步添加：

:::python
1. 定义 Subgraph Workflow（下面示例中的 `subgraph_builder`）并编译
2. 定义 Parent Graph Workflow 时，把已编译 Subgraph 传给 @[`add_node`]

```python
subgraph_builder.add_edge(START, "subgraph_node_1")

# Parent graph
```

## Subgraph 持久化

使用 Subgraph 时，需要决定它的内部数据在多次调用之间如何保存。比如，一个 Customer Support Bot 会把任务委派给多个 Specialist Subagent：其中的“Billing Expert”应该记住客户之前问过的问题，还是每次调用都从空白状态开始？

`.compile()` 的 `checkpointer` 参数控制 Subgraph 的持久化行为：

| 模式 | `checkpointer=` | 行为 |
|------|-----------------|----------|
| [Per-invocation](#per-invocation-default) | `None`（默认） | 每次调用都从新状态开始，同时继承 Parent 的 Checkpointer，以便在单次调用内部支持[中断](/oss/langgraph/interrupts)和[持久化执行](/oss/langgraph/persistence)。 |
| [Per-thread](#per-thread) | `True` | 同一 Thread 中的多次调用会累积 State。下一次调用从上一次结束位置继续。 |
| [Stateless](#stateless) | `False` | 完全不使用 Checkpoint——就像普通函数调用一样运行。不支持 Interrupt 或 Durable Execution。 |

对于大多数应用，Per-invocation 都是正确选择，包括 Subagent 处理彼此独立请求的[多智能体](/oss/langchain/multi-agent)系统。当 Subagent 确实需要多轮会话记忆时，再使用 Per-thread，例如一个会在多次交流中不断积累上下文的 Research Assistant。

<Note>
如果希望使用 Subgraph 的持久化能力（Interrupt、State Inspection、Per-thread Memory），Parent Graph 必须使用 Checkpointer 编译。参见[持久化](/oss/langgraph/persistence)。
</Note>

<Info>
下面的示例使用 LangChain 的 @[`create_agent`] 构建 Agent。`create_agent` 底层生成的就是一张 [LangGraph Graph](/oss/langgraph/graph-api)，因此这里的 Subgraph Persistence 概念同样直接适用。如果你使用原始 LangGraph `StateGraph` 构建，也可以使用同样的模式和配置；详情参见 [Graph API](/oss/langgraph/graph-api)。
</Info>

### Stateful

Stateful Subgraph 会继承 Parent Graph 的 Checkpointer，因此能够使用[中断](/oss/langgraph/interrupts)、[持久化](/oss/langgraph/persistence)和 State Inspection。两种 Stateful Mode 的区别在于 State 保留多久。

#### Per-invocation（默认）

<Tip>
这是大多数应用推荐使用的模式，包括把 Subagent 当作 Tool 调用的[多智能体](/oss/langchain/multi-agent)系统。它在保持每次调用彼此隔离的同时，仍然支持[中断](/oss/langgraph/interrupts)、[持久化](/oss/langgraph/persistence)和并行调用。
</Tip>

如果 Subgraph 的每次调用彼此独立，而且 Subagent 不需要记住之前的调用，就使用 Per-invocation。它也是最常见的模式，尤其适合 Subagent 处理一次性任务的场景，例如“查询这个客户的订单”或“总结这份文档”。

省略 `checkpointer` 或设为 `None`。每次调用都会从新状态开始，但在单次调用内部，Subgraph 会继承 Parent 的 Checkpointer，因此可以使用 `interrupt()` 暂停和恢复。

下面使用两个 Subagent（Fruit Expert 和 Veggie Expert），并把它们包装成外层 Agent 的 Tool：

:::python

```python
from langchain.agents import create_agent
from langchain.tools import tool
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import Command, interrupt

@tool
def fruit_info(fruit_name: str) -> str:
    """Look up fruit info."""
    return f"Info about {fruit_name}"

@tool
def veggie_info(veggie_name: str) -> str:
    """Look up veggie info."""
    return f"Info about {veggie_name}"

# Subagents - no checkpointer setting (inherits parent)
fruit_agent = create_agent(
    model="gpt-5.4-mini",
    tools=[fruit_info],
    prompt="You are a fruit expert. Use the fruit_info tool. Respond in one sentence.",
)

veggie_agent = create_agent(
    model="gpt-5.4-mini",
    tools=[veggie_info],
    prompt="You are a veggie expert. Use the veggie_info tool. Respond in one sentence.",
)

# Wrap subagents as tools for the outer agent
@tool
def ask_fruit_expert(question: str) -> str:
    """Ask the fruit expert. Use for ALL fruit questions."""
    response = fruit_agent.invoke(
        {"messages": [{"role": "user", "content": question}]},
    )
    return response["messages"][-1].content

@tool
def ask_veggie_expert(question: str) -> str:
    """Ask the veggie expert. Use for ALL veggie questions."""
    response = veggie_agent.invoke(
        {"messages": [{"role": "user", "content": question}]},
    )
    return response["messages"][-1].content

# Outer agent with checkpointer
agent = create_agent(
    model="gpt-5.4-mini",
    tools=[ask_fruit_expert, ask_veggie_expert],
    prompt=(
        "You have two experts: ask_fruit_expert and ask_veggie_expert. "
        "ALWAYS delegate questions to the appropriate expert."
    ),
    checkpointer=MemorySaver(),
)
```

#### Per-thread

当 Subagent 需要记住之前的交互时，使用 Per-thread 持久化。例如，一个会在多轮交流中逐步积累上下文的 Research Assistant，或者一个需要记录自己已经修改过哪些文件的 Coding Assistant。Subagent 的对话历史和其他数据会在同一 Thread 上的多次调用之间累积；每次调用都会从上一次结束位置继续。

通过 `checkpointer=True` 编译即可启用该行为。

<Warning>
Per-thread Subgraph 不支持并行 Tool Call。当 LLM 把一个 Per-thread Subagent 当作 Tool 使用时，它可能试图并行调用同一个 Tool 多次（例如同时询问 Fruit Expert 关于苹果和香蕉）。这会导致 Checkpoint 冲突，因为两次调用都写入同一个 Namespace。

下面的示例使用 LangChain 的 `ToolCallLimitMiddleware` 来防止这种情况。如果你使用纯 LangGraph `StateGraph`，则需要自行阻止并行 Tool Call，例如配置模型禁用并行工具调用，或者增加逻辑确保同一个 Subgraph 不会被并行调用多次。
</Warning>

下面的示例使用一个以 `checkpointer=True` 编译的 Fruit Expert Subagent：

:::python

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolCallLimitMiddleware
from langchain.tools import tool
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import Command, interrupt

@tool
def fruit_info(fruit_name: str) -> str:
    """Look up fruit info."""
    return f"Info about {fruit_name}"

# Subagent with checkpointer=True for persistent state
fruit_agent = create_agent(
    model="gpt-5.4-mini",
    tools=[fruit_info],
    prompt="You are a fruit expert. Use the fruit_info tool. Respond in one sentence.",
    checkpointer=True,  # [!code highlight]
)

# Wrap subagent as a tool for the outer agent
@tool
def ask_fruit_expert(question: str) -> str:
    """Ask the fruit expert. Use for ALL fruit questions."""
    response = fruit_agent.invoke(
        {"messages": [{"role": "user", "content": question}]},
    )
    return response["messages"][-1].content

# Outer agent with checkpointer
# Use ToolCallLimitMiddleware to prevent parallel calls to per-thread subagents,
# which would cause checkpoint conflicts.
agent = create_agent(
    model="gpt-5.4-mini",
    tools=[ask_fruit_expert],
    prompt="You have a fruit expert. ALWAYS delegate fruit questions to ask_fruit_expert.",
    middleware=[  # [!code highlight]
        ToolCallLimitMiddleware(tool_name="ask_fruit_expert", run_limit=1),  # [!code highlight]
    ],  # [!code highlight]
    checkpointer=MemorySaver(),
)
```

  当你有多个**不同的** Per-thread Subgraph（例如 Fruit Expert 和 Veggie Expert）时，每一个都需要自己的存储空间，否则它们的 Checkpoint 会互相覆盖。这称为 **Namespace Isolation（命名空间隔离）**。

  如果你[在 Node 内调用 Subgraph](#call-a-subgraph-inside-a-node)，LangGraph 会根据调用顺序分配 Namespace（第一次调用、第二次调用等）。这意味着，如果日后改变调用顺序，就可能导致某个 Subgraph 加载到另一个 Subgraph 的 State。为了避免这种情况，可以把每个 Subagent 包装在一个拥有唯一 Node Name 的 `StateGraph` 中，从而获得稳定、唯一的 Namespace：

  ```python
  from langgraph.graph import MessagesState, StateGraph

  def create_sub_agent(model, *, name, **kwargs):
      """Wrap an agent with a unique node name for namespace isolation."""
      agent = create_agent(model=model, name=name, **kwargs)
      return (
          StateGraph(MessagesState)
          .add_node(name, agent)  # unique name → stable namespace  # [!code highlight]
          .add_edge("__start__", name)
          .compile()
      )

  fruit_agent = create_sub_agent(
      "gpt-5.4-mini", name="fruit_agent",
      tools=[fruit_info], prompt="...", checkpointer=True,
  )
  veggie_agent = create_sub_agent(
      "gpt-5.4-mini", name="veggie_agent",
      tools=[veggie_info], prompt="...", checkpointer=True,
  )

  config = {"configurable": {"thread_id": "1"}}

  # First call - LLM calls both fruit and veggie experts
  response = agent.invoke(
      {"messages": [{"role": "user", "content": "Tell me about cherries and broccoli"}]},
      config=config,
  )
  # Fruit subagent message count: 4
  # Veggie subagent message count: 4

  # Second call - both agents accumulate independently
  response = agent.invoke(
      {"messages": [{"role": "user", "content": "Now tell me about oranges and carrots"}]},
      config=config,
  )
  # Fruit subagent message count: 8 (remembers cherries!)
  # Veggie subagent message count: 8 (remembers broccoli!)
  ```

  直接[作为 Node 添加的 Subgraph](#add-a-subgraph-as-a-node)已经会自动获得基于 Node Name 的 Namespace，因此不需要额外 Wrapper。

### Stateless

如果希望 Subagent 像普通函数一样运行、不承担任何 Checkpoint 开销，可以使用 Stateless。此时 Subgraph 无法暂停/恢复，也无法获得[持久化执行](/oss/langgraph/persistence)能力。使用 `checkpointer=False` 编译。

<Warning>
没有 Checkpoint 时，Subgraph 就没有 Durable Execution。如果进程在运行途中崩溃，Subgraph 无法从中间位置恢复，只能从头重新执行。
</Warning>

:::python
```python
subgraph_builder = StateGraph(...)
subgraph = subgraph_builder.compile(checkpointer=False)  # [!code highlight]
```
:::

:::js
```typescript
const subgraphBuilder = new StateGraph(...);
const subgraph = subgraphBuilder.compile({ checkpointer: false });  // [!code highlight]
```
:::

### Checkpointer 速查

通过 `.compile()` 的 `checkpointer` 参数控制 Subgraph Persistence：

:::python
```python
subgraph = builder.compile(checkpointer=False)  # or True / None
```
:::

:::js
```typescript
const subgraph = builder.compile({ checkpointer: false });  // or true, or null
```

| 功能 | Per-invocation（默认） | Per-thread | Stateless |
|---|---|---|---|
| `checkpointer=` | `None` | `True` | `False` |
| Interrupt（HITL） | ✅ | ✅ | ❌ |
| 多轮记忆 | ❌ | ✅ | ❌ |
| 多次调用（不同 Subgraph） | ✅ | <Tooltip tip="同一 Node 中调用多个 Per-thread Subgraph 可能发生 Namespace 冲突，但存在规避方案。">⚠️</Tooltip> | ✅ |
| 多次调用（同一 Subgraph） | ✅ | ❌ | ✅ |
| State Inspection | <Tooltip tip="Per-invocation 持久化只能检查当前 Invocation（处于中断状态时）的 State。每次 Invocation 都从新 State 开始，所以 Invocation 完成后不存在跨调用累积 State。">⚠️</Tooltip> | ✅ | ❌ |

- **Interrupt（HITL）**：Subgraph 可以使用 [interrupt()](/oss/langgraph/interrupts) 暂停执行、等待用户输入，然后从中断位置恢复。
- **多轮记忆**：Subgraph 会在同一 [Thread](/oss/langgraph/checkpointers#threads) 的多次 Invocation 之间保留 State；下一次调用从上一次留下的 State 继续，而不是重新开始。
- **多次调用（不同 Subgraph）**：同一个 Node 中可以调用多个不同 Subgraph，而不会发生 Checkpoint Namespace 冲突。
- **多次调用（同一 Subgraph）**：同一个 Subgraph Instance 可以在一个 Node 中调用多次。Per-thread 模式下这些调用会写同一个 Checkpoint Namespace 并发生冲突，因此应改用 Per-invocation。
- **State Inspection**：可通过 `get_state(config, subgraphs=True)` 查看 Subgraph State，用于调试和监控。

## 查看 Subgraph State

启用[持久化](/oss/langgraph/persistence)后，可以通过 `subgraphs` Option 检查 Subgraph State。对于 [Stateless](#stateless)（`checkpointer=False`），不会保存任何 Subgraph Checkpoint，因此也就无法读取 Subgraph State。

<Note>
查看 Subgraph State 的前提，是 LangGraph 能够**静态发现**这个 Subgraph，也就是它被[作为 Node 添加](#add-a-subgraph-as-a-node)，或在[某个 Node 内调用](#call-a-subgraph-inside-a-node)。如果 Subgraph 是在[工具](/oss/langchain/tools)函数或其他间接层中调用（例如 [Subagents](/oss/langchain/multi-agent/subagents) 模式），则无法通过这里的方式查看 State。不过无论嵌套多深，Interrupt 仍然会向最外层 Graph 传播。
</Note>

:::python
<Tabs>
  <Tab title="Per-invocation">
  只返回**当前 Invocation** 的 Subgraph State。每一次 Invocation 都从新状态开始。

  ```python
  from langgraph.graph import START, StateGraph
  from langgraph.checkpoint.memory import MemorySaver
  from langgraph.types import interrupt, Command
  from typing_extensions import TypedDict

  class State(TypedDict):
      foo: str

  # Subgraph
  def subgraph_node_1(state: State):
      value = interrupt("Provide value:")
      return {"foo": state["foo"] + value}

  subgraph_builder = StateGraph(State)
  subgraph_builder.add_node(subgraph_node_1)
  subgraph_builder.add_edge(START, "subgraph_node_1")
  subgraph = subgraph_builder.compile()  # inherits parent checkpointer

  # Parent graph
  builder = StateGraph(State)
  builder.add_node("node_1", subgraph)
  builder.add_edge(START, "node_1")

  checkpointer = MemorySaver()
  graph = builder.compile(checkpointer=checkpointer)

  config = {"configurable": {"thread_id": "1"}}

  graph.invoke({"foo": ""}, config)

  # View subgraph state for the current invocation
  subgraph_state = graph.get_state(config, subgraphs=True).tasks[0].state  # [!code highlight]

  # Resume the subgraph
  graph.invoke(Command(resume="bar"), config)
  ```
  </Tab>

  返回该 Thread 上跨所有 Invocation **累计**的 Subgraph State。

  ```python
  subgraph_builder = StateGraph(MessagesState)

  builder = StateGraph(MessagesState)

  builder.add_edge(START, "agent")

  checkpointer = MemorySaver()

  config = {"configurable": {"thread_id": "1"}}

  graph.invoke({"messages": [{"role": "user", "content": "hi"}]}, config)
  graph.invoke({"messages": [{"role": "user", "content": "what did I say?"}]}, config)

  # View accumulated subgraph state (includes messages from both invocations)
  subgraph_state = graph.get_state(config, subgraphs=True).tasks[0].state  # [!code highlight]
  ```

## 流式输出 Subgraph 结果

如果需要观察嵌套 Graph 的执行过程，我们推荐使用[事件流](/oss/langgraph/event-streaming)：`stream.subgraphs` Projection 会发现每一次嵌套 Run，并直接暴露其 `path`、`messages` 和 `values`，不需要手动解析 Namespace String。

:::python
```python
stream = graph.stream_events({"foo": "foo"}, version="v3")  # [!code highlight]

for subgraph in stream.subgraphs:
    print(subgraph.graph_name, subgraph.path)

    for snapshot in subgraph.values:
        print(subgraph.path, snapshot)
```

如果需要 Raw Protocol Event，可以直接遍历 Stream，然后按 `event["method"]` 与 `event["params"]["namespace"]` 过滤：

```python
stream = graph.stream_events({"foo": "foo"}, version="v3")
for event in stream:
    if event["method"] == "updates":
        print(event["params"]["namespace"], event["params"]["data"])
```
:::

:::js
```typescript
const stream = await graph.streamEvents(
  { foo: "foo" },
  {
    subgraphs: true,   // [!code highlight]
    version: "v3",
  }
);
for await (const snapshot of stream.values) {
  console.log(snapshot);
}
```

  ```python
  from typing_extensions import TypedDict
  from langgraph.graph.state import StateGraph, START

  # Define subgraph
  class SubgraphState(TypedDict):
      foo: str
      bar: str

  def subgraph_node_1(state: SubgraphState):
      return {"bar": "bar"}

  def subgraph_node_2(state: SubgraphState):

      # and is sending update on the shared state key ('foo')
      return {"foo": state["foo"] + state["bar"]}

  subgraph_builder.add_edge(START, "subgraph_node_1")
  subgraph_builder.add_edge("subgraph_node_1", "subgraph_node_2")

  class ParentState(TypedDict):
      foo: str

  def node_1(state: ParentState):
      return {"foo": "hi! " + state["foo"]}

  builder = StateGraph(ParentState)
  builder.add_node("node_1", node_1)
  builder.add_node("node_2", subgraph)
  builder.add_edge(START, "node_1")
  builder.add_edge("node_1", "node_2")
  ```
