**Functional API** 允许你在尽量少修改现有代码的情况下，为应用加入 LangGraph 的核心能力，包括[持久化](/oss/langgraph/persistence)、[记忆](/oss/langgraph/add-memory)、[人在回路](/oss/langgraph/interrupts)和[流式输出](/oss/langgraph/streaming)。

它专门用于把这些能力接入已经存在的过程式代码。你可以继续使用语言本身提供的分支和控制流，例如 `if`、`for` 循环以及普通函数调用。与很多要求把代码重构为显式 Pipeline 或 DAG 的数据编排框架不同，Functional API 不会强制一种僵硬的执行模型。

Functional API 使用两个核心构建块：

:::python
* **`@entrypoint`**：把一个函数标记为 Workflow 的入口，封装业务逻辑并管理执行流程，包括长时间运行的 Task 和 Interrupt。
* **@[`@task`]**：表示一个独立工作单元，例如 API 调用或数据处理步骤。Task 可以在 Entrypoint 内异步执行，并返回一个类似 Future 的对象，可以 `await`，也可以同步 Resolve。
:::

:::js
* **`entrypoint`**：封装 Workflow 逻辑并管理执行流程，包括长时间运行的 Task 和 Interrupt。
* **`task`**：表示一个独立工作单元，例如 API 调用或数据处理步骤。Task 可以在 Entrypoint 内异步执行，并返回可等待或解析的 Promise-like 结果。
:::

这样可以用一层很薄的抽象，为普通工作流加入 State 管理和 Streaming 能力。

<Tip>
关于 Functional API 的具体使用方法，请参阅[使用 Functional API](/oss/langgraph/use-functional-api)。
</Tip>

## Functional API 与 Graph API

如果更喜欢声明式开发方式，可以使用 LangGraph 的 [Graph API](/oss/langgraph/graph-api)，以“图”的方式定义 Workflow。两套 API 共享同一底层 Runtime，因此也可以在同一个应用中混合使用。

主要区别包括：

* **控制流**：Functional API 不要求你先思考图结构，可以直接使用标准语言结构来定义 Workflow，通常需要编写的代码更少。
* **短期记忆**：**Graph API** 需要声明 [**State**](/oss/langgraph/graph-api#state)，并可能需要定义 [**Reducer**](/oss/langgraph/graph-api#reducers) 来管理 Graph State Update。`@entrypoint` 和 `@task` 不要求显式 State 管理，因为它们的状态位于函数作用域内，不会默认跨函数共享。
* **Checkpoint**：两套 API 都会生成和使用 Checkpoint。在 **Graph API** 中，每个 [Super-step](/oss/langgraph/graph-api) 结束后都会生成新的 Checkpoint。在 **Functional API** 中，Task 执行结果会保存到该 Entrypoint 已有的 Checkpoint 中，而不是每执行一个 Task 都创建新的 Checkpoint。
* **可视化**：Graph API 很容易把 Workflow 可视化为图，有助于调试、理解和团队共享。Functional API 的图结构是在 Runtime 动态生成，因此不支持同样的可视化能力。

## 示例

下面构建一个简单应用：先写一篇文章，然后通过[中断](/oss/langgraph/interrupts)请求人工审核。

:::python
```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt

@task
def write_essay(topic: str) -> str:
    """Write an essay about the given topic."""
    time.sleep(1) # A placeholder for a long-running task.
    return f"An essay about topic: {topic}"

@entrypoint(checkpointer=InMemorySaver())
def workflow(topic: str) -> dict:
    """A simple workflow that writes an essay and asks for a review."""
    essay = write_essay("cat").result()
    is_approved = interrupt({
        # Any json-serializable payload provided to interrupt as argument.
        # It will be surfaced on the client side as an Interrupt when streaming data
        # from the workflow.
        "essay": essay, # The essay we want reviewed.
        # We can add any additional information that we need.
        # For example, introduce a key called "action" with some instructions.
        "action": "Please approve/reject the essay",
    })

    return {
        "essay": essay, # The essay that was generated
        "is_approved": is_approved, # Response from HIL
    }
```
:::

:::js
```typescript
import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";

const writeEssay = task("writeEssay", async (topic: string) => {
  // A placeholder for a long-running task.
  await new Promise((resolve) => setTimeout(resolve, 1000));
  return `An essay about topic: ${topic}`;
});

const workflow = entrypoint(
  { checkpointer: new MemorySaver(), name: "workflow" },
  async (topic: string) => {
    const essay = await writeEssay(topic);
    const isApproved = interrupt({
      // Any json-serializable payload provided to interrupt as argument.
      // It will be surfaced on the client side as an Interrupt when streaming data
      // from the workflow.
      essay, // The essay we want reviewed.
      // We can add any additional information that we need.
      // For example, introduce a key called "action" with some instructions.
      action: "Please approve/reject the essay",
    });

    return {
      essay, // The essay that was generated
      isApproved, // Response from HIL
    };
  }
);
```
:::

<Accordion title="详细说明">
  这个 Workflow 会围绕主题 “cat” 写一篇文章，然后暂停等待人工审核。它可以无限期保持在 Interrupt 状态，直到外部提供审核结果。

  Workflow 恢复时会从函数开头重新执行，但由于 `writeEssay` Task 的结果已经保存，因此会直接从 Checkpoint 读取结果，而不会再次计算。

## Entrypoint

:::python
@[`@entrypoint`] 装饰器可以把普通函数转换成 Workflow。它封装 Workflow 逻辑并管理执行流程，包括处理**长时间运行的 Task** 和[中断](/oss/langgraph/interrupts)。
:::

:::js
@[`entrypoint`][entrypoint] 函数可以把普通函数转换成 Workflow。它封装 Workflow 逻辑并管理执行流程，包括处理**长时间运行的 Task** 和[中断](/oss/langgraph/interrupts)。
:::

### 定义

:::python
通过 `@entrypoint` 装饰器修饰函数即可定义一个 **Entrypoint**。

函数**必须接收一个位置参数**，该参数作为 Workflow 输入。如果需要传入多项数据，可以让第一个参数使用字典类型。

使用 `entrypoint` 修饰函数后会生成一个 @[`Pregel`][Pregel.stream] 实例，用于管理 Workflow 执行，例如 Streaming、Resume 和 Checkpoint。

通常应该向 `@entrypoint` 传入一个 **Checkpointer**，以启用持久化和**人在回路**等功能。

<Tabs>
    <Tab title="同步">
    ```python
    from langgraph.func import entrypoint

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(some_input: dict) -> int:
        # some logic that may involve long-running tasks like API calls,
        # and may be interrupted for human-in-the-loop.
        ...
        return result
    ```
    </Tab>
    <Tab title="异步">
    ```python
    from langgraph.func import entrypoint

    @entrypoint(checkpointer=checkpointer)
    async def my_workflow(some_input: dict) -> int:
        # some logic that may involve long-running tasks like API calls,
        # and may be interrupted for human-in-the-loop
        ...
        return result
    ```
    </Tab>
</Tabs>
:::

:::js
通过调用 `entrypoint` 并传入配置和函数即可定义一个 **Entrypoint**。

函数**必须接收一个位置参数**作为 Workflow 输入。如果需要传入多项数据，可以让第一个参数使用对象类型。

使用函数创建 Entrypoint 后会生成一个 Workflow 实例，用于管理执行流程，例如 Streaming、Resume 和 Checkpoint。

通常也应该向 `entrypoint` 传入一个 **Checkpointer**，以启用持久化和**人在回路**等功能。

```typescript
import { entrypoint } from "@langchain/langgraph";

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (someInput: Record<string, any>): Promise<number> => {
    // some logic that may involve long-running tasks like API calls,
    // and may be interrupted for human-in-the-loop
    return result;
  }
);
```
:::

<Warning>
**序列化**

为了支持 Checkpoint，Entrypoint 的**输入**和**输出**必须可以进行 JSON 序列化。更多信息参阅[序列化](#serialization)。
</Warning>

:::python
### 可注入参数

声明 `entrypoint` 时，可以请求 Runtime 自动注入额外参数：

| 参数 | 说明 |
| --- | --- |
| **previous** | 访问给定 Thread 上一个 `checkpoint` 对应的 State。参阅[短期记忆](#short-term-memory)。 |
| **store** | [BaseStore][langgraph.store.base.BaseStore] 实例，可用于[长期记忆](/oss/langgraph/use-functional-api#long-term-memory)。 |
| **writer** | 在 Async Python < 3.11 下访问 StreamWriter。详见 [Functional API Streaming](/oss/langgraph/use-functional-api#streaming)。 |
| **config** | 访问 Runtime Config。参阅 [RunnableConfig](https://python.langchain.com/docs/concepts/runnables/#runnableconfig)。 |

<Warning>
请使用正确的参数名称和类型标注来声明这些参数。
</Warning>

<Accordion title="请求可注入参数">
  ```python
  from langchain_core.runnables import RunnableConfig
  from langgraph.func import entrypoint
  from langgraph.store.base import BaseStore
  from langgraph.store.memory import InMemoryStore
  from langgraph.checkpoint.memory import InMemorySaver
  from langgraph.types import StreamWriter

  in_memory_checkpointer = InMemorySaver(...)
  in_memory_store = InMemoryStore(...)  # An instance of InMemoryStore for long-term memory

  @entrypoint(
      checkpointer=in_memory_checkpointer,  # Specify the checkpointer
      store=in_memory_store  # Specify the store
  )
  def my_workflow(
      some_input: dict,  # The input (e.g., passed via `invoke`)
      *,
      previous: Any = None, # For short-term memory
      store: BaseStore,  # For long-term memory
      writer: StreamWriter,  # For streaming custom data
      config: RunnableConfig  # For accessing the configuration passed to the entrypoint
  ) -> ...:
  ```
</Accordion>
:::

### 短期记忆

当 `entrypoint` 配置了 `checkpointer` 后，同一 **Thread ID** 上连续 Invocation 之间的信息会被保存到[检查点](/oss/langgraph/checkpointers#checkpoints)中。

:::python
这允许你通过 `previous` 参数访问上一次 Invocation 保存的 State。

默认情况下，`previous` 就是上一次 Invocation 的返回值。

```python
@entrypoint(checkpointer=checkpointer)
def my_workflow(number: int, *, previous: Any = None) -> int:
    previous = previous or 0
    return number + previous

config = {
    "configurable": {
        "thread_id": "some_thread_id"
    }
}

my_workflow.invoke(1, config)  # 1 (previous was None)
my_workflow.invoke(2, config)  # 3 (previous was 1 from the previous invocation)
```
:::

:::js
这允许你通过 `getPreviousState` 函数访问上一次 Invocation 保存的 State。

默认情况下，`getPreviousState` 返回上一次 Invocation 的返回值。

```typescript
import { entrypoint, getPreviousState } from "@langchain/langgraph";

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (number: number) => {
    const previous = getPreviousState<number>() ?? 0;
    return number + previous;
  }
);

const config = {
  configurable: {
    thread_id: "some_thread_id",
  },
};

await myWorkflow.invoke(1, config); // 1 (previous was undefined)
await myWorkflow.invoke(2, config); // 3 (previous was 1 from the previous invocation)
```
:::

#### `entrypoint.final`

:::python
@[`entrypoint.final`][entrypoint.final] 是一种特殊 Primitive，可以从 Entrypoint 返回，用于将**写入 Checkpoint 的值**与 **Entrypoint 的返回值**解耦。

第一个值是 Entrypoint 的返回值，第二个值则会保存到 Checkpoint。类型标注为 `entrypoint.final[return_type, save_type]`。

```python
@entrypoint(checkpointer=checkpointer)
def my_workflow(number: int, *, previous: Any = None) -> entrypoint.final[int, int]:
    previous = previous or 0
    # This will return the previous value to the caller, saving
    # 2 * number to the checkpoint, which will be used in the next invocation
    # for the `previous` parameter.
    return entrypoint.final(value=previous, save=2 * number)

config = {
    "configurable": {
        "thread_id": "1"
    }
}

my_workflow.invoke(3, config)  # 0 (previous was None)
my_workflow.invoke(1, config)  # 6 (previous was 3 * 2 from the previous invocation)
```
:::

:::js
@[`entrypoint.final`][entrypoint.final] 是一种特殊 Primitive，可以从 Entrypoint 返回，用于将**写入 Checkpoint 的值**与 **Entrypoint 的返回值**解耦。

第一个值是 Entrypoint 的返回值，第二个值则会保存到 Checkpoint。

```typescript
import { entrypoint, getPreviousState } from "@langchain/langgraph";

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (number: number) => {
    const previous = getPreviousState<number>() ?? 0;
    // This will return the previous value to the caller, saving
    // 2 * number to the checkpoint, which will be used in the next invocation
    // for the `previous` parameter.
    return entrypoint.final({
      value: previous,
      save: 2 * number,
    });
  }
);

const config = {
  configurable: {
    thread_id: "1",
  },
};

await myWorkflow.invoke(3, config); // 0 (previous was undefined)
await myWorkflow.invoke(1, config); // 6 (previous was 3 * 2 from the previous invocation)
```
:::

## Task

**Task** 表示一个独立的工作单元，例如 API 调用或数据处理步骤。它有两个关键特征：

* **异步执行**：Task 天然适合异步执行，因此多个操作可以并发运行而不互相阻塞。
* **Checkpoint**：Task 结果会被保存到 Checkpoint，使 Workflow 可以从最后保存的状态继续执行。更多信息参阅[持久化](/oss/langgraph/persistence)。

### 定义

:::python
使用 `@task` 装饰器包装普通 Python 函数即可定义 Task。

```python
from langgraph.func import task

@task()
def slow_computation(input_value):
    # Simulate a long-running operation
    ...
    return result
```
:::

:::js
使用 `task` 函数包装普通函数即可定义 Task。

```typescript
import { task } from "@langchain/langgraph";

const slowComputation = task("slowComputation", async (inputValue: any) => {
  // Simulate a long-running operation
  return result;
});
```
:::

<Warning>
**序列化**

为了支持 Checkpoint，Task 的**输出**必须能够进行 JSON 序列化。
</Warning>

### 执行

**Task** 只能从 **Entrypoint**、另一个 **Task** 或 [State Graph Node](/oss/langgraph/graph-api#nodes) 中调用。

不能直接从主应用代码调用 Task。

:::python
调用一个 **Task** 时，会立即返回一个 Future Object。Future 是未来将可用的结果占位符。

要获取 Task 结果，可以同步等待（`result()`），也可以异步 `await`。

<Tabs>
    <Tab title="同步调用">
    ```python
    @entrypoint(checkpointer=checkpointer)
    def my_workflow(some_input: int) -> int:
        future = slow_computation(some_input)
        return future.result()  # Wait for the result synchronously
    ```
    </Tab>
    <Tab title="异步调用">
    ```python
    @entrypoint(checkpointer=checkpointer)
    async def my_workflow(some_input: int) -> int:
        return await slow_computation(some_input)  # Await result asynchronously
    ```
    </Tab>
</Tabs>
:::

:::js
调用一个 **Task** 时，会返回可以 `await` 的 Promise。

```typescript
const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (someInput: number): Promise<number> => {
    return await slowComputation(someInput);
  }
);
```
:::

## 什么时候应该使用 Task

以下场景适合使用 **Task**：

* **Checkpoint**：需要保存长时间运行操作的结果，使 Workflow 恢复时不用重新计算。
* **人在回路**：如果 Workflow 需要人工介入，必须使用 **Task** 封装随机性或外部非确定性操作（例如 API 调用），以确保 Workflow 能够正确恢复。更多信息参阅[确定性](#determinism)。
* **并行执行**：对于 I/O Bound 工作，Task 可以并行执行多个操作而不互相阻塞，例如同时调用多个 API。
* **可观测性**：把操作封装成 Task 后，可以使用 [LangSmith](/langsmith/observability)跟踪 Workflow 进度和每个独立操作的执行。
* **可重试工作**：如果某项工作需要因故障或不一致而重试，Task 可以提供明确的封装边界来管理 Retry Logic。

## 序列化

LangGraph 的序列化有两个关键要求：

1. `entrypoint` 的输入和输出必须可进行 JSON 序列化。
2. `task` 的输出必须可进行 JSON 序列化。

:::python
这些要求是实现 Checkpoint 和 Workflow Resume 的基础。建议使用字典、列表、字符串、数字和布尔值等 Python Primitive，确保输入输出可序列化。
:::

:::js
这些要求是实现 Checkpoint 和 Workflow Resume 的基础。建议使用 Object、Array、String、Number 和 Boolean 等 Primitive，确保输入输出可序列化。
:::

序列化保证 Task Result 和 Intermediate Value 等 Workflow State 可以可靠保存和恢复。这对于人在回路、容错和并行执行非常关键。

当 Workflow 配置了 Checkpointer 时，如果提供无法序列化的输入或输出，会在 Runtime 产生错误。

## 确定性

恢复一个 Workflow Run 时，代码**不会**从之前停止的**同一行代码**继续执行。执行会回到某个 Checkpoint Boundary，然后让 Workflow 向前**重放（Replay）**，直到再次到达暂停位置。

对于 Functional API，Replay 会从 **Entrypoint** 开头开始；LangGraph 会从 Checkpointer 恢复已经完成的 [**Task**](/oss/langgraph/functional-api#task) 和 [**Subgraph**](/oss/langgraph/use-subgraphs) 结果，而不是重新计算它们。这样，即使 Task 长时间运行或结果本身具有非确定性，也能保持跨暂停点的步骤顺序。

如果要使用**人在回路**等功能，必须把非确定性工作（例如随机值）和副作用（例如写文件或 API 调用）放在 [**Task**](/oss/langgraph/functional-api#task) 中。

不同 Workflow Run 可以产生不同结果，但恢复某一个**特定 Thread** 时，应该重放与该 Thread 已持久化的 Task 和 Subgraph Result 相同的结果。

为了让 Workflow 保持确定性并能够稳定 Replay，请遵循以下原则：

* **避免重复工作**：如果 Entrypoint 中连续执行多个副作用，例如日志、文件写入或网络请求，应把每个副作用分别封装成 Task。这样 Resume 时可以从 Checkpointer 恢复输出，而不是再次执行。
* **封装非确定性操作**：会在不同尝试中产生不同结果的值，例如随机数或墙上时间，应放进 Task 中，使 Replay 与已保存的 Checkpoint 对齐。
* **使用幂等操作**：关于 Task 部分失败与重试，参阅[幂等性](#idempotency)。

## 幂等性

幂等性意味着同一个操作执行多次仍产生相同效果。当 Step 因故障被重新运行时，这可以避免重复 API 调用和冗余处理。API 调用应始终放在 **Task** 函数中以支持 Checkpoint，同时也要设计为可幂等执行。

这对写数据的操作尤其重要。

Workflow Resume 时，LangGraph 会从 Checkpoint Replay 已完成 Task 的结果；但已经启动、尚未完成的 Task 可能会再次运行，因此副作用必须具备幂等性。可以使用 Idempotency Key，或者在执行前检查已有结果，避免意外重复。

## 常见陷阱

### 处理副作用

应把写文件、发送邮件等副作用封装进 Task，避免 Workflow Resume 时重复执行。

<Tabs>
    <Tab title="错误示例">
    下面直接在 Workflow 中执行文件写入，因此 Resume 时会第二次执行该副作用。

    :::python
    ```python
    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        # This code will be executed a second time when resuming the workflow.
        # Which is likely not what you want.
        with open("output.txt", "w") as f:  # [!code highlight]
            f.write("Side effect executed")  # [!code highlight]
        value = interrupt("question")
        return value
```
    :::

    :::js
    ```typescript
    import { entrypoint, interrupt } from "@langchain/langgraph";
    import fs from "fs";

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow },
      async (inputs: Record<string, any>) => {
        // This code will be executed a second time when resuming the workflow.
        // Which is likely not what you want.
        fs.writeFileSync("output.txt", "Side effect executed");
        const value = interrupt("question");
        return value;
      }
    );
    ```
    :::
    </Tab>
    <Tab title="正确示例">
    下面把副作用封装进 Task，因此 Resume 时可以保持一致执行语义。

    :::python
    ```python
    from langgraph.func import task

    @task  # [!code highlight]
    def write_to_file():  # [!code highlight]
        with open("output.txt", "w") as f:
            f.write("Side effect executed")

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        # The side effect is now encapsulated in a task.
        write_to_file().result()
        value = interrupt("question")
        return value
```
    :::

    :::js
    ```typescript
    import { entrypoint, task, interrupt } from "@langchain/langgraph";
    import * as fs from "fs";

    const writeToFile = task("writeToFile", async () => {
      fs.writeFileSync("output.txt", "Side effect executed");
    });

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: Record<string, any>) => {
        // The side effect is now encapsulated in a task.
        await writeToFile();
        const value = interrupt("question");
        return value;
      }
    );
    ```

### 非确定性控制流

每次执行都可能产生不同结果的操作，例如读取当前时间或随机数，应封装进 Task，以保证 Resume 时返回与之前相同的结果。

* 放在 Task 中：生成随机数（5）→ Interrupt → Resume →（仍返回 5）→ ...
* 不放在 Task 中：生成随机数（5）→ Interrupt → Resume → 再次生成随机数（7）→ ...

这在人在回路 Workflow 中存在多个 Interrupt 时尤其重要。LangGraph 会为每个 Task / Entrypoint 保存一组 Resume Value。遇到 Interrupt 时，它会把当前 Interrupt 与对应 Resume Value 匹配。这个匹配严格按**索引位置**进行，因此 Resume Value 的顺序必须与 Interrupt 顺序一致。

如果 Resume 时执行顺序发生变化，某个 @[`interrupt`] 可能被错误地匹配到另一个 `resume` Value，导致结果错误。

更多信息请阅读[确定性](#determinism)。

<Tabs>
    <Tab title="错误示例">
    下面的 Workflow 使用当前时间决定执行哪个 Task。由于结果取决于实际执行时间，因此控制流是非确定性的。

    :::python
    ```python
    from langgraph.func import entrypoint

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        t0 = inputs["t0"]
        t1 = time.time()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {
            "result": result,
            "value": value
        }
```
    :::

    :::js
    ```typescript
    import { entrypoint, interrupt } from "@langchain/langgraph";

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: { t0: number }) => {
        const t1 = Date.now();

        const deltaT = t1 - inputs.t0;

        if (deltaT > 1000) {
          const result = await slowTask(1);
          const value = interrupt("question");
          return { result, value };
        } else {
          const result = await slowTask(2);
          const value = interrupt("question");
          return { result, value };
        }
      }
    );
    ```
    :::
    </Tab>
    <Tab title="正确示例">
    :::python
    下面把读取时间封装进 Task，因此恢复执行时会使用已保存的 Task Result，控制流可以稳定 Replay。

    ```python
    import time

    from langgraph.func import task

    @task  # [!code highlight]
    def get_time() -> float:  # [!code highlight]
        return time.time()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        t0 = inputs["t0"]
        t1 = get_time().result()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {
            "result": result,
            "value": value
        }
```
    :::

    :::js
    下面把读取时间封装进 Task，因此恢复执行时会使用已保存的 Task Result，控制流可以稳定 Replay。

    import { entrypoint, task, interrupt } from "@langchain/langgraph";

          return { result, value };
