使用 LangGraph 构建一个[检索](/oss/deepagents/retrieval)智能体，让它自主决定是搜索向量数据库，还是直接回答用户。

LangChain 提供了基于 [LangGraph](/oss/langgraph/overview) 原语实现的内置[智能体](/oss/langchain/agents)。当你需要更深度的自定义时，可以直接使用 LangGraph 实现智能体。本教程将演示一种检索智能体模式。

在本教程中，你将：

1. 获取并预处理用于检索的文档。
2. 为这些文档建立语义搜索索引，并为智能体创建 Retriever Tool。
3. 构建一个能够自主决定何时调用 Retriever Tool 的 Agentic RAG 系统。

![Hybrid RAG](/images/langgraph-hybrid-rag-tutorial.png)

### 涉及概念

本教程会涉及以下概念：

- 使用以下组件实现[检索](/oss/deepagents/retrieval)：
  - [Document Loader](/oss/integrations/document_loaders)
  - [Text Splitter](/oss/integrations/splitters)、[Embedding](/oss/integrations/embeddings)
  - [Vector Store](/oss/integrations/vectorstores)
- LangGraph [Graph API](/oss/langgraph/graph-api)，包括 State、Node、Edge 和 Conditional Edge。

### 配置 LangSmith

RAG 应用会依次执行检索与生成。当你运行本教程中的示例时，[LangSmith](/langsmith/observability) 会为每一次 Query 记录 Trace，方便你检查检索过程、工具调用和模型响应。
注册 [LangSmith](https://smith.langchain.com) 后，设置以下环境变量开始记录 Trace：

```shell
export LANGSMITH_TRACING="true"
export LANGSMITH_API_KEY="..."
```

:::python
也可以直接在 Python 中设置：

```python
import getpass
import os

os.environ["LANGSMITH_TRACING"] = "true"
os.environ["LANGSMITH_API_KEY"] = getpass.getpass()
```
:::

<Tip>
如果你正在构建生产级智能体，我们还建议配置 [LangSmith Engine](/langsmith/engine)。它能够监控 Trace、检测问题并提出修复建议。
</Tip>

## 生成 Query 或直接响应

Retriever Tool 准备好后，就可以开始把智能体构建成一张 LangGraph 图。在 [Graph API](/oss/langgraph/graph-api) 中，一张图由以下部分组成：

:::python
- **[State](/oss/langgraph/graph-api#state)**：节点共同读取和更新的共享数据。本教程使用 [`MessagesState`](/oss/langgraph/graph-api#messagesstate)，其中保存一个由[聊天消息](/oss/langchain/messages)组成的 `messages` 列表。
:::

:::js
- **[State](/oss/langgraph/graph-api#state)**：节点共同读取和更新的共享数据。本教程使用 [`MessagesAnnotation`](/oss/langgraph/graph-api#using-messages-in-your-graph)，其中保存一个由[聊天消息](/oss/langchain/messages)组成的 `messages` 列表。
:::

- **[Node](/oss/langgraph/graph-api#nodes)**：接收当前 State、执行一个步骤（例如调用模型或工具），然后返回 State Update 的函数。
- **[Edge](/oss/langgraph/graph-api#edges)**：定义下一个执行哪个节点的连接，包括根据 State 进行分支的[条件边](/oss/langgraph/graph-api#conditional-edges)。

第一个节点是智能体的决策点。给定当前对话，模型可以直接回答用户；如果问题需要博客上下文，也可以调用 Retriever Tool。正是这个选择让系统成为 Agentic 系统，而不是固定的“先检索、再生成”流水线：只有在模型主动请求时才执行检索。

## 改写问题

## 组装图

:::python
- 从 `generate_query_or_respond` 开始，并判断是否需要调用 `retriever_tool`。
- 根据模型是否产生 Tool Call 路由到下一步：
  - 如果 `generate_query_or_respond` 返回了 `tool_calls`，调用 `retriever_tool` 获取上下文。
  - 否则直接回答用户。

  - 如果不相关，使用 `rewrite_question` 改写问题，然后再次调用 `generate_query_or_respond`。
  - 如果相关，进入 `generate_answer`，使用包含检索文档上下文的 @[ToolMessage] 生成最终回答。
