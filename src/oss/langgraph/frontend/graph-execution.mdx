LangGraph 智能体并不是黑盒。每一张图都由**具名 Node**组成，这些 Node 可以串行或并行执行，例如：分类、研究、分析、综合。Graph Execution Card 会为每个 Node 渲染一张卡片，显示它当前的状态、实时流式输出内容，并跟踪整个工作流的完成情况，从而把完整 Pipeline 暴露给用户。用户能够清楚看到智能体正在做什么、当前执行到哪一步，以及每一步产生了什么结果。

这种模式尤其适合生产环境中的智能体，因为它把 Graph Structure 直接转化成产品 UX。你不必再把一次 Run 当作单条 Assistant Response，而是可以把 LangGraph 内部本来就在使用的 Checkpoint、Node Name、State Key 和 Stream Metadata 直接展示给前端。

## Graph Node 如何映射到 UI Card

一张 LangGraph 图包含一系列 Node，每个 Node 负责一个具体任务。例如，一个 Research Pipeline 可能包含：

1. **Classify**：对用户 Query 进行分类
2. **Research**：收集相关信息
3. **Analyze**：基于研究结果得出结论
4. **Synthesize**：生成最终、经过整理的回答

每个 Node 会把输出写入 Graph State 中的某个特定 Key。在前端，你不需要手动硬编码这层映射：@[`useStream`] 会在运行期间通过 `stream.subgraphs` 自动发现每个 Node，并为每个观测到的 Step 暴露一个 @[`SubgraphDiscoverySnapshot`]：

```ts
// Nodes are discovered automatically — no hardcoded list needed
const graphNodes = [...stream.subgraphs.values()];

// Each snapshot carries the node name and current status
graphNodes.forEach((node) => {
  console.log(node.nodeName, node.status); // "classify", "running"
});
```

可以使用 `node.nodeName` 作为进度条和卡片标题中的标签。把每个 Snapshot 传给 `useMessages(stream, node)`，即可渲染该 Node 范围内的流式内容，而无需让 UI 依赖 Graph State Key 的具体命名。

这层映射实际上构成了 Graph 与 UI 之间的契约。后端作者可以有意识地增加、重命名或调整 Node 顺序，而前端作者则决定每类输出如何展示，例如状态 Badge、Markdown Panel、表格、图表、Trace View 或审批卡片。

## 配置 `useStream`

像平常一样配置 @[`useStream`]。这里最关键的两个属性是 `messages`（对话消息）和 `subgraphs`（当前 Run 中已经发现的 Graph Node）。把每个发现到的 Subgraph Snapshot 传给 Selector，即可读取该 Node 范围内的 Message。

## 把流式 Token 路由到对应 Node

随着 Graph 持续输出 Stream，每个被发现的 Subgraph Snapshot 都会标记它属于哪个 Node。把这个 Snapshot 传给 Selector Hook 或 Composable，即可读取该 Node 范围内的 Message：

```tsx
import { AIMessage } from "langchain";
import { useMessages, type AnyStream, type SubgraphDiscoverySnapshot } from "@langchain/react";

function NodeCard({
  node,
  stream,
}: {
  node: SubgraphDiscoverySnapshot;
  stream: AnyStream;
}) {
  const messages = useMessages(stream, node);
  const lastAIMessage = messages.find(AIMessage.isInstance);
  const streamingContent = lastAIMessage?.text ?? "";

  return <NodeCardBody node={node} content={streamingContent} />;
}
```

第一个挂载的 Selector 会为对应的 Node Namespace 打开一条 Scoped Subscription。当 Node Card 卸载时，该订阅会自动释放。

## 判断 Node 状态

每个发现到的 Node 都带有当前状态。直接使用 `node.status` 即可；Discovery Snapshot 会返回 `"pending"`、`"running"`、`"complete"` 或 `"error"`：

```ts
type NodeStatus = SubgraphDiscoverySnapshot["status"];

const status: NodeStatus = node.status;
```

## 构建 Pipeline 进度条

顶部的横向进度条可以让用户快速获得整个 Pipeline 的全局视图。每个 Step 都是一段带标签的进度项，随着 Node 完成而逐步填充：

```tsx
function PipelineProgress({
  nodes,
  isLoading,
}: {
  nodes: SubgraphDiscoverySnapshot[];
  isLoading: boolean;
}) {
  const firstIncompleteIdx = nodes.findIndex((node) => node.status !== "complete");

  return (
    <div className="flex items-center gap-1">
      {nodes.map((node, i) => {
        const isRunning =
          isLoading && node.status !== "complete" && firstIncompleteIdx === i;
        const colors = {
          pending: "bg-gray-200 text-gray-500",
          running: "bg-blue-400 text-white animate-pulse",
          complete: "bg-green-500 text-white",
          error: "bg-red-500 text-white",
        };
        const status = isRunning ? "running" : node.status;

        return (
          <div key={node.id} className="flex items-center">
            <div
              className={`rounded-full px-3 py-1 text-xs font-medium ${colors[status]}`}
            >
              {node.nodeName}
            </div>
            {i < nodes.length - 1 && (
              <div
                className={`mx-1 h-0.5 w-6 ${
                  status === "complete" ? "bg-green-500" : "bg-gray-200"
                }`}
              />
            )}
          </div>
        );
      })}
    </div>
  );
}
```

## 构建可折叠的 NodeCard 组件

每个 Node 都拥有自己的卡片，用于展示状态 Badge、内容（流式或最终结果），并为较长输出提供可折叠区域：

```tsx
function NodeCard({
  node,
  stream,
}: {
  node: SubgraphDiscoverySnapshot;
  stream: AnyStream;
}) {
  const [open, setOpen] = useState(node.status === "running");
  const messages = useMessages(stream, node);
  const lastAIMessage = messages.find(AIMessage.isInstance);

  useEffect(() => {
    if (node.status === "running") setOpen(true);
    if (node.status === "complete") setOpen(false);
  }, [node.status]);

  return (
    <div className="rounded-lg border bg-white shadow-sm">
      <button
        onClick={() => setOpen(!open)}
        className="flex w-full items-center justify-between p-4"
      >
        <div className="flex items-center gap-3">
          <h3 className="font-semibold">{node.nodeName}</h3>
          <StatusBadge status={node.status} />
        </div>
        <span className={open ? "rotate-90" : ""}>▶</span>
      </button>

      {open && (
        <div className="border-t px-4 py-3">
          <div className="prose prose-sm max-w-none">
            {lastAIMessage?.text?.trim()
              ? <Markdown>{lastAIMessage.text}</Markdown>
              : <p className="italic text-gray-500">Processing...</p>}
          </div>
        </div>
      )}
    </div>
  );
}
```

## 流式内容与已完成内容

Node Card 会同时读取流式内容和最终内容对应的 Scoped Message。这样就不需要假设 Graph Node Name 与它实际写入的 State Key 名字相同（例如 Playground Graph 中 `do_research` 写入的是 `research`）：

| 来源 | 何时使用 |
| --- | --- |
| `useMessages(stream, node)` | 渲染某个 Node 范围内的流式和最终 Message |
| `stream.values` | 使用真实 State Key 读取整张图的 State，例如最终的 `synthesis` 字段 |

推荐模式是：Node Card 中展示最近一条 Scoped AI Message；只有在明确需要某个 Graph State 字段时，才直接读取 `stream.values`。

由于 Scoped Message 会与真正生成它的 Node 绑定，UI 可以自然支持并行 Graph Path，而无需根据 Message 顺序猜测来源。每张卡片只会响应属于自身 Node 的 Stream Event；与此同时，已经完成的值依然可以通过 `stream.values` 获取。

```ts
function NodeContent({ stream, node }: { stream: AnyStream; node: SubgraphDiscoverySnapshot }) {
  const messages = useMessages(stream, node);
  const content = messages.find(AIMessage.isInstance)?.text ?? "";

  return <Markdown>{content}</Markdown>;
}
```

<Tip>
流式内容可能包含尚未完整生成的 Token 或 Markdown。如果你需要渲染 Markdown，请确保 Renderer 能够优雅处理不完整语法，例如尚未闭合的加粗标记 `**`。
</Tip>

## 组合完整实现

下面是完整的 Card List，把路由、状态判断和卡片渲染组合在一起：

```tsx
function NodeCardList({
  nodes,
  stream,
  isLoading,
}: {
  nodes: SubgraphDiscoverySnapshot[];
  stream: AnyStream;
  isLoading: boolean;
}) {
  const firstIncompleteIdx = nodes.findIndex((node) => node.status !== "complete");

  return (
    <div className="space-y-3">
      {nodes.map((node, i) => {
        const isComplete = node.status === "complete";
        const isRunning = isLoading && !isComplete && firstIncompleteIdx === i;
        if (!isComplete && !isRunning) return null;

        return <NodeCard key={node.id} node={node} stream={stream} />;
      })}
    </div>
  );
}
```

## 适用场景

Graph Execution Card 很适合所有需要可见性的多步骤 Pipeline：

- **Research Pipeline**：分类 → 收集来源 → 分析 → 综合报告
- **内容生成**：提纲 → 草稿 → 事实核查 → 编辑 → 发布
- **数据处理**：摄取 → 校验 → 转换 → 聚合 → 导出
- **代码生成**：理解需求 → 规划架构 → 编写代码 → Review → 测试
- **决策工作流**：收集上下文 → 评估选项 → 对候选方案打分 → 给出建议

## 处理动态 Pipeline

并不是所有图都有固定 Node 集合。某些 Pipeline 会根据输入动态增加或跳过 Node。Discovery Map 只包含当前 Thread 中实际观测到的 Node：

```ts
const activeNodes = [...stream.subgraphs.values()];
```

因此，UI 只会显示与当前执行真正相关的 Card，而不会出现空的占位卡片。

<Info>
如果图中包含条件分支（例如对于简单事实问题跳过“Research”），被跳过的 Node 不会出现在 `stream.subgraphs` 中。你的 Pipeline Progress Bar 可以只渲染已经发现的 Node，也可以把那些预期存在、但没有对应 Snapshot 的 Node 显示为灰色。
</Info>

## 最佳实践

- **从 Stream 中发现 Node**。使用 `stream.subgraphs` 动态渲染 Card，而不是硬编码预期 Node；条件分支或被跳过的步骤只有在真正运行时才会出现。
- **把 State Key 当作 UI Contract**。明确哪些 Graph Output 足够稳定、应该暴露给前端渲染，并把这些 Key 与 Graph Definition 一起文档化。
- **Node Card 使用 Scoped Message**。这样无论 Node 正在流式输出还是已经完成，都可以正确渲染，同时不会把 UI Card 与 State Key Name 强耦合。
- **自动折叠已完成 Node**。在长 Pipeline 中自动收起已完成的 Card，让用户把注意力集中在当前活跃步骤。
- **显示预计耗时**。如果你有每个 Node 历史执行耗时数据，可以展示时间估计，帮助用户建立等待预期。
- **增加全局进度指示器**。除了每个 Node 的 Card，还可以在 Pipeline 顶部展示总体进度，例如“第 2 / 4 步”。
- **按 Node 处理错误**。如果某个 Node 失败，在它自己的 Card 中展示错误，而不是让整个 Pipeline UI 一起崩掉；其他 Node 仍有可能成功完成。
