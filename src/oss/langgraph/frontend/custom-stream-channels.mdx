LangGraph 智能体能够流式传输的不只是 Message 和 Tool Call。服务端的 **Stream Transformer** 可以在协议事件流向客户端的过程中检查或改写这些事件，并把自己的结构化数据发布到一个具名的 **Custom Channel** 上。前端可以通过两个 Selector 读取这个 Channel：使用 @[`useExtension`] 获取最新 Payload，或者使用 @[`useChannel`] 作为读取原始事件的 Escape Hatch。

下面的示例是一个 Customer Support Agent。它的 Transformer 会在每个事件到达浏览器之前，对其中的 PII（邮箱、电话号码、SSN、银行卡号、IP）进行脱敏，同时把累计脱敏统计发布到 `redaction-stats` Channel。侧边面板会实时渲染这些统计数据。

## Custom Channel 如何工作

一个 Custom Channel 有服务端和客户端两个端点。在服务端，@[`StreamTransformer`] 打开一个具名 @[`StreamChannel`]，然后向其中 Push Payload。在客户端，Selector 订阅匹配的 `custom:<name>` Channel，并把 Payload 以响应式 State 暴露出来。

Transformer 的 `process` 方法会对每一个 Protocol Event 执行。它既可以原地修改事件（这里会对 `messages`、`tools` 和 `values` 数据中的 PII 做清洗），也可以在需要报告信息时向 Side Channel Push 更新。

客户端 Selector（`useExtension`、`useChannel`）随 v1 前端 SDK Package 一起提供，包括 `@langchain/react`、`@langchain/vue`、`@langchain/svelte` 和 `@langchain/angular`。

```python
import time

from langgraph.stream import ProtocolEvent, StreamChannel, StreamTransformer


class RedactionStatsTransformer(StreamTransformer):
    def __init__(self, scope: tuple[str, ...] = ()) -> None:
        super().__init__(scope)
        # Open a channel named "redaction-stats".
        self.redaction_stats = StreamChannel("redaction-stats")
        self.counts = empty_counts()

    def init(self) -> dict[str, StreamChannel]:
        return {"redactionStats": self.redaction_stats}

    def process(self, event: ProtocolEvent) -> bool:
        # Redact event["params"]["data"] in place and tally what was found.
        delta = redact_in_place(event, self.counts)
        if delta:
            # Publish a payload on the channel.
            self.redaction_stats.push(
                {
                    "kind": "update",
                    "at": int(time.time() * 1000),
                    "delta": delta,
                    "counts": dict(self.counts),
                    "total": sum(self.counts.values()),
                }
            )
        return True  # Keep the (now-redacted) event in the stream.


def create_redaction_stats_transformer() -> RedactionStatsTransformer:
    return RedactionStatsTransformer()
```

在构建 Agent 时挂载 Transformer：


:::js

```ts
import { StreamChannel } from "@langchain/langgraph";
import type { ProtocolEvent, StreamTransformer } from "@langchain/langgraph";

export const createRedactionStatsTransformer = (): StreamTransformer<{
  redactionStats: StreamChannel<RedactionStatsEvent>;
}> => {
  // Open a remote channel named "redaction-stats".
  const redactionStats = StreamChannel.remote<RedactionStatsEvent>("redaction-stats");
  const counts = emptyCounts();

  return {
    init: () => ({ redactionStats }),

    process(event: ProtocolEvent): boolean {
      // Redact event.params.data in place and tally what was found.
      const delta = redactInPlace(event, counts);
      if (Object.keys(delta).length > 0) {
        // Publish a payload on the channel.
        redactionStats.push({
          kind: "update",
          at: Date.now(),
          delta,
          counts: { ...counts },
          total: totalRedactions(counts),
        });
      }
      return true; // Keep the (now-redacted) event in the stream.
    },
  };
};
```

在构建 Agent 时挂载 Transformer：

```ts
import { createAgent } from "langchain";

const agent = createAgent({
  model: "anthropic:claude-haiku-4-5",
  tools: [...],
  streamTransformers: [createRedactionStatsTransformer],
});
```

```ts
type PiiType = "email" | "phone" | "ssn" | "credit_card" | "ip_address";

type RedactionStatsEvent = {

  at: number;
  delta: Partial<Record<PiiType, number>>;
  counts: Record<PiiType, number>;
  total: number;
```

## 使用 `useExtension` 读取最新 Payload

`useExtension` 会订阅一个 `custom:<name>` Channel，并返回 Transformer 最近一次 Push 的 Payload；返回值已经完成了解包并带有类型信息。当 UI 只需要当前值时，它通常是最方便的选择，例如实时计数器、完成百分比或状态 Badge。

传入的是裸 Channel Name（`"redaction-stats"`），不要带 `custom:` 前缀：

<CodeGroup>
```tsx React
import { useExtension } from "@langchain/react";

const latest = useExtension<RedactionStatsEvent>(stream, "redaction-stats");
// latest?.total, latest?.counts.email, latest?.delta
```

```vue Vue
import { useExtension } from "@langchain/vue";

const latest = useExtension<RedactionStatsEvent>(stream, "redaction-stats");
// latest.value?.total
```

```svelte Svelte
import { useExtension } from "@langchain/svelte";

const latest = useExtension<RedactionStatsEvent>(stream, "redaction-stats");
// latest?.total
```

```ts Angular
import { injectExtension } from "@langchain/angular";

const latest = injectExtension<RedactionStatsEvent>(stream, "redaction-stats");
// latest()?.total
```
</CodeGroup>

返回值会遵循各框架自己的响应式模型：React 和 Svelte 中是普通值，Vue 中是 `Ref`（`latest.value`），Angular 中是 Signal（`latest()`）。在第一个 Payload 到达之前，其值为 `undefined`。

可选的第三个 `target` 参数可以把订阅限定到某个 Namespace，方式与 `useMessages(stream, node)` 把 Message 限定到某个已发现 Graph Node 相同。Namespace Targeting 参见 [Graph Execution](/oss/langgraph/frontend/graph-execution)。

## 使用 `useChannel` 缓冲原始事件

`useChannel` 是读取 Raw Event 的 Escape Hatch。它可以订阅一个或多个 Channel，并返回底层 Protocol Event 的有界 Buffer，而不是单个已经解包的值。当你需要“历史”而不是“最新值”时，例如 Event Log、Audit Trail，或者需要消费没有对应高级 Selector 的 Channel，就应该使用它。

这里需要传完整 Channel ID（`"custom:redaction-stats"`）：

<CodeGroup>
```tsx React
import { useChannel } from "@langchain/react";

const rawEvents = useChannel(stream, ["custom:redaction-stats"]);
```

```vue Vue
import { useChannel } from "@langchain/vue";

const rawEvents = useChannel(stream, ["custom:redaction-stats"]);
// rawEvents.value
```

```svelte Svelte
import { useChannel } from "@langchain/svelte";

const rawEvents = useChannel(stream, ["custom:redaction-stats"]);
```

```ts Angular
import { injectChannel } from "@langchain/angular";

const rawEvents = injectChannel(stream, ["custom:redaction-stats"]);
// rawEvents()
```
</CodeGroup>

每一项都是 Raw Protocol Event，因此 Payload 位于 `event.params.data` 下。需要你自己完成解包：

```ts
function parseRedactionStatsEvents(rawEvents: Event[]): RedactionStatsEvent[] {
  const out: RedactionStatsEvent[] = [];
  for (const event of rawEvents) {
    const data = event.params?.data;
    const payload = data?.payload ?? data;
    if (payload?.kind === "update") out.push(payload);
  }
  return out;
}
```

可以通过 Options 参数控制 Buffer：

```ts
const rawEvents = useChannel(
  stream,
  ["custom:redaction-stats"],
  undefined, // target namespace
  { bufferSize: 200, replay: true },
);
```

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `bufferSize` | `"default"` | 最多保留多少个 Buffer Event。超过上限后，较旧事件会被丢弃。 |
| `replay` | `true` | Selector 挂载时，是否重放此前已经在该 Channel 上观测到的事件，而不是只接收后续 Live Event。 |

<Note>
常见场景优先使用高级 Selector（`useExtension`、`useMessages`、`useToolCalls`、`useValues`）。它们会返回已经解包、带类型的数据，而且只跟踪你真正渲染的部分。只有明确需要 Raw Event Stream 时才使用 `useChannel`。
</Note>

## 如何选择 `useExtension` 与 `useChannel`

二者读取的是同一个 Custom Channel，但返回内容不同：

| | `useExtension` | `useChannel` |
| --- | --- | --- |
| **返回** | 最新 Payload（`T \| undefined`） | Raw Event 的有界 Buffer（`Event[]`） |
| **数据形态** | 已解包、带类型的 Payload | 原始 Protocol Event；需要自行解包 `event.params.data` |
| **订阅方式** | Channel Name（`"redaction-stats"`） | 完整 Channel ID（`["custom:redaction-stats"]`） |
| **适合场景** | 只需要当前值 | 需要历史、Log 或多个 Channel |
| **可选参数** | — | `bufferSize`、`replay` |

一种常见做法是在同一个 Channel 上同时使用二者：`useExtension` 驱动实时 Summary（例如当前累计计数），而 `useChannel` 为滚动 Event Log 保存整个 Thread 中的每次更新。

## 适用场景

Custom Channel 适合所有无法自然映射为 Message、Tool Call 或 Graph State 的服务端信号：

- **合规与脱敏统计**：例如上例中的 PII 清洗数量、被阻断内容数量或 Policy Hit 次数。
- **进度汇报**：长时间运行 Tool 输出的完成百分比或 Step Label。
- **实时指标**：一次 Run 中不断累积的 Token Usage、Latency 或 Cost。
- **来源与引用**：Agent Grounding 回答时，把检索到的 Document 持续 Push 到侧边面板。
- **领域事件**：后端希望暴露给前端、但又不希望改变 Message Transcript 的任意结构化更新。
