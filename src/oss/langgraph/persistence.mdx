持久化使 LangGraph 应用能够在单次图运行结束后继续保留有用信息。当智能体需要延续对话、在中断后恢复、从故障中恢复，或跨多次交互记住信息时，持久化就非常重要。

LangGraph 提供两套互补的持久化系统：

- **[Checkpointer](/oss/langgraph/checkpointers)** 将一个线程（Thread）的图状态保存为检查点（Checkpoint）。它适用于短期、线程范围内的记忆，包括保持对话连续性、人在回路工作流、时间旅行以及容错。
- **[Store](/oss/langgraph/stores)** 将应用自定义的数据持久化到图状态之外。它适用于长期、跨线程记忆，例如用户偏好、事实信息和共享知识。

多数应用可以同时使用二者：[Checkpointer](/oss/langgraph/checkpointers) 跟踪当前线程，[Store](/oss/langgraph/stores) 则维护跨线程的持久信息。

## 快速入门

在编译图时传入 Checkpointer、Store，或者同时传入二者：

:::python
```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore

checkpointer = InMemorySaver()
store = InMemoryStore()

graph = builder.compile(checkpointer=checkpointer, store=store)

result = graph.invoke(
    {"messages": [{"role": "user", "content": "Hi, my name is Bob."}]},
    {"configurable": {"thread_id": "thread-1"}},
)
```
:::

:::js
```typescript
import { MemorySaver, MemoryStore } from "@langchain/langgraph";

const checkpointer = new MemorySaver();
const store = new MemoryStore();

const graph = builder.compile({ checkpointer, store });

const result = await graph.invoke(
  { messages: [{ role: "user", content: "Hi, my name is Bob." }] },
  { configurable: { thread_id: "thread-1" } }
);
```
:::

<Info>
**Agent Server 会自动处理持久化**

使用 [Agent Server](/langsmith/agent-server) 时，无需手动实现或配置 Checkpointer 与 Store。服务器会在后台处理持久化基础设施。
</Info>

## Checkpointer 与 Store 的区别

| | Checkpointer | Store |
| ---- | ---- | ---- |
| 持久化内容 | 图状态快照 | 应用自定义的键值数据 |
| 作用域 | 单个线程 | 跨线程 |
| 记忆类型 | 短期、线程范围内的记忆 | 长期、跨线程记忆 |
| 适用场景 | 对话连续性、人在回路、时间旅行和容错 | 用户偏好、事实和共享知识 |
| 访问方式 | 在图配置中传入 `thread_id` | 从节点或应用代码中读写条目 |
| 完整指南 | [Checkpointer](/oss/langgraph/checkpointers) | [Store](/oss/langgraph/stores) |

## 常见问题排查

### PostgresSaver：`thread_id` 过长

使用 `PostgresSaver`（或 `AsyncPostgresSaver`）时，`thread_id` 会保存在长度受限的数据库列中。如果 `thread_id` 超过列的最大长度，就会出现数据库错误。

**解决方法：** 将 `thread_id` 控制在 255 个字符以内。如果需要确定性的 ID，可以使用 UUID 或哈希：

:::python
```python
import uuid

config = {"configurable": {"thread_id": str(uuid.uuid4())[:255]}}
```
:::

### `MemorySaver` 在重启后不会保留数据

`MemorySaver` 和 `InMemorySaver` 会把检查点保存在内存（RAM）中。进程重启后，所有检查点都会丢失。

**解决方法：** 在生产环境中使用持久化 Checkpointer：

- `PostgresSaver`：基于 PostgreSQL，支持异步操作
- `SqliteSaver`：基于本地文件，适合开发环境

### 检查点无限增长

在长对话中，检查点会持续累积，这可能增加延迟和存储成本。

**解决方法：** 定期清理旧检查点，或设置保留策略：

:::python
```python
from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string("postgresql://...")
checkpointer.setup()  # Creates tables with indexes
# Consider adding a cron job to delete checkpoints older than N days
```
:::

### 父图访问子图状态

当子图更新状态后，父图可能无法立即看到这些变化。这是因为每个子图都会管理自己的 Checkpoint Namespace。

**解决方法：** 对需要跨图边界共享的数据使用[通过 Store 共享状态](/oss/langgraph/stores)，或者配置子图将数据写入父图的 Checkpoint。
