Functional API 允许你继续使用普通的函数、`if/else`、循环和函数调用来编写工作流，同时获得 LangGraph Runtime 提供的持久化、Checkpoint、人在回路、Streaming 和容错能力。

如果你的代码已经是过程式结构，或者你不需要显式可视化 Graph Topology，Functional API 通常比 Graph API 更轻量。

核心只有两个原语：

- `entrypoint`：定义整个 Workflow 的入口和执行边界。
- `task`：定义可独立 Checkpoint、Retry 和并发执行的工作单元。

## 快速开始

:::python
```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task

@task
def double(x: int) -> int:
    return x * 2

@entrypoint(checkpointer=InMemorySaver())
def workflow(x: int) -> int:
    result = double(x).result()
    return result + 1

config = {"configurable": {"thread_id": "1"}}
print(workflow.invoke(10, config))  # 21
```
:::

:::js
```typescript
import { MemorySaver, entrypoint, task } from "@langchain/langgraph";

const double = task("double", async (x: number) => x * 2);

const workflow = entrypoint(
  { name: "workflow", checkpointer: new MemorySaver() },
  async (x: number) => {
    const result = await double(x);
    return result + 1;
  }
);

const config = { configurable: { thread_id: "1" } };
console.log(await workflow.invoke(10, config)); // 21
```
:::

## 定义 Entrypoint

Entrypoint 是一次 Workflow Invocation 的顶层函数。它接收一个输入并返回一个输出。

:::python
```python
from langgraph.func import entrypoint

@entrypoint(checkpointer=checkpointer)
def workflow(inputs: dict) -> dict:
    ...
    return result
```
:::

:::js
```typescript
const workflow = entrypoint(
  { name: "workflow", checkpointer },
  async (inputs: Input): Promise<Output> => {
    return result;
  }
);
```
:::

Entrypoint 的输入和输出应该能够进行 JSON 序列化，因为它们可能被 Checkpointer 保存。

### Entrypoint 的执行方式

:::python
```python
# synchronous
result = workflow.invoke(input, config)

# asynchronous
result = await workflow.ainvoke(input, config)

# streaming
for chunk in workflow.stream(input, config, stream_mode="updates"):
    print(chunk)

# typed event streaming
stream = workflow.stream_events(input, config, version="v3")
for message in stream.messages:
    print(message.text)
```
:::

:::js
```typescript
const result = await workflow.invoke(input, config);

for await (const chunk of await workflow.stream(input, config)) {
  console.log(chunk);
}

const stream = await workflow.streamEvents(input, config, { version: "v3" });
for await (const message of stream.messages) {
  console.log(await message.text);
}
```
:::

## 定义 Task

Task 用于把一个操作变成独立的 Runtime Unit。Task 结果会被 Checkpoint，因此 Workflow 恢复时，已经成功完成的 Task 不需要再次执行。

:::python
```python
from langgraph.func import task

@task
def fetch_user(user_id: str) -> dict:
    return db.get_user(user_id)
```
:::

:::js
```typescript
const fetchUser = task("fetchUser", async (userId: string) => {
  return db.getUser(userId);
});
```
:::

适合变成 Task 的操作包括：

- 网络请求；
- LLM 调用；
- 数据库读写；
- 文件写入；
- 随机数 / 当前时间等非确定性操作；
- 昂贵计算；
- 希望单独 Retry 的操作。

### 获取 Task 结果

:::python
同步 Entrypoint 中调用 `.result()`：

```python
@entrypoint(checkpointer=checkpointer)
def workflow(x: int):
    future = double(x)
    return future.result()
```

异步 Entrypoint 中直接 `await`：

```python
@entrypoint(checkpointer=checkpointer)
async def workflow(x: int):
    return await double(x)
```
:::

:::js
```typescript
const workflow = entrypoint(
  { name: "workflow", checkpointer },
  async (x: number) => await double(x)
);
```
:::

## 并行执行 Task

多个彼此独立的 Task 可以并发执行。

:::python
```python
@task
def fetch_profile(user_id: str):
    return get_profile(user_id)

@task
def fetch_orders(user_id: str):
    return get_orders(user_id)

@entrypoint(checkpointer=checkpointer)
def workflow(user_id: str):
    profile_future = fetch_profile(user_id)
    orders_future = fetch_orders(user_id)

    profile = profile_future.result()
    orders = orders_future.result()
    return {"profile": profile, "orders": orders}
```
:::

:::js
```typescript
const workflow = entrypoint(
  { name: "workflow", checkpointer },
  async (userId: string) => {
    const [profile, orders] = await Promise.all([
      fetchProfile(userId),
      fetchOrders(userId),
    ]);
    return { profile, orders };
  }
);
```
:::

对于动态数量的任务，也可以先创建多个 Task，再等待全部完成。

## 在 Task 中配置 Retry

瞬时错误应该通过 Retry Policy 处理，而不是在 Workflow 中手写复杂重试循环。

:::python
```python
from langgraph.types import RetryPolicy

@task(retry_policy=RetryPolicy(max_attempts=3))
def call_api(url: str):
    return requests.get(url).json()
```
:::

:::js
```typescript
const callApi = task(
  {
    name: "callApi",
    retry: { maxAttempts: 3 },
  },
  async (url: string) => (await fetch(url)).json()
);
```
:::

只应对瞬时错误重试，例如连接失败、限流、临时 5xx。参数错误、权限错误或确定性业务错误不应无限重试。

## Timeout

Task 和 Entrypoint 可以配置 Timeout，用于限制卡死操作。

:::python
```python
from langgraph.types import TimeoutPolicy

@task(timeout=TimeoutPolicy(run_timeout=30, idle_timeout=10))
async def fetch_data(url: str):
    ...
```
:::

:::js
```typescript
const fetchData = task(
  {
    name: "fetchData",
    timeout: { runTimeout: 30_000, idleTimeout: 10_000 },
  },
  async (url: string) => { ... }
);
```
:::

详细语义参阅[容错](/oss/langgraph/fault-tolerance)。

<a id="short-term-memory"></a>
## 短期记忆

如果 Entrypoint 配置了 Checkpointer，并且多次 Invocation 使用同一个 `thread_id`，就可以在不同调用之间保存短期状态。

:::python
通过 `previous` 参数读取上一次 Invocation 保存的值：

```python
from typing import Any

@entrypoint(checkpointer=checkpointer)
def counter(value: int, *, previous: Any = None) -> int:
    previous = previous or 0
    return previous + value

config = {"configurable": {"thread_id": "1"}}

counter.invoke(1, config)  # 1
counter.invoke(2, config)  # 3
counter.invoke(4, config)  # 7
```
:::

:::js
使用 `getPreviousState`：

```typescript
import { getPreviousState } from "@langchain/langgraph";

const counter = entrypoint(
  { name: "counter", checkpointer },
  async (value: number) => {
    const previous = getPreviousState<number>() ?? 0;
    return previous + value;
  }
);
```
:::

### 返回值与保存值分离

有时希望返回给调用者的值与写入下一轮短期记忆的值不同。使用 `entrypoint.final`：

:::python
```python
@entrypoint(checkpointer=checkpointer)
def workflow(x: int, *, previous=None):
    previous = previous or 0
    return entrypoint.final(
        value={"visible": previous},
        save=previous + x,
    )
```
:::

:::js
```typescript
return entrypoint.final({
  value: { visible: previous },
  save: previous + x,
});
```
:::

<a id="long-term-memory"></a>
## 长期记忆

Checkpointer 的作用域是单个 Thread。若希望跨 Thread 保存用户偏好、长期事实或共享知识，应使用 [Store](/oss/langgraph/stores)。

:::python
```python
from langgraph.store.memory import InMemoryStore
from langgraph.store.base import BaseStore

store = InMemoryStore()

@entrypoint(checkpointer=checkpointer, store=store)
def workflow(
    inputs: dict,
    *,
    store: BaseStore,
):
    user_id = inputs["user_id"]
    namespace = (user_id, "memories")

    store.put(namespace, "preference", {
        "language": inputs["language"]
    })

    memories = store.search(namespace)
    return [item.value for item in memories]
```
:::

:::js
```typescript
import { MemoryStore } from "@langchain/langgraph";

const store = new MemoryStore();

const workflow = entrypoint(
  { name: "workflow", checkpointer, store },
  async (inputs) => {
    const namespace = [inputs.userId, "memories"];
    await store.put(namespace, "preference", {
      language: inputs.language,
    });
    return await store.search(namespace);
  }
);
```
:::

如果配置 Embedding，Store 还支持语义检索。详见 [Store](/oss/langgraph/stores)。

<a id="human-in-the-loop"></a>
## 人在回路

在 Entrypoint 或 Task 中调用 `interrupt()` 可以暂停 Workflow，等待外部输入。

:::python
```python
from langgraph.types import interrupt, Command

@entrypoint(checkpointer=checkpointer)
def workflow(request: dict):
    approved = interrupt({
        "action": "approve",
        "request": request,
    })

    if not approved:
        return {"status": "rejected"}

    return {"status": "approved"}

config = {"configurable": {"thread_id": "1"}}

# Initial invocation pauses
result = workflow.invoke({"amount": 100}, config)

# Resume
result = workflow.invoke(Command(resume=True), config)
```
:::

:::js
```typescript
import { interrupt, Command } from "@langchain/langgraph";

const workflow = entrypoint(
  { name: "workflow", checkpointer },
  async (request) => {
    const approved = interrupt({ action: "approve", request });
    return { status: approved ? "approved" : "rejected" };
  }
);

await workflow.invoke(input, config);
await workflow.invoke(new Command({ resume: true }), config);
```
:::

<Warning>
Resume 时 Entrypoint 会从函数开头重新执行。所有非确定性操作和副作用都应该放入 Task，避免重复执行导致不一致。
</Warning>

完整规则参阅[中断](/oss/langgraph/interrupts)。

## 多个 Interrupt

同一个 Workflow 可以包含多个 Interrupt，但其执行顺序必须保持稳定。

```text
Task A
 ↓
interrupt("approve A")
 ↓ resume
Task B
 ↓
interrupt("approve B")
 ↓ resume
完成
```

如果不同分支可能动态产生不同数量的 Interrupt，应优先把每次审批拆成独立 Invocation / Node，或使用 Graph API 显式建模控制流。

<a id="streaming"></a>
## Streaming

Functional API 使用与 LangGraph 相同的 Streaming Runtime。

### Streaming Task / Entrypoint Update

:::python
```python
for chunk in workflow.stream(
    input,
    config,
    stream_mode="updates",
):
    print(chunk)
```
:::

### Streaming LLM Token

只要使用 LangChain Chat Model，即使 Task 内调用的是普通 `invoke()`，仍然可以通过 `messages` Stream Mode 获取 Token。

:::python
```python
for msg, metadata in workflow.stream(
    input,
    config,
    stream_mode="messages",
):
    print(msg.content, end="")
```
:::

### 自定义 Streaming

:::python
```python
from langgraph.config import get_stream_writer

@task
def process_items(items: list[str]):
    writer = get_stream_writer()
    results = []
    for i, item in enumerate(items):
        results.append(process(item))
        writer({"progress": i + 1, "total": len(items)})
    return results
```
:::

:::js
Task / Entrypoint 可以通过 Runtime Writer 发送自定义事件。
:::

如果是新应用，更推荐使用 [Event Streaming](/oss/langgraph/event-streaming) 的类型化 Projection。

## 调用子图

Functional Entrypoint 可以直接调用已编译 `StateGraph`，或者把 Subgraph Invocation 封装成 Task。

:::python
```python
@entrypoint(checkpointer=checkpointer)
def workflow(inputs: dict):
    result = subgraph.invoke({"messages": inputs["messages"]})
    return result
```
:::

若 Subgraph 内包含 Interrupt，Resume 时 Entrypoint 会从头重新执行，因此调用前的副作用仍需满足幂等性。

详见[子图](/oss/langgraph/use-subgraphs)。

## 调用另一个 Entrypoint

一个 Entrypoint 可以调用另一个 Entrypoint，但需要明确两者的 State / Checkpoint 边界。通常更推荐：

- 可复用的原子工作封装为 `task`；
- 复杂子工作流封装为 Subgraph；
- Entrypoint 作为顶层业务入口。

这样 Runtime 层级更容易理解。

## 错误后恢复

如果 Workflow 因异常失败，而底层问题随后被修复，可以使用同一个 `thread_id` 和 `None` / `null` 恢复。

:::python
```python
try:
    workflow.invoke(input, config)
except Exception:
    fix_external_issue()

# Resume from persisted state
result = workflow.invoke(None, config)
```
:::

:::js
```typescript
try {
  await workflow.invoke(input, config);
} catch (err) {
  await fixExternalIssue();
}

const result = await workflow.invoke(null, config);
```
:::

已经成功完成的 Task Result 会从 Checkpoint 恢复，不需要重新执行。

## 确定性与 Replay

这是 Functional API 最重要的心智模型之一：

> Workflow 恢复时，不是从 Python / JavaScript 源代码的暂停行继续，而是从 Entrypoint 开头重新执行，并用 Checkpointer 恢复已经完成的 Task Result。

因此下面这种代码存在问题：

```python
@entrypoint(checkpointer=checkpointer)
def workflow(input):
    now = time.time()              # nondeterministic
    db.insert(input)               # side effect
    approved = interrupt("approve?")
    ...
```

Resume 后 `time.time()` 和 `db.insert()` 都会再次执行。

应改为：

```python
@task
def get_time():
    return time.time()

@task
def insert_record(input):
    return db.upsert(input)

@entrypoint(checkpointer=checkpointer)
def workflow(input):
    now = get_time().result()
    record = insert_record(input).result()
    approved = interrupt("approve?")
    ...
```

Task 结果会被持久化，因此 Replay 可以恢复同一个值。

### 保持 Task / Interrupt 顺序稳定

不要在 Resume Point 之前随意新增、删除或重排 Task / Interrupt。LangGraph 需要把 Replay 中遇到的调用与已保存结果正确对应。

如果需要进行较大 Workflow 结构变更，参阅[向后兼容](/oss/langgraph/backward-compatibility)。

## 副作用与幂等性

Task 仍然可能因为“已经启动但尚未成功 Checkpoint”而被再次执行，因此外部副作用本身也应该尽量幂等。

推荐：

- 数据库写入使用 Upsert；
- API 使用 Idempotency Key；
- 邮件 / 支付等高影响操作在服务端记录业务唯一 ID；
- 不把“Task 被 Checkpoint”当作外部系统 Exactly-once Guarantee。

## 在 Functional API 与 Graph API 之间选择

Functional API 更适合：

- 已有过程式代码；
- 控制流比较线性；
- 希望少写样板代码；
- State 主要存在于函数作用域；
- 使用标准 `if` / `for` 就能表达逻辑。

Graph API 更适合：

- 多路复杂分支；
- 大量并行 Fan-out / Fan-in；
- 多个 Node 共享 State；
- 希望可视化 Graph；
- 团队需要明确的业务拓扑。

两者可以混用。参阅[选择 API](/oss/langgraph/choosing-apis)。

## 测试

Functional Workflow 可以像普通函数一样拆分测试：

- 单独测试 Task 函数的业务逻辑；
- 使用 `InMemorySaver` 测试持久化与 Resume；
- 使用固定 Thread ID 测试短期记忆；
- 对 Interrupt 分别测试暂停和 Resume；
- 对副作用使用 Fake / Mock Client。

```python
checkpointer = InMemorySaver()

@entrypoint(checkpointer=checkpointer)
def workflow(...):
    ...

config = {"configurable": {"thread_id": "test-1"}}
```

## 可观测性

Functional API 中的 Entrypoint 和 Task 同样会出现在 LangSmith Trace 中。Task 边界因此不仅影响 Checkpoint，也影响可观测性。

一个实用原则：**如果某个操作值得独立 Retry、Checkpoint 或观察，它通常值得成为 Task。**
