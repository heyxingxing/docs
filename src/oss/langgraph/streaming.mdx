<Tip>
对于新应用，我们推荐使用 [Event Streaming](/oss/langgraph/event-streaming)——这是 LangGraph v1.2 引入的类型化 Projection API。Event Streaming 为 messages、values、subgraphs、output 等 Projection 提供独立迭代器，因此无需自己根据 `stream_mode` Chunk 进行分支处理。
</Tip>

本页介绍 LangGraph 的 **Stream Mode API**。它通过 `updates`、`values`、`messages`、`custom`、`tools`、`checkpoints`、`tasks` 和 `debug` 等 Stream Mode 暴露 Graph Execution。需要直接访问底层 Graph Runtime Event 或特定流式输出时，可以使用这套 API。

## 快速开始

### 基本用法

:::python
LangGraph 图提供 @[`stream`][Pregel.stream]（同步）和 @[`astream`][Pregel.astream]（异步）方法，并以 Iterator 形式产生流式输出。通过一个或多个 [Stream Mode](#stream-modes) 控制接收哪些数据。

```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["updates", "custom"],  # [!code highlight]
    version="v2",  # [!code highlight]
):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"Node {node_name} updated: {state}")
    elif chunk["type"] == "custom":
        print(f"Status: {chunk['data']['status']}")
```

```shell title="Output"
Status: thinking of a joke...
Node generate_joke updated: {'joke': 'Why did the ice cream go to school? To get a sundae education!'}
```

<Accordion title="完整示例">
```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.config import get_stream_writer


class State(TypedDict):
    topic: str
    joke: str


def generate_joke(state: State):
    writer = get_stream_writer()
    writer({"status": "thinking of a joke..."})
    return {"joke": f"Why did the {state['topic']} go to school? To get a sundae education!"}

graph = (
    StateGraph(State)
    .add_node(generate_joke)
    .add_edge(START, "generate_joke")
    .add_edge("generate_joke", END)
    .compile()
)

for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["updates", "custom"],
    version="v2",
):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"Node {node_name} updated: {state}")
    elif chunk["type"] == "custom":
        print(f"Status: {chunk['data']['status']}")
```
</Accordion>
:::

:::js
LangGraph 图提供 @[`stream`][Pregel.stream] 方法，并以 Async Iterator 形式产生流式输出：

```typescript
for await (const chunk of await graph.stream(inputs, {
  streamMode: "updates",
})) {
  console.log(chunk);
}
```
:::

### Stream 输出格式（v2）

<Note>
需要 LangGraph 1.1 或更高版本。本页 Python 示例默认使用 `version="v2"`。
</Note>

向 `stream()` 或 `astream()` 传入 `version="v2"` 后，每一个 Chunk 都使用统一的 `StreamPart` 字典格式，无论 Stream Mode 数量和 Subgraph 设置如何：

```python
{
    "type": "values" | "updates" | "messages" | "custom" | "checkpoints" | "tasks" | "debug",
    "ns": (),           # namespace tuple, populated for subgraph events
    "data": ...,        # the actual payload (type varies by stream mode)
}
```

每种模式都有对应的 `TypedDict` 类型，例如 @[`ValuesStreamPart`]、@[`UpdatesStreamPart`]、@[`MessagesStreamPart`]、@[`CustomStreamPart`]、@[`CheckpointStreamPart`]、@[`TasksStreamPart`]、@[`DebugStreamPart`]。它们可以从 `langgraph.types` 导入；联合类型 @[`StreamPart`] 可根据 `part["type"]` 自动进行类型收窄。

v1 默认格式会随着设置变化：单模式返回原始数据，多模式返回 `(mode, data)`，Subgraph 又会加入 Namespace。v2 则始终保持同一种结构，因此更适合复杂消费逻辑。
:::

<a id="stream-modes"></a>
## Stream Mode

把 `stream_mode` / `streamMode` 传给 `stream` 或 `astream`，可以选择要流式接收的数据类型。

| 模式 | 说明 |
| --- | --- |
| `values` | 每个 Graph Step 后的**完整 State**。 |
| `updates` | 每个 Node 执行后产生的 **State Update / Delta**；同一 Step 多个 Node 会分别发出。 |
| `messages` | LLM Token 与 Message Metadata，支持逐 Token 输出。 |
| `custom` | Node / Tool 通过 Stream Writer 主动发送的自定义数据。 |
| `tools` | Tool Lifecycle Event 与 Tool Progress。 |
| `checkpoints` | 每次 Checkpoint 时发出的事件，与 Checkpointer 保存的信息一致。 |
| `tasks` | Task Start / Finish / Error Event。 |
| `debug` | 尽可能丰富的调试信息，包括 Node、Task、Checkpoint 和完整 State。 |

### `values`：完整 State

`values` 会在每一个 Step 后输出整个 Graph State。State 很大时，这会产生较多数据；如果只关心变化，优先使用 `updates`。

:::python
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="values",
    version="v2",
):
    if chunk["type"] == "values":
        print(chunk["data"])
```
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  { topic: "ice cream" },
  { streamMode: "values" }
)) {
  console.log(chunk);
}
```
:::

### `updates`：State Update

`updates` 只返回每个 Node 在该 Step 中更新的字段，而不是完整累计 State。

:::python
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="updates",
    version="v2",
):
    if chunk["type"] == "updates":
        print(chunk["data"])
```
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  { topic: "ice cream" },
  { streamMode: "updates" }
)) {
  console.log(chunk);
}
```
:::

### `messages`：LLM Token

使用 `messages` 可以流式读取 Graph 中任意位置调用的 LangChain Chat Model Token，即使 Node 内调用的是普通 `invoke()` / `ainvoke()` 而不是 Model 自身的 Streaming API。

:::python
`messages` 的每个 Chunk 包含 `(message_chunk, metadata)`：

```python
for chunk in graph.stream(
    inputs,
    stream_mode="messages",
    version="v2",
):
    if chunk["type"] == "messages":
        msg, metadata = chunk["data"]
        print(msg.content, end="", flush=True)
```
:::

:::js
```typescript
for await (const [msg, metadata] of await graph.stream(
  inputs,
  { streamMode: "messages" }
)) {
  process.stdout.write(String(msg.content ?? ""));
}
```
:::

Message Metadata 中包括触发模型调用的 Graph Node、Tag 等信息，因此可以进行过滤。

#### 按 Tag 过滤

如果一个 Node 中调用多个模型，可以通过 Model Tag 只消费某一路输出：

:::python
```python
joke_model = init_chat_model(model="gpt-5.4-mini", tags=["joke"])
poem_model = init_chat_model(model="gpt-5.4-mini", tags=["poem"])

for chunk in graph.stream(
    {"topic": "cats"},
    stream_mode="messages",
    version="v2",
):
    if chunk["type"] == "messages":
        msg, metadata = chunk["data"]
        if metadata["tags"] == ["joke"]:
            print(msg.content, end="", flush=True)
```
:::

:::js
```typescript
for await (const [msg, metadata] of await graph.stream(
  { topic: "cats" },
  { streamMode: "messages" }
)) {
  if (metadata.tags?.includes("joke")) {
    console.log(msg.content);
  }
}
```
:::

#### 完全从 Stream 中排除某次模型调用

使用 `nostream` Tag 可以让某次模型调用正常执行，但其 Token 不进入 `messages` Stream。这适合内部结构化输出，或已经通过其他 Channel 把同样内容发送给客户端的场景。

### `custom`：自定义数据

可以从 Node 或 Tool 内主动把进度、状态、Artifact 等任意数据推送到 Stream。

:::python
1. 使用 @[`get_stream_writer`] 获取 Writer。
2. 调用 `.stream()` / `.astream()` 时使用 `stream_mode="custom"`，或把 `"custom"` 加入多模式列表。

<Warning>
Python < 3.11 的异步代码中，`get_stream_writer()` 不能依赖 ContextVar 自动传播，应把 `writer` 参数显式传入 Node / Tool。
</Warning>

```python
from langgraph.config import get_stream_writer

def node(state: State):
    writer = get_stream_writer()
    writer({"status": "retrieving"})
    result = do_work()
    writer({"status": "done"})
    return {"result": result}

for chunk in graph.stream(inputs, stream_mode="custom", version="v2"):
    if chunk["type"] == "custom":
        print(chunk["data"])
```
:::

:::js
Node / Tool 可以通过 `LangGraphRunnableConfig.writer` 写入自定义数据：

```typescript
const node: GraphNode<typeof State> = async (state, config) => {
  config.writer({ status: "retrieving" });
  const result = await doWork();
  config.writer({ status: "done" });
  return { result };
};

for await (const chunk of await graph.stream(inputs, {
  streamMode: "custom",
})) {
  console.log(chunk);
}
```
:::

<a id="tools"></a>
### `tools`：Tool Lifecycle 和进度

`tools` 模式会输出结构化 Tool Event，包括：

- `on_tool_start`
- `on_tool_event`
- `on_tool_end`
- `on_tool_error`

:::python
```python
for chunk in graph.stream(
    {"messages": [{"role": "user", "content": "Find flights to Tokyo"}]},
    stream_mode=["updates", "tools"],
    version="v2",
):
    if chunk["type"] == "tools":
        print(chunk["data"])
```
:::

:::js
```typescript
for await (const [mode, chunk] of await graph.stream(
  { messages: [{ role: "user", content: "Find flights to Tokyo" }] },
  { streamMode: ["updates", "tools"] }
)) {
  if (mode === "tools") {
    switch (chunk.event) {
      case "on_tool_start":
        console.log(`Tool started: ${chunk.name}`, chunk.input);
        break;
      case "on_tool_event":
        console.log(`Tool progress: ${chunk.name}`, chunk.data);
        break;
      case "on_tool_end":
        console.log(`Tool finished: ${chunk.name}`, chunk.output);
        break;
      case "on_tool_error":
        console.error(`Tool failed: ${chunk.name}`, chunk.error);
        break;
    }
  }
}
```
:::

#### 在 React 中使用 Tool Progress

`@langchain/langgraph-sdk/react` 的 @[`useStream`] Hook 在包含 `"tools"` Stream Mode 时会暴露 `toolProgress` 数组。每个 `ToolProgress` 记录：

| 字段 | 说明 |
| --- | --- |
| `name` | Tool 名称 |
| `state` | `starting`、`running`、`completed` 或 `error` |
| `toolCallId` | LLM 产生的 Tool Call ID |
| `input` | Tool 输入参数 |
| `data` | 最近一次 `on_tool_event` 数据 |
| `result` | `on_tool_end` 的最终结果 |
| `error` | `on_tool_error` 的错误 |

```typescript
import { useStream } from "@langchain/langgraph-sdk/react";

function Chat() {
  const stream = useStream({
    assistantId: "my-agent",
    streamMode: ["values", "tools"],
  });

  const activeTools = stream.toolProgress.filter(
    (t) => t.state === "starting" || t.state === "running"
  );

  return (
    <div>
      {activeTools.map((tool) => (
        <ToolProgressCard
          key={tool.toolCallId ?? tool.name}
          name={tool.name}
          state={tool.state}
          data={tool.data}
        />
      ))}
    </div>
  );
}
```

`tools` 与 `custom` 都可以表达进度，但定位不同：

- **`tools`**：自动提供结构化 Tool Lifecycle Event；异步生成器 Tool 可以自然地产生 Progress。
- **`custom`**：完全自由的数据 Channel，适用于 Node Progress、UI Event 或无法映射到 Tool Lifecycle 的内容。

### Subgraph 输出

如果希望父图 Stream 中包含 [Subgraph](/oss/langgraph/use-subgraphs) 输出，应设置 `subgraphs=True` / `subgraphs: true`。

:::python
v2 中 Subgraph Event 与根图使用相同 `StreamPart`，通过 `ns` 判断来源：

```python
for chunk in graph.stream(
    {"foo": "foo"},
    subgraphs=True,
    stream_mode="updates",
    version="v2",
):
    print(chunk["type"])
    print(chunk["ns"])
    print(chunk["data"])
```
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  { foo: "foo" },
  { subgraphs: true, streamMode: "updates" }
)) {
  console.log(chunk);
}
```
:::

<Note>
该设置适用于所有 Stream Mode，包括 `messages`。如果把 `create_agent` / `createAgent` 返回的已编译 Agent 嵌入父图，它就是 Subgraph；不打开 `subgraphs` 时，父图的 `messages` Stream 不会自动包含内层 Agent 的 Token。
</Note>

### `checkpoints`

如果图使用 Checkpointer 编译，`checkpoints` 模式会在创建 Checkpoint 时发出包含 State、Task、Config 和 Metadata 的事件。需要观察持久化边界、时间旅行或恢复行为时非常有用。

:::python
```python
for chunk in graph.stream(
    inputs,
    config=config,
    stream_mode="checkpoints",
    version="v2",
):
    if chunk["type"] == "checkpoints":
        print(chunk["data"])
```
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  inputs,
  { ...config, streamMode: "checkpoints" }
)) {
  console.log(chunk);
}
```
:::

<a id="tasks"></a>
### `tasks`

`tasks` 模式会发出 Task Start / Finish / Error 等 Runtime Event，用于观察每个 Pregel Task 的生命周期。

:::python
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    config=config,
    stream_mode="tasks",
    version="v2",
):
    if chunk["type"] == "tasks":
        print(chunk["data"])
```
:::

<a id="debug"></a>
### `debug`

`debug` 模式尽可能输出完整调试信息，包括 Node Name、完整 State、Checkpoint 与 Task Event。

:::python
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="debug",
    version="v2",
):
    if chunk["type"] == "debug":
        print(chunk["data"])
```

<Note>
`debug` 会把 `checkpoints` 与 `tasks` 等信息组合在一起。如果只需要某类信息，直接使用对应 Stream Mode 更高效。
</Note>
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  { topic: "ice cream" },
  { streamMode: "debug" }

  console.log(chunk);
}
```

### 同时使用多个模式

:::python

for chunk in graph.stream(

## 高级用法

### 与任意 LLM API 配合

即使某个 LLM API 没有实现 LangChain Chat Model 接口，也可以使用 `custom` Stream Mode 把它自己的流式 Chunk 转发给 LangGraph Client。

:::python
```python
from langgraph.config import get_stream_writer

def call_arbitrary_model(state):
    writer = get_stream_writer()
    for chunk in your_custom_streaming_client(state["topic"]):
        writer({"custom_llm_chunk": chunk})
    return {"result": "completed"}

for chunk in graph.stream(
    {"topic": "cats"},
    stream_mode="custom",
    version="v2",
):
    if chunk["type"] == "custom":
        print(chunk["data"])
```
:::

:::js
```typescript
const callArbitraryModel: GraphNode<typeof State> = async (state, config) => {
  for await (const chunk of yourCustomStreamingClient(state.topic)) {
    config.writer({ custom_llm_chunk: chunk });
  }
  return { result: "completed" };
};
```
:::

### 对特定 Chat Model 禁用 Streaming

应用可能同时使用支持 Streaming 与不支持 Streaming 的模型。可以对单个模型显式关闭 Streaming。

:::python
```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "claude-sonnet-4-6",
    streaming=False,
)
```

如果某个 Integration 不支持 `streaming` 参数，可以使用所有 Chat Model 基类都支持的 `disable_streaming=True`。
:::

:::js
```typescript
import { ChatOpenAI } from "@langchain/openai";

const model = new ChatOpenAI({
  model: "gpt-5.5",
  streaming: false,
});
```

不支持 `streaming` 参数的 Integration 可以使用 `disableStreaming: true`。
:::

:::python
### 从 v1 迁移到 v2

v2 的主要价值是：无论模式数量与 Subgraph 设置如何，输出统一为 `StreamPart`。

| 场景 | v1 | v2 (`version="v2"`) |
| --- | --- | --- |
| 单个模式 | 原始数据 | `StreamPart`：`type` / `ns` / `data` |
| 多个模式 | `(mode, data)` | 同一种 `StreamPart`，检查 `chunk["type"]` |
| Subgraph | `(namespace, data)` | 同一种 `StreamPart`，检查 `chunk["ns"]` |
| 多模式 + Subgraph | `(namespace, mode, data)` | 同一种 `StreamPart` |
| `invoke()` | 普通 State Dict | 在对应新 API 中可获得更结构化的输出 / Interrupt 信息 |

新代码优先使用 v2；旧代码可逐步把 Tuple Unpacking 改为根据 `type` 和 `ns` 分支。
:::

:::python
<a id="async"></a>
### Async + Python < 3.11

Python < 3.11 的 `asyncio` Task 不会自动传播 Context Variable，因此异步 Node 内调用 LLM 时，要显式把 `RunnableConfig` 传给 `ainvoke()`；自定义 Streaming 则应显式接收 Writer，而不是依赖 `get_stream_writer()`。

```python
async def call_model(state, config):
    response = await model.ainvoke(messages, config)
    return {"response": response}
```

Python 3.11+ 通常可以由 ContextVar 自动传播这些信息。
:::

## 什么时候用 Streaming，什么时候用 Event Streaming

- 需要最底层 `stream_mode`、`tasks`、`checkpoints`、`debug` 等 Runtime Event：使用本页的 **Streaming**。
- 希望分别消费 `messages`、`values`、`subgraphs`、`output`，避免手工解析 Chunk：优先使用 [Event Streaming](/oss/langgraph/event-streaming)。
- 部署在 Agent Server 后并通过远程 Client 消费：参阅 [LangSmith Streaming API](/langsmith/streaming)。
