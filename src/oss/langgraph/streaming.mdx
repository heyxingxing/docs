<Tip>
对于新应用，官方更推荐使用[事件流（Event Streaming）](/oss/langgraph/event-streaming)——这是 LangGraph v1.2 引入的 Typed Projection API。Event Streaming 为 Message、Value、Subgraph、Output 等 Projection 提供彼此独立的 Iterator，因此你不需要自己在一个混合 Stream 中根据 `stream_mode` 分支处理 Chunk。
</Tip>

本页介绍 LangGraph 的 **Stream Mode API**。它通过 `updates`、`values`、`messages`、`custom`、`checkpoints`、`tasks`、`tools` 与 `debug` 等模式暴露 Graph Execution。当你需要直接消费 Runtime Event 或某种特定 Stream Output 时，可以使用这套 API。

## 快速开始

### 基础用法

:::python
LangGraph Graph 提供同步 @[`stream`][Pregel.stream] 与异步 @[`astream`][Pregel.astream] 方法，以 Iterator 形式持续产出结果。通过一个或多个 [Stream Mode](#stream-modes) 控制希望接收的数据。

```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["updates", "custom"],
    version="v2",
):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"Node {node_name} updated: {state}")
    elif chunk["type"] == "custom":
        print(f"Status: {chunk['data']['status']}")
```

```shell title="Output"
Status: thinking of a joke...
Node generate_joke updated: {'joke': 'Why did the ice cream go to school? To get a sundae education!'}
```

<Accordion title="完整示例">
```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.config import get_stream_writer

class State(TypedDict):
    topic: str
    joke: str

def generate_joke(state: State):
    writer = get_stream_writer()
    writer({"status": "thinking of a joke..."})
    return {"joke": f"Why did the {state['topic']} go to school? To get a sundae education!"}

graph = (
    StateGraph(State)
    .add_node(generate_joke)
    .add_edge(START, "generate_joke")
    .add_edge("generate_joke", END)
    .compile()
)

for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["updates", "custom"],
    version="v2",
):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"Node {node_name} updated: {state}")
    elif chunk["type"] == "custom":
        print(f"Status: {chunk['data']['status']}")
```
</Accordion>
:::

```typescript
for await (const chunk of await graph.stream(inputs, {
  streamMode: "updates",

```

### Stream Output Format（v2）

<Note>
需要 LangGraph 1.1 或更高版本。本页 Python 示例统一使用 `version="v2"`。
</Note>

传入 `version="v2"` 后，无论使用多少 Stream Mode、是否启用 Subgraph，所有 Chunk 都拥有统一的 `StreamPart` Shape：

```python
{
    "type": "values" | "updates" | "messages" | "custom" | "checkpoints" | "tasks" | "debug",
    "ns": (),           # subgraph event 时填充 namespace path
    "data": ...,        # payload，类型由 stream mode 决定
}
```

每种 Mode 都有对应 `TypedDict`：@[`ValuesStreamPart`]、@[`UpdatesStreamPart`]、@[`MessagesStreamPart`]、@[`CustomStreamPart`]、@[`CheckpointStreamPart`]、@[`TasksStreamPart`]、@[`DebugStreamPart`]。可以从 `langgraph.types` 导入。@[`StreamPart`] 是基于 `part["type"]` 的 Discriminated Union，因此 IDE / Type Checker 能够正确 Narrow `data` 的类型。

v1 的输出格式会随着 Streaming Option 改变：单 Mode 返回原始数据；多 Mode 返回 `(mode, data)`；Subgraph 返回 `(namespace, data)`。v2 始终使用同一种 Format：

<CodeGroup>
```python v2
for chunk in graph.stream(inputs, stream_mode="updates", version="v2"):
    print(chunk["type"])  # "updates"
    print(chunk["ns"])    # ()
    print(chunk["data"])  # {"node_name": {"key": "value"}}
```
```python v1
for chunk in graph.stream(inputs, stream_mode="updates"):
    print(chunk)
```
</CodeGroup>

v2 也支持 Type Narrowing：

```python
for part in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["values", "updates", "messages", "custom"],
    version="v2",
):
    if part["type"] == "values":
        print(f"State: topic={part['data']['topic']}")
    elif part["type"] == "updates":
        for node_name, state in part["data"].items():
            print(f"Node `{node_name}` updated: {state}")
    elif part["type"] == "messages":
        msg, metadata = part["data"]
        print(msg.content, end="", flush=True)
    elif part["type"] == "custom":
        print(f"Progress: {part['data']['progress']}%")
```
:::

## Stream Mode

:::python
可以向 @[`stream`][CompiledStateGraph.stream] / @[`astream`][CompiledStateGraph.astream] 传入一种或多种 Mode：

| Mode | Type | 说明 |
| :--- | :--- | :--- |
| [values](#graph-state) | @[`ValuesStreamPart`] | 每个 Step 后的完整 State。 |
| [updates](#graph-state) | @[`UpdatesStreamPart`] | 每个 Step 的 State Update；同一 Step 多个 Update 会分别输出。 |
| [messages](#llm-tokens) | @[`MessagesStreamPart`] | LLM Call 产生的 `(token/message chunk, metadata)`。 |
| [custom](#custom-data) | @[`CustomStreamPart`] | Node / Tool 通过 @[`get_stream_writer`] 主动发送的任意自定义数据。 |
| [checkpoints](#checkpoints) | @[`CheckpointStreamPart`] | Checkpoint Event；格式与 `get_state()` 类似，需要 Checkpointer。 |
| [tasks](#tasks) | @[`TasksStreamPart`] | Task Start / Finish Event，包括 Result 与 Error，需要 Checkpointer。 |
| [debug](#debug) | @[`DebugStreamPart`] | 尽可能完整的执行信息，组合 Checkpoint / Task 和额外 Metadata。 |
:::

:::js
JavaScript / TypeScript 支持：

| Mode | 说明 |
| :--- | :--- |
| [values](#graph-state) | 每个 Step 后的完整 State。 |
| [updates](#graph-state) | 每个 Step 的 State Update。 |
| [messages](#llm-tokens) | LLM Token 与 Metadata。 |
| [custom](#custom-data) | `writer` 发送的自定义数据。 |
| [tools](#tool-progress) | Tool 生命周期事件：`on_tool_start`、`on_tool_event`、`on_tool_end`、`on_tool_error`。 |
| [debug](#debug) | Graph Execution 的完整 Debug 信息。 |
:::

<a id="messages"></a>

### Graph State

使用 `updates` 与 `values` 可以观察 Graph State 如何随执行推进：

- `updates`：只输出当前 Step 的**增量更新**。
- `values`：输出当前 Step 完成后的**完整 State Snapshot**。

:::python
```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
  topic: str
  joke: str

def refine_topic(state: State):
    return {"topic": state["topic"] + " and cats"}

def generate_joke(state: State):
    return {"joke": f"This is a joke about {state['topic']}"}

graph = (
  StateGraph(State)
  .add_node(refine_topic)
  .add_node(generate_joke)
  .add_edge(START, "refine_topic")
  .add_edge("refine_topic", "generate_joke")
  .add_edge("generate_joke", END)
  .compile()
)
```

<Tabs>
<Tab title="updates">
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="updates",
    version="v2",
):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"Node `{node_name}` updated: {state}")
```
</Tab>
<Tab title="values">
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="values",
    version="v2",
):
    if chunk["type"] == "values":
        print(f"topic: {chunk['data']['topic']}, joke: {chunk['data']['joke']}")
```
</Tab>
</Tabs>
:::

```typescript

import { z } from "zod/v4";
```

### LLM Token

`messages` Mode 可以从 Graph 任意位置——Node、Tool、Subgraph 或 Task——实时流式输出 LLM Token。

:::python
`messages` Mode 的每个 Payload 都是 `(message_chunk, metadata)`：

- `message_chunk`：LLM Token / Message Segment。
- `metadata`：对应 Graph Node、Model Invocation 等 Metadata。

如果使用的 LLM 没有 LangChain Integration，可以改用 [`custom`](#custom-data) Mode 手动转发 Token。

<Warning>
Python < 3.11 的 Async Code 需要手动把 @[`RunnableConfig`] 传给 `ainvoke()`，否则 Callback Context 无法正确传播。详情见[Python < 3.11 Async](#async)。
</Warning>

```python
from dataclasses import dataclass
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, START

@dataclass
class MyState:
    topic: str
    joke: str = ""

model = init_chat_model(model="gpt-5.4-mini")

def call_model(state: MyState):
    response = model.invoke([
        {"role": "user", "content": f"Write a joke about {state.topic}"}
    ])
    return {"joke": response.content}

graph = StateGraph(MyState).add_node(call_model).add_edge(START, "call_model").compile()

for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="messages",
    version="v2",
):
    if chunk["type"] == "messages":
        message_chunk, metadata = chunk["data"]
        if message_chunk.content:
            print(message_chunk.content, end="|", flush=True)
```
:::

:::js
```typescript
for await (const [messageChunk, metadata] of await graph.stream(inputs, {
  streamMode: "messages",
})) {
  if (messageChunk.content) process.stdout.write(String(messageChunk.content));
}
```
:::

#### 按 Metadata 过滤 LLM Token

复杂 Graph 里可能有多个 LLM Node 并行输出 Token。可以利用 `metadata["langgraph_node"]` 只消费某个 Node 的输出。

:::python
```python
for chunk in graph.stream(
    {"topic": "cats"},
    stream_mode="messages",
    version="v2",
):
    if chunk["type"] == "messages":
        msg, metadata = chunk["data"]
        if msg.content and metadata["langgraph_node"] == "write_poem":
            print(msg.content, end="|", flush=True)
```
:::

:::js
```typescript
for await (const [msg, metadata] of await graph.stream(
  { topic: "cats" },
  { streamMode: "messages" }
)) {
  if (msg.content && metadata.langgraph_node === "writePoem") {
    console.log(msg.content + "|");
  }
}
```

### Custom Data

如果希望从 Node 或 Tool 内发送任意自定义数据，例如进度、日志、检索状态或业务 Event，可以使用 `custom` Mode。

:::python
步骤：

1. 使用 @[`get_stream_writer`] 获取 Writer，并发出任意 Payload。
2. 调用 `.stream()` / `.astream()` 时设置 `stream_mode="custom"`，或者组合 `["updates", "custom"]`。

<Warning>
Python < 3.11 的 Async Code 中 @[`get_stream_writer`] 无法正常工作，应在 Node / Tool Function Signature 中显式接收 `writer: StreamWriter`。参见[Async](#async)。
</Warning>

<Tabs>
<Tab title="node">
```python
from typing import TypedDict
from langgraph.config import get_stream_writer
from langgraph.graph import StateGraph, START

class State(TypedDict):
    query: str
    answer: str

def node(state: State):
    writer = get_stream_writer()
    writer({"custom_key": "Generating custom data inside node"})
    return {"answer": "some data"}

graph = StateGraph(State).add_node(node).add_edge(START, "node").compile()

for chunk in graph.stream(
    {"query": "example"},
    stream_mode="custom",
    version="v2",
):
    if chunk["type"] == "custom":
        print(chunk["data"])
```
</Tab>
<Tab title="tool">
```python
from langchain.tools import tool
from langgraph.config import get_stream_writer

@tool
def query_database(query: str) -> str:
    """Query the database."""
    writer = get_stream_writer()
    writer({"data": "Retrieved 0/100 records", "type": "progress"})
    # perform query
    writer({"data": "Retrieved 100/100 records", "type": "progress"})
    return "some-answer"
```
</Tab>
</Tabs>
:::

:::js
Node / Tool 可以使用 Runtime Config 中的 `writer`：

```typescript
const node: GraphNode<typeof State> = async (state, config) => {
  config.writer({ custom_key: "Generating custom data inside node" });
  return { answer: "some data" };
};

for await (const chunk of await graph.stream(inputs, { streamMode: "custom" })) {
  console.log(chunk);
}
```

### Tool Progress

`tools` Stream Mode 会实时发送 Tool Execution Lifecycle Event，适合 UI 中显示 Progress、Partial Result 与 Error State。

| Event | 何时触发 | Payload |
|---|---|---|
| `on_tool_start` | Tool Invocation 开始 | `name`、`input`、`toolCallId` |
| `on_tool_event` | Tool 产生中间数据 | `name`、`data`、`toolCallId` |
| `on_tool_end` | Tool 返回最终结果 | `name`、`output`、`toolCallId` |
| `on_tool_error` | Tool 抛错 | `name`、`error`、`toolCallId` |

要主动发送 `on_tool_event`，把 Tool Function 定义成 **Async Generator**：每次 `yield` 都会产生一个 Progress Event，最终 `return` Value 作为 Tool Result。

```typescript
const searchFlights = tool(
  async function* (input) {
    const airlines = ["United", "Delta", "American", "JetBlue"];
    const completed: string[] = [];

    for (let i = 0; i < airlines.length; i++) {
      await new Promise((r) => setTimeout(r, 500));
      completed.push(airlines[i]);
      yield {
        message: `Searching ${airlines[i]}...`,
        progress: (i + 1) / airlines.length,
        completed,
      };
    }

    return JSON.stringify({ flights: [] });
  },
  {
    name: "search_flights",
    description: "Search for available flights to a destination.",
    schema: z.object({ destination: z.string(), date: z.string() }),
  }
);
```

既有返回 Promise 的 Tool 完全兼容，只是只会产生 Start / End，而不会产生中间 `on_tool_event`。

```typescript
for await (const [mode, chunk] of await graph.stream(
  { messages: [{ role: "user", content: "Find flights to Tokyo" }] },
  { streamMode: ["updates", "tools"] }
)) {
  if (mode === "tools") {
    switch (chunk.event) {
      case "on_tool_start":
        console.log(`Tool started: ${chunk.name}`, chunk.input);
        break;
      case "on_tool_event":
        console.log(`Tool progress: ${chunk.name}`, chunk.data);
        break;
      case "on_tool_end":
        console.log(`Tool finished: ${chunk.name}`, chunk.output);
        break;
      case "on_tool_error":
        console.error(`Tool failed: ${chunk.name}`, chunk.error);
        break;
    }
  }
}
```

前端 `useStream` 在启用 `"tools"` Mode 后会提供 `toolProgress` Array，每项包含 `name`、`state`、`toolCallId`、`input`、`data`、`result`、`error`。

**`tools` vs `custom`**：

- `tools`：自动产生结构化 Tool Lifecycle Event，特别适合 Tool Progress UI。
- `custom`：完全自由的数据通道，也可以从普通 Node 发送，适合不属于 Tool Lifecycle 的业务 Event。
:::

### Subgraph Output

如果希望 Parent Graph Stream 同时包含 [Subgraph](/oss/langgraph/use-subgraphs) Output，设置 `subgraphs=True` / `subgraphs: true`。

:::python
v2 中所有 Subgraph Event 仍然使用统一 `StreamPart` Format，区别在 `ns`：根 Graph 的 `ns=()`，Subgraph 则是类似 `("node_name:<task_id>",)` 的 Namespace Path。

```python
for chunk in graph.stream(
    {"foo": "foo"},
    subgraphs=True,
    stream_mode="updates",
    version="v2",
):
    print(chunk["type"])
    print(chunk["ns"])
    print(chunk["data"])
```
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  { foo: "foo" },
  { subgraphs: true, streamMode: "updates" }
)) {
  console.log(chunk);
}
```
:::

<Note>
这对**所有** Stream Mode 都适用，包括 `messages`。像 `create_agent` / `createAgent` 这样的 Agent Builder 返回的是已编译 Graph；把它添加为 Parent Graph Node 后就成为 Subgraph。如果 Parent 不启用 `subgraphs=True`，Parent 的 `messages` Stream 不会自动收到内部 Agent 的 LLM Token。
</Note>

<Accordion title="完整示例：从 Subgraph 流式输出">
:::python
```python
from langgraph.graph import START, StateGraph
from typing import TypedDict

class SubgraphState(TypedDict):
    foo: str
    bar: str

def subgraph_node_1(state: SubgraphState):
    return {"bar": "bar"}

def subgraph_node_2(state: SubgraphState):
    return {"foo": state["foo"] + state["bar"]}

subgraph = (
    StateGraph(SubgraphState)
    .add_node(subgraph_node_1)
    .add_node(subgraph_node_2)
    .add_edge(START, "subgraph_node_1")
    .add_edge("subgraph_node_1", "subgraph_node_2")
    .compile()
)

class ParentState(TypedDict):
    foo: str

def node_1(state: ParentState):
    return {"foo": "hi! " + state["foo"]}

graph = (
    StateGraph(ParentState)
    .add_node("node_1", node_1)
    .add_node("node_2", subgraph)
    .add_edge(START, "node_1")
    .add_edge("node_1", "node_2")
    .compile()
)

for chunk in graph.stream(
    {"foo": "foo"},
    stream_mode="updates",
    subgraphs=True,
    version="v2",
):
    if chunk["type"] == "updates":
        if chunk["ns"]:
            print(f"Subgraph {chunk['ns']}: {chunk['data']}")
        else:
            print(f"Root: {chunk['data']}")
```
:::
</Accordion>

:::python
### Checkpoint

`checkpoints` Mode 会在 Graph 执行期间实时发送 Checkpoint Event，数据格式与 `get_state()` 返回的 State Snapshot 类似。需要 Graph 配置 [Checkpointer](/oss/langgraph/persistence)。

```python
from langgraph.checkpoint.memory import MemorySaver

graph = builder.compile(checkpointer=MemorySaver())
config = {"configurable": {"thread_id": "1"}}

for chunk in graph.stream(
    inputs,
    config=config,
    stream_mode="checkpoints",
    version="v2",
):
    if chunk["type"] == "checkpoints":
        print(chunk["data"])
```

### Task

`tasks` Mode 会发送 Task Start / Finish Event，包括执行的 Node、Result 和 Error。也需要 [Checkpointer](/oss/langgraph/persistence)。

```python
for chunk in graph.stream(
    inputs,
    config=config,
    stream_mode="tasks",
    version="v2",
):
    if chunk["type"] == "tasks":
        print(chunk["data"])
```
:::

### Debug

`debug` Mode 输出尽可能多的 Graph Execution 信息，包括 Node Name 与完整 State。

:::python
```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode="debug",
    version="v2",
):
    if chunk["type"] == "debug":
        print(chunk["data"])
```

<Note>
`debug` 会组合 `checkpoints` 与 `tasks` 并附带额外 Metadata。如果只需要其中一部分，直接使用 `checkpoints` 或 `tasks` 更简单。
</Note>
:::

:::js
```typescript
for await (const chunk of await graph.stream(
  { topic: "ice cream" },
  { streamMode: "debug" }

}
```

## 进阶

### 与任意 LLM 一起使用

`custom` Mode 不依赖 LangChain Chat Model Interface，因此即使底层模型客户端是 OpenAI 原生 SDK、内部 HTTP Client 或其他自定义 Streaming API，也可以手动把 Token 写入 LangGraph Stream。

:::python
```python
from langgraph.config import get_stream_writer

def call_arbitrary_model(state):
    writer = get_stream_writer()
    for chunk in your_custom_streaming_client(state["topic"]):
        writer({"custom_llm_chunk": chunk})
    return {"result": "completed"}

for chunk in graph.stream(
    {"topic": "cats"},
    stream_mode="custom",
    version="v2",
):
    if chunk["type"] == "custom":
        print(chunk["data"])
```
:::

:::js
```typescript
const callArbitraryModel: GraphNode<typeof State> = async (state, config) => {
  for await (const chunk of yourCustomStreamingClient(state.topic)) {
    config.writer({ custom_llm_chunk: chunk });
  }
  return { result: "completed" };
};
```
:::

### 对特定 Chat Model 禁用 Streaming

如果一个应用同时使用支持 Streaming 与不支持 Streaming 的 Model，需要对不支持的 Model 显式关闭流式能力。

:::python
优先在初始化 Model 时设置 `streaming=False`：

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "claude-sonnet-4-6",
    streaming=False,
)
```

如果某个 Integration 不支持 `streaming` 参数，可以使用 Base Class 提供的 `disable_streaming=True`。
:::

:::js
```typescript
const model = new ChatOpenAI({
  model: "gpt-5.5",
  streaming: false,
});
```

如果 Integration 不支持该参数，可以使用 `disableStreaming: true`。
:::

:::python
### 迁移到 v2

v2 提供统一输出格式：

| 场景 | v1 | v2 (`version="v2"`) |
|---|---|---|
| 单一 Stream Mode | 原始 Data | `StreamPart`：`type` / `ns` / `data` |
| 多个 Stream Mode | `(mode, data)` | 同一种 `StreamPart` |
| Subgraph Streaming | `(namespace, data)` | 同一种 `StreamPart`，检查 `ns` |
| 多 Mode + Subgraph | `(namespace, mode, data)` | 同一种 `StreamPart` |
| `invoke()` Return | Plain Dict | `GraphOutput`，包含 `.value` 与 `.interrupts` |
| Interrupt（Stream） | State 中 `__interrupt__` | `values` Part 的 `interrupts` Field |
| Interrupt（Invoke） | Result Dict 中 `__interrupt__` | `GraphOutput.interrupts` |
| Pydantic / Dataclass | Plain Dict | 自动 Coerce 为 Model / Dataclass Instance |

#### v2 Invoke Format

```python
from langgraph.types import GraphOutput

result = graph.invoke(inputs, version="v2")

assert isinstance(result, GraphOutput)
result.value
result.interrupts
```

<Warning>
`GraphOutput` 仍暂时支持 `result["key"]`、`"key" in result` 和 `result["__interrupt__"]` 等 Dict-style Access，但这些 API 已 Deprecated。应迁移到 `result.value` 与 `result.interrupts`。
</Warning>

恢复 Interrupt：

<CodeGroup>
```python v2
config = {"configurable": {"thread_id": "thread-1"}}
result = graph.invoke(inputs, config=config, version="v2")

if result.interrupts:
    print(result.interrupts[0].value)
    graph.invoke(Command(resume=True), config=config, version="v2")
```
```python v1
config = {"configurable": {"thread_id": "thread-1"}}
result = graph.invoke(inputs, config=config)

if "__interrupt__" in result:
    print(result["__interrupt__"][0].value)
    graph.invoke(Command(resume=True), config=config)
```
</CodeGroup>

#### Pydantic / Dataclass State Coercion

v2 的 `values` Mode 会根据 Graph State Schema 自动把 Output Coerce 回 Pydantic Model / Dataclass：

```python
from pydantic import BaseModel
from typing import Annotated
import operator

class MyState(BaseModel):
    value: str
    items: Annotated[list[str], operator.add]

for chunk in graph.stream(
    {"value": "x", "items": []},
    stream_mode="values",
    version="v2",
):
    print(type(chunk["data"]))  # <class 'MyState'>
```

### Python < 3.11 的 Async 注意事项

Python < 3.11 的 `asyncio` Task 不支持 `context` Parameter，因此 LangGraph 无法自动传播完整 Context。这会影响 Streaming：

1. Async LLM Call（例如 `ainvoke()`）必须显式传 @[`RunnableConfig`]，否则 Callback 不能正确传播。
2. Async Node / Tool 中不能使用 @[`get_stream_writer`]；必须显式接收 `writer: StreamWriter`。

**手动传 Config：**

```python
async def call_model(state, config):
    joke_response = await model.ainvoke(
        [{"role": "user", "content": f"Write a joke about {state['topic']}"}],
        config,
    )
    return {"joke": joke_response.content}

async for chunk in graph.astream(
    {"topic": "ice cream"},
    stream_mode="messages",
    version="v2",
):
    if chunk["type"] == "messages":
        message_chunk, metadata = chunk["data"]
        if message_chunk.content:
            print(message_chunk.content, end="|", flush=True)
```

**手动接收 Writer：**

```python
from langgraph.types import StreamWriter

async def generate_joke(state: State, writer: StreamWriter):
    writer({"custom_key": "Streaming custom data while generating a joke"})
    return {"joke": f"This is a joke about {state['topic']}"}

async for chunk in graph.astream(
    {"topic": "ice cream"},
    stream_mode="custom",
    version="v2",
):
    if chunk["type"] == "custom":
        print(chunk["data"])
```
