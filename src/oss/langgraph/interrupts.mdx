Interrupt 允许你在图执行到任意位置时暂停，并在继续之前等待外部输入。这是 LangGraph 实现**人在回路（Human-in-the-loop）**工作流的核心机制。当触发 Interrupt 时，LangGraph 会通过[持久化层](/oss/langgraph/persistence)保存 Graph State，并可以无限期等待，直到你显式恢复执行。

在任意 Graph Node 中调用 `interrupt()` 即可暂停执行。这个函数接收任意可 JSON 序列化的 Value，并把它暴露给调用方。准备继续时，再次调用 Graph，并传入带 `resume` Value 的 `Command`；这个 Resume Value 会成为 Node 内 `interrupt()` 调用的返回值。

与在固定 Node 前后暂停的静态断点不同，Interrupt 是**动态的**：它可以出现在代码任意位置，也可以根据业务逻辑有条件触发。

:::python
- **Checkpoint 会保存现场**：Checkpointer 会写入精确 Graph State，因此即使图处于 Error / Pause 状态，也可以稍后恢复。
- **`thread_id` 是持久游标**：通过 `config={"configurable": {"thread_id": ...}}` 告诉 Checkpointer 要加载哪条 Thread 的 State。
- **Event Streaming 中的 Interrupt Payload**：使用 `graph.stream_events(..., version="v3")` 时，传给 `interrupt()` 的值会出现在 `stream.interrupts` 中；如果 Run 因等待输入而暂停，`stream.interrupted` 为 `True`。
:::

:::js
- **Checkpoint 会保存现场**：Checkpointer 保存精确 Graph State，因此以后可以恢复。
- **`thread_id` 是持久游标**：调用 `invoke` 时传入 `{ configurable: { thread_id: ... } }`。
- **Interrupt Payload 会出现在 `__interrupt__`**：传给 `interrupt()` 的值会通过结果的 `__interrupt__` 字段返回。
:::

复用同一个 `thread_id` 会继续同一条执行历史；使用新的值则会创建全新的 Thread 和空 State。

## 使用 `interrupt` 暂停执行

@[`interrupt`] 会暂停图，并向外部调用方返回一个 Value。要使用它，需要：

1. 配置 **Checkpointer** 以持久化 Graph State；生产环境应使用持久化后端。
2. 在 Config 中提供 **Thread ID**，Runtime 才知道应该恢复哪份 State。
3. 在需要暂停的位置调用 `interrupt()`，Payload 必须能够进行 JSON 序列化。

:::python
```python
from langgraph.types import interrupt

def approval_node(state: State):
    # Pause and ask for approval
    approved = interrupt("Do you approve this action?")

    # When you resume, Command(resume=...) returns that value here
    return {"approved": approved}
```
:::

:::js
```typescript
import { interrupt } from "@langchain/langgraph";

async function approvalNode(state: State) {
    // Pause and ask for approval
    const approved = interrupt("Do you approve this action?");

    // Command({ resume: ... }) provides the value returned into this variable
    return { approved };
}
```
:::

调用 `interrupt()` 后：

1. Graph Execution 在当前 Interrupt 位置暂停。
2. Checkpointer 保存 State；生产环境中应使用数据库等持久化 Checkpointer。
3. Interrupt Payload 返回给调用方。
4. 图会持续等待，直到收到 Resume 输入。
5. Resume Value 被传回 Node，成为 `interrupt()` 的返回值。

## 恢复 Interrupt

Graph 暂停后，通过再次调用图，并把 Resume Value 放入 `Command(resume=...)` 来继续执行。

:::python
推荐使用 [Event Streaming](/oss/langgraph/event-streaming) 驱动可能发生 Interrupt 的图：

<LanggraphInterruptsResumeV2Py />

<Note>
普通 `graph.invoke(...)` 同样支持 Interrupt，并通过 `result["__interrupt__"]` 暴露结果。如果不需要类型化 Stream Projection，可以继续使用它；否则优先使用 `graph.stream_events(..., version="v3")`。
</Note>
:::

:::js
```typescript
import { Command } from "@langchain/langgraph";

const config = { configurable: { thread_id: "thread-1" } };

// Initial run - hits the interrupt and pauses
const result = await graph.invoke({ input: "data" }, config);
console.log(result.__interrupt__);

// Resume with the human's response
await graph.invoke(new Command({ resume: true }), config);
```
:::

恢复时要记住：

- 必须使用触发 Interrupt 时的**同一个 Thread ID**。
- `Command(resume=...)` 中的 Value 会成为 @[`interrupt`] 调用的返回值。
- Resume 时，**Node 会从函数开头重新执行**，而不是从 Interrupt 所在的源代码行继续；因此 Interrupt 之前的代码会再次运行。
- Resume Value 可以是任意可 JSON 序列化 Value。

<Warning>
`Command(resume=...)` 是把 `Command` 作为 `invoke()` / `stream()` / `stream_events()` **输入**时的主要模式。`update`、`goto`、`graph` 等其他参数主要用于[从 Node 返回 Command](/oss/langgraph/graph-api#command)。普通多轮对话应传入正常输入对象，不要使用只有 `Command(update=...)` 的输入来“开始下一轮”。
</Warning>

## 常见模式

Interrupt 最重要的能力是“暂停并等待外部输入”，典型场景包括：

- <Icon icon="circle-check" /> [审批工作流](#approve-or-reject)：在执行 API 调用、数据库修改、支付等高影响操作前暂停。
- <Icon icon="link" /> [处理多个 Interrupt](#handling-multiple-interrupts)：同一次 Invocation 中并行分支可能产生多个 Interrupt。
- <Icon icon="pencil" /> [审核和修改 State](#review-and-edit-state)：人工检查并修改 LLM 输出或 Tool Call。
- <Icon icon="tool" /> [在 Tool 内部 Interrupt](#interrupts-in-tools)：Tool 真正执行前进行审核与编辑。
- <Icon icon="shield-check" /> [校验人工输入](#validating-human-input)：输入非法时重新询问。

### 处理多个 Interrupt

如果多个并行分支同时调用 `interrupt()`，一次 Invocation 可能产生多个待恢复 Interrupt。此时应把每个 **Interrupt ID** 映射到对应 Resume Value，以确保 Runtime 正确配对。

:::python
<LanggraphInterruptsMultiplePy />
:::

:::js
```typescript
import {
  Annotation,
  Command,
  END,
  INTERRUPT,
  MemorySaver,
  START,
  StateGraph,
  interrupt,
  isInterrupted,
} from "@langchain/langgraph";

const State = Annotation.Root({
  vals: Annotation<string[]>({
    reducer: (left, right) =>
      left.concat(Array.isArray(right) ? right : [right]),
    default: () => [],
  }),
});

function nodeA(_state: typeof State.State) {
  const answer = interrupt("question_a") as string;
  return { vals: [`a:${answer}`] };
}

function nodeB(_state: typeof State.State) {
  const answer = interrupt("question_b") as string;
  return { vals: [`b:${answer}`] };
}

const graph = new StateGraph(State)
  .addNode("a", nodeA)
  .addNode("b", nodeB)
  .addEdge(START, "a")
  .addEdge(START, "b")
  .addEdge("a", END)
  .addEdge("b", END)
  .compile({ checkpointer: new MemorySaver() });

const config = { configurable: { thread_id: "1" } };

const interruptedResult = await graph.invoke({ vals: [] }, config);
const resumeMap: Record<string, string> = {};
if (isInterrupted(interruptedResult)) {
  for (const i of interruptedResult[INTERRUPT]) {
    if (i.id != null) resumeMap[i.id] = `answer for ${i.value}`;
  }
}
const result = await graph.invoke(new Command({ resume: resumeMap }), config);
```
:::

### 批准或拒绝

最常见的模式是在高影响动作前暂停并请求批准：

:::python
```python
from typing import Literal
from langgraph.types import interrupt, Command

def approval_node(state: State) -> Command[Literal["proceed", "cancel"]]:
    is_approved = interrupt({
        "question": "Do you want to proceed with this action?",
        "details": state["action_details"]
    })

    if is_approved:
        return Command(goto="proceed")
    return Command(goto="cancel")
```
:::

:::js
```typescript
import { interrupt, Command } from "@langchain/langgraph";

const approvalNode: typeof State.Node = (state) => {
  const isApproved = interrupt({
    question: "Do you want to proceed?",
    details: state.actionDetails
  });

  if (isApproved) return new Command({ goto: "proceed" });
  return new Command({ goto: "cancel" });
}
```
:::

:::python
批准时传 `True`，拒绝时传 `False`：

```python
graph.stream_events(Command(resume=True), config=config, version="v3").output
graph.stream_events(Command(resume=False), config=config, version="v3").output
```
:::

:::js
```typescript
await graph.invoke(new Command({ resume: true }), config);
await graph.invoke(new Command({ resume: false }), config);
```

<a id="interrupts-in-tools"></a>
### 在 Tool 中使用 Interrupt

Interrupt 也可以直接放在 Tool 函数内部。这样，无论 Tool 在图的哪个位置被调用，都会在真正执行前自动暂停，便于人工批准、编辑参数或取消操作。

:::python
```python
from langchain.tools import tool
from langgraph.types import interrupt

@tool
def send_email(to: str, subject: str, body: str):
    """Send an email to a recipient."""

    response = interrupt({
        "action": "send_email",
        "to": to,
        "subject": subject,
        "body": body,
        "message": "Approve sending this email?"
    })

    if response.get("action") == "approve":
        final_to = response.get("to", to)
        final_subject = response.get("subject", subject)
        final_body = response.get("body", body)
        return f"Email sent to {final_to} with subject '{final_subject}'"
    return "Email cancelled by user"
```
:::

:::js
```typescript
import { tool } from "@langchain/core/tools";
import { interrupt } from "@langchain/langgraph";
import * as z from "zod";

const sendEmailTool = tool(
  async ({ to, subject, body }) => {
    const response = interrupt({
      action: "send_email",
      to,
      subject,
      body,
      message: "Approve sending this email?",
    });

    if (response?.action === "approve") {
      const finalTo = response.to ?? to;
      const finalSubject = response.subject ?? subject;
      const finalBody = response.body ?? body;
      return `Email sent to ${finalTo} with subject '${finalSubject}'`;
    }
    return "Email cancelled by user";
  },
  {
    name: "send_email",
    description: "Send an email to a recipient",
    schema: z.object({
      to: z.string(),
      subject: z.string(),
      body: z.string(),
    }),
  },
);
```
:::

这种模式把审批逻辑和 Tool 本身绑定在一起，因此 Tool 可在多个 Agent / Graph 中复用，而无需在每个调用点额外实现 HITL。

<a id="validating-human-input"></a>
### 校验人工输入

当输入非法，需要重新询问用户时，推荐模式是：**每次 Node Invocation 只调用一次 `interrupt()`**，把错误提示写入 State，然后使用 **Conditional Edge** 重新路由回该 Node。

<Warning>
不要在同一个 Node 中使用 `while True` + 多次 `interrupt()` 进行校验。因为每次 Resume 都会从 Node 开头重新执行，循环内此前迭代也会被重放，可能导致执行次数快速膨胀。
</Warning>

正确模式：

1. 在 State 中保存下一次要显示的问题，例如 `pending_question`。
2. Node 中只调用一次 `interrupt()`。
3. 如果输入非法，更新 `pending_question` 并返回。
4. 使用 Conditional Edge 再次进入同一 Node；输入合法后进入 `END` 或下一个 Node。

## Interrupt 使用规则

当 Node 内调用 @[`interrupt`] 时，LangGraph 会抛出一个由 Runtime 捕获的特殊异常，以此暂停执行并保存当前 State。收到 Resume 输入后，**整个 Node 会从函数开头重新运行**，并不是从 `interrupt()` 那一行继续。这带来几条必须遵循的规则。

### 不要用宽泛 `try/except` 包裹 `interrupt`

`interrupt()` 本身通过特殊异常暂停 Runtime。如果用宽泛 `except Exception` 捕获它，这个 Interrupt 可能无法传播到 Graph Runtime。

:::python
<CodeGroup>
```python Good
def node_a(state: State):
    interrupt("What's your name?")
    try:
        fetch_data()
    except Exception as e:
        print(e)
    return state
```
```python Specific exception
def node_a(state: State):
    try:
        name = interrupt("What's your name?")
        fetch_data()
    except NetworkException as e:
        print(e)
    return state
```
</CodeGroup>
:::

如果确实需要捕获 Error，尽量捕获具体异常类型，不要把 `interrupt()` 放进宽泛的 Exception Handler。

### 在同一 Node 中保持 Interrupt 调用顺序稳定

当 Node 包含多个 Interrupt 时，LangGraph 会为当前 Task 保存一组 Resume Value。每次 Resume 都从 Node 开头开始，并按**索引位置**把 Resume Value 与遇到的 Interrupt 依次配对。因此调用顺序必须保持稳定。

:::python
```python
def node_a(state: State):
    name = interrupt("What's your name?")
    age = interrupt("What's your age?")
    city = interrupt("What's your city?")
    return {"name": name, "age": age, "city": city}
```
:::

:::js
```typescript
async function nodeA(state: State) {
    const name = interrupt("What's your name?");
    const age = interrupt("What's your age?");
    const city = interrupt("What's your city?");
    return { name, age, city };
}
```
:::

不要：

- 根据可能变化的条件跳过某个 Interrupt。
- 用非确定性的循环动态产生不同数量的 Interrupt。
- 使用 `while True` + `interrupt()` 做输入校验；使用[条件边模式](#validating-human-input)。

### Interrupt Payload 必须容易序列化

推荐只传字符串、数字、布尔值、数组、普通 Object / Dict 等 JSON 兼容类型。

```python
response = interrupt({
    "question": "Enter user details",
    "fields": ["name", "email", "age"],
    "current_values": state.get("user", {})
})
```

不要在 Payload 中传函数、数据库连接、复杂类实例等对象，否则不同 Checkpointer / Serializer 可能无法保存。

### `interrupt` 之前的副作用必须幂等

因为 Resume 会从 Node 开头重跑，`interrupt()` 之前发生的副作用也会再次执行。比如先创建数据库记录、再 Interrupt，那么每次 Resume 都可能重复创建记录。

推荐：

- Interrupt 之前使用幂等操作，例如 Upsert。
- 尽可能把非幂等副作用放到 Interrupt 之后。
- 更复杂的副作用拆成独立 Node / Task，并配置可靠重试与 Idempotency Key。

:::python
<CodeGroup>
```python Idempotent operation
def node_a(state: State):
    db.upsert_user(
        user_id=state["user_id"],
        status="pending_approval"
    )
    approved = interrupt("Approve this change?")
    return {"approved": approved}
```
```python Side effect after interrupt
def node_a(state: State):
    approved = interrupt("Approve this change?")
    if approved:
        db.create_audit_log(
            user_id=state["user_id"],
            action="approved"
        )
    return {"approved": approved}
```
</CodeGroup>
:::

## 与以函数方式调用的 Subgraph 配合

如果 Parent Node 在函数内部调用 Subgraph，而 Subgraph 内触发 Interrupt，那么 Resume 时：

1. Parent Graph 会从**调用 Subgraph 的 Parent Node 开头**重新执行。
2. Subgraph 也会从触发 Interrupt 的 **Subgraph Node 开头**重新执行。

:::python
```python
def node_in_parent_graph(state: State):
    some_code()  # <-- re-executes when resumed
    subgraph_result = subgraph.invoke(some_input)

def node_in_subgraph(state: State):
    some_other_code()  # <-- also re-executes when resumed
    result = interrupt("What's your name?")
```
:::

:::js
```typescript
async function nodeInParentGraph(state: State) {
    someCode();
    const subgraphResult = await subgraph.invoke(someInput);
}

async function nodeInSubgraph(state: State) {
    someOtherCode();
    const result = interrupt("What's your name?");
}
```
:::

## 使用静态 Interrupt 调试

静态 Interrupt 可以作为 Breakpoint，在指定 Node **之前或之后**暂停执行，适合单步调试 Graph。

:::python
编译时设置：

```python
graph = builder.compile(
    interrupt_before=["node_a"],
    interrupt_after=["node_b", "node_c"],
    checkpointer=checkpointer,
)

config = {"configurable": {"thread_id": "some_thread"}}
graph.invoke(inputs, config=config)
graph.invoke(None, config=config)
```

也可以在单次 `invoke` 时通过 `interrupt_before` / `interrupt_after` 动态设置。
:::

:::js
编译时可通过 `interruptBefore` / `interruptAfter` 设置：

```typescript
const graph = builder.compile({
  interruptBefore: ["nodeA"],
  interruptAfter: ["nodeB", "nodeC"],
  checkpointer,
});

const config = { configurable: { thread_id: "some_thread" } };
await graph.invoke(inputs, config);
await graph.invoke(null, config);
```
:::

<Note>
静态 Interrupt 更适合 Debugging，不推荐作为正式 HITL 工作流。正式人在回路逻辑应优先使用 @[`interrupt`] 函数。
</Note>

<Tip>
使用 [LangSmith](/langsmith/observability) 可以观察 Interrupt 前后的 Trace、State 和 Tool Call。
</Tip>
