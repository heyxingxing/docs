## 概览

在 LangGraph 中，Pregel 将 [**Actor**](https://en.wikipedia.org/wiki/Actor_model) 和 **Channel** 组合成一个应用。**Actor** 从 Channel 读取数据，并向 Channel 写入数据。Pregel 按照 **Pregel Algorithm / Bulk Synchronous Parallel（批量同步并行）** 模型，将应用执行组织成多个 Step。

每个 Step 包含三个阶段：

* **Plan（规划）**：决定当前 Step 要执行哪些 **Actor**。例如，第一个 Step 会选择订阅特殊 **Input Channel** 的 Actor；后续 Step 则会选择订阅上一 Step 中发生更新的 Channel 的 Actor。
* **Execution（执行）**：并行执行所有被选中的 **Actor**，直到全部完成、某个 Actor 失败，或达到超时时间。在这个阶段，当前 Step 对 Channel 的更新对其他 Actor 不可见，直到下一个 Step 才会生效。
* **Update（更新）**：使用当前 Step 中各 **Actor** 写入的值更新 Channel。

以上过程会持续重复，直到没有任何 **Actor** 被选中执行，或达到最大 Step 数。

## Actor

一个 **Actor** 对应一个 `PregelNode`。它订阅 Channel、从中读取数据并向其中写入数据，可以视作 Pregel 算法中的 Actor。`PregelNode` 实现了 LangChain 的 Runnable 接口。

## Channel

Channel 用于 Actor（PregelNode）之间的通信。每个 Channel 都有一个 Value Type、一个 Update Type，以及一个 Update Function。Update Function 接收一系列 Update，并据此修改 Channel 中保存的值。Channel 既可以把数据从一个 Chain 传给另一个 Chain，也可以让 Chain 把数据发送给未来 Step 中的自己。

### LastValue

@[`LastValue`] 是默认 Channel 类型。它只保存最近一次写入的值，并覆盖之前的值。适合保存输入/输出值，或把数据从一个 Step 传递到下一个 Step。

:::python
```python
from langgraph.channels import LastValue

channel: LastValue[int] = LastValue(int)
```
:::

:::js
```typescript
import { LastValue } from "@langchain/langgraph/channels";

const channel = new LastValue<number>();
```
:::

### Topic

@[`Topic`] 是一个可配置的 PubSub Channel，适合在 Actor 之间发送多个值，或跨多个 Step 累积输出。它可以配置为去重，也可以在一次 Run 中累积所有写入值。

:::python
```python
from langgraph.channels import Topic

# Accumulate all values written across steps
channel: Topic[str] = Topic(str, accumulate=True)
```
:::

:::js
```typescript
import { Topic } from "@langchain/langgraph/channels";

// Accumulate all values written across steps
const channel = new Topic<string>({ accumulate: true });
```
:::

### BinaryOperatorAggregate

@[`BinaryOperatorAggregate`] 保存一个持久值，并通过把二元运算符应用到当前值和每次新的 Update 上来更新它。适合用于跨 Step 计算持续累积的聚合值。

:::python
```python
import operator
from langgraph.channels import BinaryOperatorAggregate

# Running total: each write adds to the current value
total = BinaryOperatorAggregate(int, operator.add)
```
:::

:::js
```typescript
import { BinaryOperatorAggregate } from "@langchain/langgraph/channels";

// Running total: each write adds to the current value
const total = new BinaryOperatorAggregate<number>({ operator: (a, b) => a + b });
```
:::

:::python
### DeltaChannel

<Warning>
`DeltaChannel` 要求 `langgraph>=1.2`，目前仍处于 **Beta**。未来版本中的 API 可能发生变化。
</Warning>

@[`DeltaChannel`] 在每个 Step 中只保存增量 Delta，而不是保存完整的累积值。对于频繁写入、并且随时间不断增长的大型 Channel，这尤其有用。例如，长时间运行的 Thread 中不断增长的对话消息列表。如果不使用 Delta 存储，每个 Checkpoint 都需要重新序列化完整列表；使用 `DeltaChannel` 后，每一步只需要保存新增的消息。

<Tip>
当一个 Channel 同时满足“写入频繁”和“随时间持续变大”时，可以考虑使用 `DeltaChannel`。一个明显信号是：如果某个 Channel 的 Checkpoint 大小会随着 Thread 长度近似线性增长，`DeltaChannel` 通常很适合。
</Tip>

可以像普通 Reducer 一样，在 `Annotated` 类型中使用 `DeltaChannel`：

```python
from typing import Annotated, Sequence
from typing_extensions import TypedDict
from langgraph.channels import DeltaChannel


def my_reducer(state: list[str], writes: Sequence[list[str]]) -> list[str]:
    result = list(state)
    for write in writes:
        result.extend(write)
    return result


class State(TypedDict):
    messages: Annotated[list[str], DeltaChannel(my_reducer)]
```

#### Bulk Reducer 要求

传给 `DeltaChannel` 的 `reducer` 是一个 **Bulk Reducer（批量归约器）**：它会在一次调用中接收当前 State，以及当前 Step 中**全部写入值组成的序列**，而不是像标准 Reducer 那样逐个进行 Pairwise 归约。这与 `StateGraph` 中通过 `Annotated` 使用的逐 Key Reducer 不同，后者每次 Update 都会调用一次 Reducer。

<Warning>
Bulk Reducer **必须满足结合性（Associative / Batching-invariant）**：

```
reducer(reducer(state, [xs]), [ys]) == reducer(state, [xs, ys])
```

如果 Reducer 不满足结合性，LangGraph 在不同 Step 中如何对写入进行批处理就可能影响最终重建出的 State，从而产生不一致行为。
</Warning>

<Warning>
**Reducer 在重建时运行，而不是在写入时运行。** @[`BinaryOperatorAggregate`] 的 Reducer 会在写入时调用，因此组合后的完整值会被序列化进 Checkpoint；而 `DeltaChannel` 的 Reducer 则会在 Channel Value 从持久化写入记录中**重新构建**时执行。真正被序列化的是每个 Step 的原始 Write；只有在值被 Materialize 时——例如下一次读取、下一个 Step 的 Actor 执行、或重放历史时——才会调用 Reducer。

设计 Reducer 时有以下实际影响：

- **让 Reducer 成为 `(state, writes)` 的纯函数。** 任何副作用、随机性或读取墙上时钟的操作，例如 `uuid.uuid4()`、`datetime.now()`，都会在每次重建值时重新执行，因此每次 Replay 可能得到不同结果；这些结果并不会固化进持久化 Write。
- **不要依赖 Reducer 对传入 Write 的修改被持久化。** 如果 Reducer 修改了 Write 对象，例如给一个没有 ID 的 Item 赋予稳定 ID，这种修改只存在于当前重建出的 Value 中。底层持久化的 Write 仍是原始形态，因此下一次重建仍会拿到未修改的输入。
- **在上游写入前就附加身份和稳定元数据。** 如果下游需要跨 Turn 使用 ID 引用某个 Item，例如后续更新或删除它，应在该值写入 Channel 之前就分配 ID，而不是在 Reducer 内部分配。
</Warning>

以下是两个最常见场景的 Bulk Reducer：

```python
from typing import Any, Sequence


# List: append all writes in order
def list_reducer(state: list[Any], writes: Sequence[list[Any]]) -> list[Any]:
    result = list(state)
    for write in writes:
        result.extend(write)
    return result


# Dict: merge all writes, last write wins on key conflicts
def dict_reducer(
    state: dict[str, Any], writes: Sequence[dict[str, Any]]
) -> dict[str, Any]:
    result = dict(state)
    for write in writes:
        result.update(write)
    return result
```

二者都满足结合性：逐批应用与一次性应用所有 Batch 会得到相同结果。

#### 使用 snapshot_frequency 限制读取延迟

如果不保存 Snapshot，那么读取 `DeltaChannel` Value 需要重放完整写入历史。对于包含 N 个 Step 的 Thread，其复杂度是 O(N)。设置 `snapshot_frequency=K` 后，每 K 个 Pregel Step 会写入一次完整 Snapshot，从而把读取深度限制在最多 K 个 Step：

```python
class State(TypedDict):
    messages: Annotated[
        list[str],
        DeltaChannel(my_reducer, snapshot_frequency=5),
    ]
```

更大的 `snapshot_frequency` 可以降低存储开销，但会提高读取延迟；更小的值可以更严格地限制读取延迟，但 Checkpoint 会更大。`None`（默认值）表示完全不创建 Snapshot，适合读取较少或 Thread 较短的情况。

#### 版本兼容与回滚

<Warning>
不建议把已经持久化的 Channel 从 `DeltaChannel` 改为非 Delta Channel。两种 Channel 的 Checkpoint 编码方式不同，因此对已有 Thread 修改类型可能导致 State 重建不完整或错误。应在一个 Thread 的整个生命周期中保持 Channel 定义稳定。修改 Channel 类型前，请先把受影响 Thread 迁移到新的表示形式，或者丢弃这些 Thread 并创建新 Thread。

**不支持回滚到不支持 `DeltaChannel` 的版本。** `langgraph>=1.2` 会使用新的格式写入 Delta Channel Checkpoint，而旧版 Runtime 无法读取该格式。一旦某个 Thread 使用过 `DeltaChannel`，降级 LangGraph 后旧 Runtime 无法理解 Delta 格式，也就无法重建 Channel State。如果必须回滚，请在降级前使用 [delta-channel-dump recovery script](https://github.com/langchain-ai/langgraph/tree/main/examples/delta-channel-dump) 迁移受影响的 Thread，或者将其丢弃。
</Warning>
:::

## 高层 API

LangGraph 提供两套用于创建 Pregel 应用的高层 API：[StateGraph（Graph API）](/oss/langgraph/graph-api)和 [Functional API](/oss/langgraph/functional-api)。

<Tabs>
    <Tab title="StateGraph（Graph API）">
    :::python
    @[StateGraph（Graph API）][StateGraph] 是更高层的抽象，用于简化 Pregel 应用的构建。你只需要定义由节点和边组成的图；编译图时，StateGraph API 会自动生成底层 Pregel 应用。

    ```python
    from typing import TypedDict

    from langgraph.constants import START
    from langgraph.graph import StateGraph

    class Essay(TypedDict):
        topic: str
        content: str | None
        score: float | None

    def write_essay(essay: Essay):
        return {
            "content": f"Essay about {essay['topic']}",
        }

    def score_essay(essay: Essay):
        return {
            "score": 10
        }

    builder = StateGraph(Essay)
    builder.add_node(write_essay)
    builder.add_node(score_essay)
    builder.add_edge(START, "write_essay")
    builder.add_edge("write_essay", "score_essay")

    # Compile the graph.
    # This will return a Pregel instance.
    graph = builder.compile()
    ```
    :::

    :::js
    @[StateGraph（Graph API）][StateGraph] 是更高层的抽象，用于简化 Pregel 应用的构建。你只需要定义由节点和边组成的图；编译图时，StateGraph API 会自动生成底层 Pregel 应用。

    ```typescript
    import { START, StateGraph } from "@langchain/langgraph";

    interface Essay {
      topic: string;
      content?: string;
      score?: number;
    }

    const writeEssay = (essay: Essay) => {
      return {
        content: `Essay about ${essay.topic}`,
      };
    };

    const scoreEssay = (essay: Essay) => {
      return {
        score: 10
      };
    };

    const builder = new StateGraph<Essay>({
      channels: {
        topic: null,
        content: null,
        score: null,
      }
    })
      .addNode("writeEssay", writeEssay)
      .addNode("scoreEssay", scoreEssay)
      .addEdge(START, "writeEssay")
      .addEdge("writeEssay", "scoreEssay");

    // Compile the graph.
    // This will return a Pregel instance.
    const graph = builder.compile();
    ```
    :::

    在 [Functional API](/oss/langgraph/functional-api) 中，可以使用 @[`@entrypoint`] 创建 Pregel 应用。`entrypoint` 装饰器允许你定义一个接收输入并返回输出的函数。

    ```python
    from typing import TypedDict

    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint

    class Essay(TypedDict):
        topic: str
        content: str | None
        score: float | None


    checkpointer = InMemorySaver()

    @entrypoint(checkpointer=checkpointer)
    def write_essay(essay: Essay):
        return {
            "content": f"Essay about {essay['topic']}",
        }

    print("Nodes: ")
    print(write_essay.nodes)
    print("Channels: ")
    print(write_essay.channels)
    ```

    ```typescript
    import { MemorySaver } from "@langchain/langgraph";
    import { entrypoint } from "@langchain/langgraph/func";

    interface Essay {
      topic: string;
      content?: string;
      score?: number;
    }

    const checkpointer = new MemorySaver();

    const writeEssay = entrypoint(
      { checkpointer, name: "writeEssay" },
      async (essay: Essay) => {
        return {
          content: `Essay about ${essay.topic}`,
        };
      }
    );

    console.log("Nodes: ");
    console.log(writeEssay.nodes);
    console.log("Channels: ");
    console.log(writeEssay.channels);
    ```
